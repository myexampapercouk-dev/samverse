In depth

How speed work is done

01

Measure first

Every job starts with a baseline for each key page type, such as the homepage, a service or product page and, for stores, category, cart and checkout pages. PageSpeed Insights, browser tools and Query Monitor show whether the bottleneck is hosting, plugins, the theme, images, scripts or the database.

02

Fix the biggest wins first

Work is done in order of impact: server response and caching, then images, then the theme or page builder, plugins, scripts and fonts, then the database. Typical fixes include WebP images, lazy loading below the fold, deferring non-critical scripts and replacing heavy plugins with lighter options.

03

WooCommerce-specific work

Cart, checkout and account pages are kept out of the page cache, while everything else is cached. Product images, filters, search, cart scripts, scheduled actions and order data are reviewed, and test orders confirm that payments and emails still work after each change.

04

Hosting, PHP and server checks

The PHP version, server caching, object caching (where the host supports it) and CDN setup are checked. If the hosting itself is the bottleneck, you get an honest recommendation rather than endless plugin tweaks.

05

Safe and tested

A full backup is taken first, changes are made on staging where possible, and pages, menus, forms and the checkout are tested on desktop and mobile after each round of changes.

06

What you receive

A before-and-after report with PageSpeed Insights results and Core Web Vitals for key pages, a plain-English list of what was changed and why, and simple guidelines for keeping the site fast as you add content.

What a speed optimization job looks like, step by step

Most speed work is invisible, so here is exactly what happens when you hire me to speed up your WordPress site or WooCommerce store, from your first message to the final report.

  1. Free review and a fixed quote. You send the website address and the pages that matter most. I check whether the problem looks like hosting, the theme, plugins or something heavier, then send a fixed quote. If the honest answer is that your hosting plan cannot keep up, you hear that before you pay for anything.
  2. Diagnosis under the score. After a full backup, I look at what the score does not tell you: how long the server takes to send the first byte, which plugins load scripts on every page, which database queries are slow, what is stored in autoloaded options, and what each third-party tag adds.
  3. Fixes in small rounds. Changes go in batches rather than all at once, so if anything misbehaves it is obvious which change caused it and it can be reversed quickly.
  4. Testing after every round. Key pages on a phone and a desktop, menus, forms, sliders, search and, for stores, a full test order.
  5. Report and handover. Before and after results, what changed and why, and what to watch for as you add content.

Lab scores and real visitors: reading the results honestly

PageSpeed Insights shows two different things. The section about what your real users are experiencing is field data: Core Web Vitals collected from real Chrome visitors over the previous 28 days, and it only appears once a site has enough traffic. The performance score below it is a lab test, a single simulated visit on a throttled phone, and it can move a few points every time you run it.

The lab results improve as soon as the fixes go live, so they are what the before-and-after report compares. Field data catches up over the following four weeks, and Search Console's Core Web Vitals report follows it. If your slowest metric is the main image or heading taking too long to appear, fixing slow LCP explains what usually causes it.

Signs you need a speed service, not another plugin

  • You have tried two or three optimization plugins and the site got slower, or started breaking.
  • There is a long pause before anything appears at all. That is usually server response time, which no image plugin can fix; see how to reduce TTFB.
  • The WordPress dashboard is slow too, not just the public pages.
  • The site feels fine on office Wi-Fi but crawls on a phone. Slow on mobile but fast on desktop covers the usual reasons.
  • Your store slows down during sales, or cart and checkout lag while other pages feel quick.
  • Search Console lists URLs as "Poor" or "Needs improvement" in its Core Web Vitals report.

WooCommerce speed optimization for Indian stores

Stores slow down in ways brochure sites do not, and Indian stores have a few extra moving parts. Things I look at closely:

  • Plugins that load everywhere. Pin code delivery checkers, COD fee rules, GST invoice plugins and WhatsApp order notifications are all useful, but many load scripts or run queries on every page instead of only where they are needed.
  • Payment gateway scripts. Scripts from gateways such as Razorpay belong on checkout, not on your home page and blog.
  • Background tasks. WooCommerce queues work in its scheduled actions table. Thousands of failed or pending actions slow the dashboard and can delay order emails.
  • Order storage. Newer WooCommerce versions can store orders in their own tables (High-Performance Order Storage), which helps busy stores once every plugin supports it.

Every round ends with a test payment using the gateway's test mode or a low-value order, so UPI, cards and order emails are confirmed working. On a site that combines a WooCommerce shop with a table reservation form, like the one I built for Southern Flavours, both flows get tested. For a deeper look, read WooCommerce speed optimization, and if your store needs new features rather than speed, see WooCommerce development.

What is included, and what is not

The full list of fixes is near the top of this page. These sit outside a speed job:

  • Redesigning pages or rebuilding the theme. If the theme or page builder is the real bottleneck, I will say so and quote a rebuild separately. Often it is not; why Elementor sites get slow shows how much can be fixed without starting again.
  • Hosting fees and premium licences, such as a WP Rocket or image compression subscription. These are paid to the provider, ideally in your name.
  • Removing tools you rely on. Chat widgets, pixels and tag managers are loaded more efficiently, never deleted without your say-so. How third-party scripts slow a website explains the trade-offs.

How long it takes

Most sites take a few working days. What stretches that: the number of different page templates, a heavy page builder, a large store with years of order data, waiting for hosting access, no staging site on your plan, or a hosting move. Database clean-up on a big store is done carefully, in steps; WordPress database optimisation shows why.

A magazine-style portal like India Automation Hub, with thumbnails, category filtering and recent-post widgets on every page, pulls in a lot per page view, so caching and image handling need particular care.

FAQ

Common questions

How much faster will my site get?

It depends on your hosting, theme and plugins. I share a before-and-after report from PageSpeed Insights so you can see the improvement.

Will optimization break my website?

I work carefully: a full backup is taken first, changes are made on staging where possible, and every key page, form and (for stores) the checkout is tested after each change.

Do I need to change my hosting?

Not always. I optimize what you have first, and recommend a hosting upgrade only if it is really the bottleneck.

How long does it take?

Most sites are optimized within 2–4 working days. Larger WooCommerce stores, or sites that need a hosting move, can take longer, and you get a timeline with the quote.

Do you optimize WooCommerce stores?

Yes. Stores need extra care because cart, checkout and account pages can't be page-cached, so the work also covers server response, cart and checkout scripts, product filters and search, scheduled tasks and the database, with test orders after every change.

Can you guarantee a PageSpeed score of 100?

No honest developer can, because hosting, design and third-party tools such as chat, analytics and ads all affect the score. The aim is good Core Web Vitals for real visitors, and the report shows exactly what changed.

What do you need from me to start?

Your website address, a WordPress admin login, hosting access if possible, and a list of the pages that matter most. Any temporary access can be removed once the work is done.

Will my site stay fast afterwards?

It stays fast as long as new images, plugins and scripts are added carefully. The report includes simple guidelines, and a monthly maintenance plan can keep an eye on speed for you.

Is a plugin like WP Rocket enough on its own?

Sometimes, for a small site on good hosting. A caching plugin cannot fix slow server response, heavy plugins, oversized images or third-party scripts, and adding several optimization plugins on top of each other often causes conflicts. The free review tells you which situation you are in.

Why does my PageSpeed score change every time I test?

The score comes from a single simulated visit, so network conditions and server load at that moment move it by a few points. Look at the trend over several tests and at the real-user Core Web Vitals data, which is what Google uses.

Can you speed up an Elementor site without rebuilding it?

Usually, yes. Elementor's performance settings, fewer nested containers and widgets, better image and font loading, and removing unused add-ons often make a big difference. A rebuild is only worth considering when the page structure itself is the bottleneck, and I will tell you if that is the case.

Do I need a CDN or Cloudflare?

It depends on where your visitors are and how your hosting is set up. A CDN helps when visitors are spread across regions or countries. Cloudflare's free plan can help, but wrong settings can break logins, checkout or forms, so it is set up and tested as part of the job if it makes sense.
