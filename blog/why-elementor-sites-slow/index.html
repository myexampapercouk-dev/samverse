Why Elementor Sites Get Slow, and How to Fix Them (Pages and the Editor)

Why is Elementor so slow? The real causes, from nested containers and add-on packs to fonts and hosting, and the Elementor settings and fixes that speed it up.

Key takeaways
  • Most slow Elementor sites are slow because of how they were built: nested containers, add-on packs, animations, full-size images and a heavy theme underneath.
  • Turn on Elementor's performance settings one at a time, remove add-ons and widgets you do not use, and rebuild only the heaviest sections with flat containers.
  • A slow Elementor editor is a separate problem, usually long pages, low PHP memory, weak hosting or a plugin, and page caching does nothing for it.

Elementor is usually slow because of how a site was built with it, not because of Elementor itself. The common causes are deeply nested sections and containers, several add-on packs loading scripts on every page, full-size images, animations everywhere, too many fonts and icon libraries, a heavy theme underneath and weak hosting. Most of these can be fixed without rebuilding the site or switching builders.

All the client sites in my case studies are built with Elementor, on themes from Hello Elementor to Astra and OceanWP, so this is the toolset I spend my time building with and fixing. If you want it done for you, see Elementor development for builds and repairs, or WordPress speed optimization when hosting, caching and the database need work too.

Is Elementor slow, or is it your site?

Elementor adds more HTML, CSS and JavaScript than a hand-coded theme or the block editor, and that overhead is real. But a lean Elementor page on decent hosting can load quickly and pass Core Web Vitals. When a page is slow, it's usually the build: what was added, how it was structured and what it runs on. Before changing anything, run your slowest page through PageSpeed Insights on mobile and note what it flags:

  • Slow Largest Contentful Paint (LCP): often a large hero image or section background, or a slow server.
  • A warning about DOM size: too many nested containers and widgets.
  • Unused CSS or JavaScript: add-ons, icon libraries and widgets loading on every page.
  • Long blocking time or poor INP: heavy scripts from sliders, animations and third-party widgets.
  • Slow server response time: if this is the main problem, look at hosting and caching before Elementor.

Nested sections and containers

Older Elementor sites were built with sections, columns and inner sections, and every level adds wrapper elements. A page built as sections inside columns inside sections can end up with thousands of elements, which phones take longer to lay out. Flexbox containers do the same job with far fewer wrappers. Recent versions include a Convert option that turns an old section into a container, but check the result closely, because spacing and widths often need tidying afterwards.

Add-on packs

Two or three add-on plugins installed "just in case" is one of the most common things I find on slow Elementor sites. Many load their CSS and scripts on every page whether their widgets are used or not. Keep one well-coded pack at most, and use its widget manager to switch off everything you don't use. Elementor has its own Element Manager in the dashboard menu, where you can disable unused core and Pro widgets too.

Images and backgrounds

Background images on sections and containers are easy to upload at full camera size and forget. Resize each image to the largest size it's shown at, compress it and serve WebP. Don't lazy-load the main hero image, because that delays LCP; lazy-load what sits further down the page. See image optimization for WordPress.

Fonts and icons

Every Google Font family and weight is another file to download. Pick one or two families and only the weights the design uses, set them as global fonts, and avoid styling individual widgets with a different font. Icon libraries are similar: loading a whole icon font to show five icons is wasteful, which is what Elementor's inline font icons setting addresses.

Animations, sliders and video backgrounds

Entrance animations keep content hidden until scripts run, which can delay what visitors see. Sliders and carousels load extra scripts and often several large images at the top of the page. A single strong hero image with a clear headline is faster, and usually clearer for visitors than a five-slide carousel.

The theme and hosting underneath

Elementor on top of a heavy multipurpose theme means two frameworks loading their own CSS and scripts. A minimal theme such as Hello Elementor, Astra or GeneratePress leaves the layout to Elementor; see choosing the best theme for Elementor. And no front-end tuning fixes a server that takes a second or more to respond: that's hosting, PHP version and page caching.

Elementor's performance settings

Elementor ships with settings that cut what it loads. Names and locations change between versions; at the time of writing, most sit under Elementor > Settings > Performance, with newer options under the Features tab. Turn them on one at a time and check your key pages after each:

  • CSS print method: external files are the usual choice, because browsers and caches can reuse them across pages.
  • Optimized image loading and lazy-loaded background images: improve how images, including container backgrounds, are loaded.
  • Improved asset loading and improved CSS loading: load each widget's scripts and styles only on pages that use it. On many recent versions these are already active.
  • Inline font icons: shows icons as inline SVG instead of loading whole icon font libraries.
  • Load Google Fonts locally: serves fonts from your own server instead of Google's, saving a connection to another server.
  • Element caching: stores the rendered output of elements so pages are built faster. Test it carefully on pages with forms, loops and other dynamic content.

After changing settings, use Elementor > Tools > Regenerate Files & Data, then clear your caches.

Caching and optimisation plugins with Elementor

Page caching, such as LiteSpeed Cache on LiteSpeed hosts like Hostinger or WP Rocket elsewhere, makes the biggest difference to how quickly pages arrive. The aggressive options need care on Elementor sites:

  • Delaying or deferring JavaScript can break menus, popups, sliders and forms if Elementor's own scripts are delayed. Test every interactive element after enabling it, and exclude the scripts that break.
  • Removing unused CSS can strip styles that only apply when a visitor opens a menu, tab or popup. Check mobile menus, tabs and accordions.
  • One caching plugin only. Two page caches, or minification in two places, cause conflicts rather than speed.

See reducing unused CSS and JavaScript for what's worth chasing and what isn't.

A step-by-step plan to speed up an Elementor site

  1. Back up, and work on a staging copy if your host offers one.
  2. Measure the homepage and your two or three most important pages in PageSpeed Insights on mobile.
  3. Fix the hosting basics: a current PHP version, page caching on and enough memory. Elementor > System Info shows your PHP version and memory limit.
  4. Remove unused add-ons and widgets, and disable unused widgets in the Element Manager.
  5. Turn on the performance settings one at a time.
  6. Optimise images, starting with the hero and section backgrounds.
  7. Set global fonts and colours, and trim font families and weights.
  8. Rebuild the heaviest sections with flat containers and fewer widgets.
  9. Cut animations, sliders and video backgrounds near the top of the page.
  10. Re-test the same pages and compare against your starting figures.

When the Elementor editor is slow

A slow editor is a different problem from slow pages, because the editor is never cached. The usual causes:

  • Very long pages with hundreds of widgets. Split them, or turn repeating blocks into templates.
  • Low PHP memory or weak hosting. Check Elementor > System Info and ask your host whether you're hitting resource limits.
  • Plugins loading code into the editor. Elementor > Tools has a Safe Mode that loads the editor without other plugins or your theme, which quickly shows whether one of them is to blame.
  • Browser extensions such as ad blockers and password managers; try a private window.

If the editor won't load at all, see Elementor stuck on loading, and if the whole dashboard is slow, why the WordPress admin is slow.

Should you switch away from Elementor?

Usually not. Your team keeps easy drag-and-drop editing, and most of the fixes above work on the existing site. A rebuild makes sense when the site is so heavy that fixing it would cost more than starting again, or when it's being redesigned anyway. Even then, a clean Elementor rebuild with containers and global styles is often the right answer; the block editor or a custom theme suits sites with strict performance targets or locked-down editing. FAQs

Why is Elementor so slow?

Usually because of how the site was built: nested containers, add-on packs, full-size images, animations and too many fonts, often on a heavy theme and basic hosting. Elementor adds some overhead of its own, but a lean Elementor page on good hosting can load quickly.

Is Elementor slower than Gutenberg?

Out of the box, yes: the block editor outputs less code. In practice the gap depends on how each site is built. A careful Elementor build can beat a block theme loaded with plugins, and a careless one will be slower.

Does Elementor Pro make a site slower?

Not by itself. Pro adds features such as the Theme Builder, forms and popups, and with improved asset loading active, widget assets load only on pages that use them. Sites get slow when widgets, popups and effects pile up, whether they come from Pro or from add-ons.

Which Elementor performance settings should I turn on?

Start with optimised image loading, lazy-loaded background images, inline font icons and local Google Fonts, and make sure improved asset and CSS loading are active. Turn them on one at a time, regenerate files and data, clear caches and check your key pages after each.

Why is the Elementor editor so slow?

Long pages with many widgets, low PHP memory, weak hosting and plugins loading code into the editor are the usual causes. Use Safe Mode under Elementor > Tools to test without other plugins, and check System Info for your memory limit.

Will a caching plugin fix a slow Elementor site?

It helps pages arrive faster, but it doesn't reduce what the browser has to download and run once they do. Heavy layouts, add-ons and images still need fixing, and caching does nothing for the editor.
