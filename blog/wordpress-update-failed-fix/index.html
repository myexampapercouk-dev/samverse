WordPress Update Failed? How to Fix "Download Failed", Locked Updates and Half-Finished Plugin Updates

Fix WordPress "Update failed", "Download failed", "The package could not be installed" and "Another update is currently in progress" errors, step by step.

Key takeaways
  • "Another update is currently in progress" is a core_updater.lock option that expires after about 15 minutes; delete only that row if it stays and no update is running.
  • Download and install failures usually come from the server: timeouts, blocked connections, expired premium licences, full disks, wrong permissions or file ownership.
  • When an update keeps failing, replace the plugin with a fresh zip or update core manually over SFTP without touching wp-content or wp-config.php, after a full backup.

WordPress updates usually take seconds, but sometimes they stop with "Update failed", "Download failed", "The package could not be installed" or "Another update is currently in progress". Sometimes a plugin update stops halfway. Your content is rarely affected, but a site that can't update falls behind on security fixes. Back up files and database before you retry anything.

If visitors see "Briefly unavailable for scheduled maintenance", deal with that first; see WordPress stuck in maintenance mode.

"Update failed" on the Plugins screen is usually followed by one of these more specific messages. Copy any extra detail, such as "cURL error 28", exactly; your host will ask for it.

"Another update is currently in progress"

When WordPress updates its core files, it saves a lock in the database, an option called core_updater.lock, so two updates can't run at once. The lock is removed when the update finishes and treated as expired after about 15 minutes. If an update crashed, the lock stays behind until then.

  1. Wait 15 minutes, then try again, making sure no one else, and none of your host's tools, is running updates.
  2. If it's still locked, delete the option. In phpMyAdmin, open the options table (usually wp_options, though your prefix may differ), find the row whose option_name is core_updater.lock and delete only that row.
  3. If your host provides WP-CLI, the same fix is one command:
wp option delete core_updater.lock

Background automatic updates use a similar lock called auto_updater.lock. Only remove a lock when you're sure no update is actually running.

"Download failed" and missing packages

Your server downloads updates itself, so a download failure is usually a server problem:

  • Timeouts: "cURL error 28" means the connection took too long. Retry later and ask your host if it persists.
  • Blocked or broken connections: a host firewall, DNS trouble or outdated SSL certificates on the server can stop outgoing downloads. Tools → Site Health checks whether your site can communicate with WordPress.org.
  • Temporary folder problems: a message about the "destination directory for file streaming" points to the server's temp folder not being writable. Your host can fix it.
  • Premium licences: paid plugins and themes update from the vendor's servers only while a valid licence key is entered and active. An expired licence or a domain change often explains "Update package not available".

"The package could not be installed" and permission errors

After downloading, WordPress unpacks the zip into wp-content/upgrade and copies the new files into place. Recent versions also keep a temporary backup of the old plugin or theme so they can restore it if the update fails. Every step needs write access and free space.

  • Wrong or damaged zip: when uploading manually, "No valid plugins were found" usually means you uploaded the vendor's whole download bundle rather than the plugin's own zip. Re-download if it might be corrupt.
  • Disk space: a full hosting account, or one at its file-count (inode) limit, causes copy failures. Delete old backup archives stored on the server, and clear leftover folders in wp-content/upgrade while no update is running.
  • Permissions: folders are commonly 755 and files 644. Never use 777 as a quick fix.
  • Ownership: files should belong to the account PHP runs as. After a migration or uploads by another user, WordPress may fail to create folders or ask for FTP details. Ask your host to correct ownership rather than adding FS_METHOD to wp-config.php as a workaround.

See WordPress file permissions explained for safe settings and how to check them.

PHP timeouts and updates that stop halfway

Large plugins such as page builders and WooCommerce take longer to install. On a slow or busy server, PHP can hit its time limit (max_execution_time) or memory limit partway through, and updating many plugins at once makes that likelier.

Signs of a half-finished update: a plugin deactivated with "Plugin file does not exist", a critical error, or a version number that didn't change. To recover:

  1. Clear any leftover .maintenance file first, using the maintenance mode guide linked above.
  2. Re-run updates one at a time, keeping the browser tab open until each finishes.
  3. If one plugin keeps failing, update it manually (below) and ask your host about raising PHP's time and memory limits.

Updating manually via SFTP

For a plugin, download a fresh zip from WordPress.org or your vendor account. The simplest route is Plugins → Add New → Upload Plugin; WordPress offers to replace the installed version with the uploaded one. Over SFTP, rename the old folder in wp-content/plugins, upload the new unzipped folder under the original name, test, then delete the old copy. Don't delete the plugin from the dashboard first; some remove their settings when deleted.

For WordPress core:

  1. Take a full backup, then download the latest WordPress zip from wordpress.org only and unzip it on your computer.
  2. Connect by SFTP and open the WordPress folder, the one containing wp-config.php.
  3. Rename the existing wp-admin and wp-includes folders, then upload the new ones.
  4. Upload the loose files from the new package's top level, overwriting the old ones. Don't upload the wp-content folder, and leave wp-config.php and .htaccess alone.
  5. Open /wp-admin/. If WordPress asks to update the database, let it.
  6. Clear caches, test the site, then delete the renamed old folders.

Where WP-CLI is available, wp core update and wp plugin update plugin-name do the same job from the command line and usually avoid web server time limits.

Habits that prevent failed updates

  • Back up before every round of updates, and keep copies off the server
  • Update important plugins one at a time, and read changelogs for major versions
  • Test major updates on a staging copy first
  • Keep free disk space, and run a PHP version your plugins support
  • Update at quiet times, not mid-sale
  • Keep premium licences active
