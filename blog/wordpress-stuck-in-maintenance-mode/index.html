WordPress Stuck in Maintenance Mode? How to Fix "Briefly Unavailable for Scheduled Maintenance"

WordPress stuck in maintenance mode? Delete the .maintenance file, finish the failed update safely, check plugins and themes, and stop it recurring.

Key takeaways
  • WordPress shows the maintenance message while updating and normally removes it in seconds; if an update is interrupted, a .maintenance file is left behind.
  • Deleting the .maintenance file from the site's root folder through your hosting file manager or FTP usually brings the site back immediately.
  • After fixing it, check which update failed, complete it properly and update in smaller batches with a backup to avoid a repeat.

If WordPress is stuck in maintenance mode and shows "Briefly unavailable for scheduled maintenance. Check back in a minute.", the quick fix is to delete the file called .maintenance from your site's root folder (the folder containing wp-config.php) using your hosting file manager or FTP. The site usually comes back at once. Then check which update was interrupted and finish it properly.

Here is why it happens, how to fix it step by step on common Indian hosting panels, and how to stop it recurring.

Why WordPress gets stuck in maintenance mode

When you update WordPress core, plugins or themes, WordPress creates a temporary .maintenance file. While it exists, visitors see the maintenance message. When the update finishes, WordPress deletes the file. If something interrupts the update, the file stays and the site stays "under maintenance".

Common causes:

  • Closing the browser tab or losing connection during an update.
  • Updating many plugins at once on slow or limited hosting.
  • The server hitting a time or memory limit mid-update.
  • A plugin or theme update that fails or is incompatible.
  • File permission problems that stop WordPress deleting the file.

WordPress stuck in maintenance mode: step-by-step fix

  1. Wait a minute or two and refresh. Sometimes a slow update is still running.
  2. Log in to your hosting panel (hPanel on Hostinger, cPanel on many other hosts) and open the File Manager. Or connect with FTP.
  3. Go to the site's root folder, usually public_html or a folder named after your domain. It contains wp-config.php, wp-content and wp-admin.
  4. Show hidden files. The .maintenance file starts with a dot, so it may be hidden. Enable "show hidden files" in the file manager settings or your FTP client.
  5. Delete .maintenance.
  6. Clear caches: your caching plugin, hosting cache and CDN such as Cloudflare. Then reload the site in a private window.

If you are not comfortable with the file manager, your host's support team can delete the file for you.

After deleting the file: finish the update

Removing the file brings the site back, but the update that failed may be half done. Check:

  • Dashboard, Updates: see which plugins, themes or core still show as needing an update.
  • Plugins page: look for deactivated plugins or error notices.
  • Front end: test key pages, forms, checkout and the menu.

Update the remaining items one at a time. If a particular plugin fails again, check its compatibility with your WordPress and PHP versions, or update it manually by uploading a fresh copy. Fixing a failed WordPress update covers the next steps.

If the site shows an error after removing the file

Sometimes deleting .maintenance reveals a bigger problem from the half-finished update:

  • "There has been a critical error on this website": a plugin or theme is broken. See fixing the WordPress critical error.
  • A blank white page: see the white screen of death.
  • 500 Internal Server Error: see fixing the 500 error.

In most of these cases, renaming the folder of the plugin that was updating (inside wp-content/plugins) deactivates it and brings the site back while you sort it out. If things are badly broken, restoring a recent backup may be quickest.

If updates have stopped appearing in the dashboard instead, see WordPress update button missing.

If you cannot find the .maintenance file

Sometimes the file is not where you expect. Check these before assuming something else is wrong:

  • You are in the wrong folder. If you host several sites, make sure you are in the folder for the affected domain. Look for its wp-config.php.
  • Hidden files are still hidden. Some file managers need a page refresh after enabling the setting.
  • The cache is showing an old page. The file may already be gone, but your caching plugin, hosting cache or CDN is still serving the maintenance page. Purge all caches and test in a private window or on mobile data.
  • The message comes from somewhere else. A maintenance plugin, a hosting-level maintenance mode or a custom maintenance.php file in wp-content can show a similar message.

If you see a file named maintenance.php inside wp-content, that is a custom maintenance page template, not the flag. Leave it unless you know why it is there; the flag is always the .maintenance file in the root.

Can I prevent it with settings?

There is no setting that stops WordPress using maintenance mode during updates, and you would not want one, because it prevents visitors seeing a half-updated site. What you can do is reduce the chance of an interrupted update:

  • Ask your host to raise PHP memory and execution time limits to sensible values for WordPress.
  • Remove plugins you no longer use, so there is less to update.
  • Update during quieter hours, not during a sale or campaign.
  • Use a stable internet connection when running updates from the dashboard.
  • Check that the hosting plan has enough resources. Very cheap plans that struggle under normal traffic often fail during updates too. Choosing WordPress hosting in India covers what to look for.

If the same plugin keeps failing to update, check whether it is a premium plugin with an expired licence, or a copy from an unofficial source. Unofficial copies can fail to update and may contain malware; the risks of nulled plugins explains why.

Maintenance mode plugins are different

If you intentionally used a "coming soon" or maintenance mode plugin, the message comes from that plugin, not from a .maintenance file. Log in to wp-admin (visitors may be blocked, but admins usually are not) and turn it off in the plugin settings. If you cannot log in, rename the plugin's folder via the file manager to deactivate it.

How to prevent it happening again

  • Take a backup before updating. Backup plugins compared helps you pick one.
  • Update a few plugins at a time, not twenty at once, especially on shared hosting.
  • Keep the tab open until updates finish.
  • Test big updates on staging first, especially WooCommerce, page builders and themes.
  • Check PHP version and memory limits with your host.
  • Consider whether auto-updates suit you. WordPress auto-updates explains the trade-offs.
  • Follow a safe routine; updating WordPress safely lays one out.

What to tell your host or developer

If you ask for help, a few details speed things up a lot:

  • The exact message visitors see, or a screenshot.
  • What you were updating and roughly when it started.
  • Whether you have already deleted the .maintenance file and cleared caches.
  • Any error message shown after removing the file.
  • Whether you have a recent backup and where it is stored.
  • Your hosting provider and how to access the panel, shared securely rather than in a public message.

With this information, most stuck maintenance problems can be resolved quickly without guesswork. Keep a short record of each incident and fix, so patterns such as one plugin repeatedly failing become obvious.

When to get help

If you are unsure which files to touch or the site still does not load, get help before deleting more. A WordPress maintenance service can take care of updates, backups and monitoring so this does not happen during a sale or campaign. For business sites, a stuck maintenance page is mostly a symptom of rushed or unplanned updates. A regular routine with backups, staging for big changes, small batches and a quick check of key pages afterwards prevents nearly all of these incidents, and makes any problem that does happen far quicker to undo.

FAQs

Why is my WordPress stuck in maintenance mode?

An update was interrupted, so WordPress did not delete its temporary .maintenance file. Deleting that file from the root folder usually fixes it.

Where is the .maintenance file?

In the WordPress root folder, next to wp-config.php, usually public_html. It is hidden, so enable "show hidden files" in your file manager or FTP client.

Is it safe to delete the .maintenance file?

Yes. It is only a temporary flag. After deleting it, check and complete any updates that did not finish.

The site is still down after deleting the file. What now?

Clear all caches, then check for a critical error, white screen or 500 error, usually caused by the plugin or theme that was updating.

How long should WordPress maintenance mode last?

Normally a few seconds to a minute per update. If it lasts several minutes, the update has probably failed.
