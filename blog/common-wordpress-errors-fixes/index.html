Most WordPress errors come from a small set of causes: a plugin or theme with faulty code, a server limit such as memory or PHP version, a database problem, a broken configuration file such as .htaccess, or an SSL or DNS setting. For any error, the safe first steps are the same: stop changing things, note what changed just before it started, take a backup, then read the recovery mode email or the error log so you know the real cause before you fix it.

This page is the map. The table below matches each common error to its usual cause and first fix, and each section links to a step-by-step guide for that error. First steps for any WordPress error

  1. Stop. Don't keep clicking update, reinstalling plugins or changing settings at random. Each change makes the cause harder to trace.
  2. Note what changed in the last day or two: updates, new plugins, code edits, a PHP switch, a hosting move, DNS changes.
  3. Take a backup from your hosting panel if the site is accessible enough to allow it.
  4. Check the admin inbox for WordPress's recovery mode email, which names the plugin or theme that failed.
  5. Read the error log. Your hosting panel's error log, or WordPress's own debug log, usually names the exact file and line.
  6. Isolate the cause. Disable plugins by renaming the plugins folder over File Manager or SFTP, then switch to a default theme if needed.
  7. Ask your host if the log points to the server, such as memory, disk space or timeouts.

To make WordPress write errors to wp-content/debug.log without showing them to visitors, add this to wp-config.php, and remove it once you're done:

define( 'WP_DEBUG', true );
define( 'WP_DEBUG_LOG', true );
define( 'WP_DEBUG_DISPLAY', false );

Errors that take the whole site down

"There has been a critical error on this website"

WordPress caught a PHP fatal error, most often right after a plugin, theme or PHP update. The admin email contains a recovery mode link that lets you log in and deactivate the faulty plugin. Step by step: how to fix "There has been a critical error".

White screen of death

A completely blank page is the same kind of PHP failure, with error display switched off or memory exhausted before anything could load. See the WordPress white screen of death.

500 Internal Server Error

A generic server-side failure. The usual suspects are a corrupt .htaccess file, a plugin fatal error, the wrong PHP version or a server limit. The server error log usually says which; see how to fix a 500 Internal Server Error.

Error establishing a database connection

WordPress can't reach its database. Check first whether the host's database server is down, then whether the database name, user, password and host in wp-config.php are right, which is the usual cause after a migration. Tables can also become corrupted. Full guide: how to fix "Error establishing a database connection".

502 and 504 gateway errors

The web server waited for PHP and gave up, usually because PHP workers were busy with slow requests, a plugin called a slow outside service, or Cloudflare couldn't get a timely answer. See fixing 502 and 504 errors.

Stuck in maintenance mode

WordPress creates a temporary .maintenance file during updates and deletes it afterwards. If the update was interrupted, the file stays and every visitor sees "Briefly unavailable for scheduled maintenance". See WordPress stuck in maintenance mode.

Memory, upload and permission errors

WordPress memory errors

"Allowed memory size of ... bytes exhausted" means a PHP process needed more memory than the limit allows. WordPress can request more with WP_MEMORY_LIMIT in wp-config.php, but not above the server's own memory_limit. If raising it only delays the error, a plugin or import is the real problem. See fixing memory limit errors.

HTTP error on image upload

The media uploader's vague "HTTP error" usually comes down to a very large image, memory, an upload limit or a security rule. See fixing the HTTP error when uploading images, and increasing the upload size limit if the file is simply too big.

403 Forbidden

The server understood the request but refused it. Common reasons are a security plugin or host firewall blocking your IP, wrong file permissions, or a bad rule in .htaccess. See how to fix a 403 Forbidden error.

URL, redirect and SSL errors

  • 404s on pages that exist: usually broken rewrite rules after a migration or a plugin change. Re-saving permalinks fixes most cases; see pages returning 404.
  • Too many redirects: two systems disagree about https or www, often WordPress and Cloudflare's SSL mode, or a redirect plugin and the server; see fixing ERR_TOO_MANY_REDIRECTS.
  • Certificate and "Not secure" warnings: an expired or mismatched certificate, or images and scripts still loading over http; see SSL certificate errors explained.

Dashboard and update errors

  • Login not working: the login page reloads, rejects a correct password or redirects in a loop. Cookies, caching, a security plugin or a wrong site URL are the usual causes; see WordPress login not working.
  • Update failed: "Update failed", "Could not create directory" or "Download failed" usually means file permissions, low disk space, a timeout or an inactive premium licence; see fixing failed WordPress updates.

Problems with no error message

Some of the most costly problems show no error at all:

  • Forms that stop sending. The thank-you message appears, but no email arrives. This is usually email delivery, fixed with SMTP; see WordPress not sending emails.
  • Changes that don't show. Almost always a cache: your caching plugin, the host or a CDN; see WordPress changes not showing.
  • Something broke after installing or updating a plugin, but only on certain pages. That's a conflict; see finding and fixing plugin conflicts.
  • Checkout failing on a store. See WooCommerce checkout not working.

How to prevent most WordPress errors

  • Take a backup before every update, and keep copies off the server; see the backup and restore guide
  • Update one important plugin at a time and test big updates on staging; see how to update WordPress safely
  • Keep PHP on a supported version, after checking compatibility
  • Delete plugins and themes you don't use, and replace abandoned ones
  • Use uptime monitoring, so you hear about errors before customers do
  • Keep the admin email current, so recovery mode emails reach someone

FAQs

What is the most common WordPress error?

The critical error and its relatives, the white screen and the 500 error, are among the most common. All three usually come down to a plugin or theme failing after an update or a PHP version change.

How do I find out what's causing a WordPress error?

Check the recovery mode email first, then the error log in your hosting panel or WordPress's debug.log. The log names the file that failed, and the folder in its path tells you which plugin or theme it belongs to.

Will deactivating plugins delete my settings or content?

No. Deactivating a plugin, or renaming its folder, keeps its settings in the database. Deleting a plugin from the dashboard can remove its data, depending on the plugin, so deactivate while troubleshooting rather than delete.

Can WordPress errors hurt my Google rankings?

A short outage usually doesn't. If Google keeps getting server errors for days, it slows down crawling and can eventually drop affected pages from results. Fix errors quickly, then check the Pages report in Search Console.

Why do WordPress errors so often appear after updates?

Because an update changes code that other plugins, your theme or your PHP version depend on. Updating one thing at a time, after a backup, means you know exactly what to roll back.
