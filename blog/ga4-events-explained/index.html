Google Analytics 4 Events Explained: Key Events, Enhanced Measurement, and Tracking Forms, WhatsApp and Calls on WordPress

Key takeaways
  • GA4 records every interaction as an event; key events are the few you mark as business outcomes, such as enquiries, calls, WhatsApp clicks and purchases.
  • Enhanced measurement covers page views, scrolls, outbound clicks and downloads, but enquiries need their own events, best fired on a successful submission or thank-you page.
  • Use clear, consistent event names, mark only real outcomes as key events, and test every event in DebugView and Realtime before trusting the reports.

In Google Analytics 4, everything a visitor does is recorded as an event: viewing a page, scrolling, clicking a link, submitting a form or making a purchase. Key events are the events you mark as important business outcomes, such as an enquiry form, a call, a WhatsApp click or an order. GA4 collects some events automatically, but the ones that show whether your website brings business usually need setting up, either with Google Tag Manager or with code, and testing in DebugView before you rely on them.

When I set up SEO through WordPress SEO services, Search Console and GA4 are set up so progress can be measured, and for campaign pages, landing page design includes GA4 events for form submissions and WhatsApp clicks. This guide explains how events work, so you can check your own setup or follow what a developer has done.

If GA4 isn't installed yet, start with setting up GA4 and Search Console, then come back here.

Events, parameters and key events

  • Event: any interaction GA4 records, identified by a name such as page_view or generate_lead.
  • Parameter: extra detail sent with an event, such as the page, the link clicked or the form's name.
  • Key event: an event you've marked as a business outcome. Google called these conversions until 2024; Google Ads still uses the word conversion for actions it counts for bidding.

Most sites record many events and should mark only a handful as key events. If everything is a key event, the reports stop telling you anything.

The four kinds of GA4 event

KindExamplesHow it's set up
Automatically collectedfirst_visit, session_start, user_engagementSent by the GA4 tag with no extra work
Enhanced measurementpage_view, scroll, click (outbound links), view_search_results, file_download, video_start, form_start, form_submitSwitched on or off per data stream
Recommendedgenerate_lead, sign_up, purchase, add_to_cart, begin_checkoutYou send them, using Google's suggested names and parameters
Customcontact_whatsapp, contact_call, calculator_usedYou send them, with names you choose

Use a recommended name when one fits, such as generate_lead for an enquiry and purchase for an order, because GA4 and Google Ads understand them. Use custom names for everything else, in lowercase with underscores, and keep them consistent across the site.

Enhanced measurement: useful, with limits

Enhanced measurement is set under Admin > Data streams > your web stream (menu names are correct at the time of writing; Google moves them from time to time). It records page views, scrolls to near the bottom of a page, clicks on links to other websites, site search, file downloads, embedded YouTube video plays and form interactions.

Two cautions. Scroll tracking only records one depth, near the end of the page, so it says little about long pages. And the form interaction events often miss or misread WordPress forms that submit without reloading the page, so don't treat form_submit as a reliable enquiry count. Track enquiries with your own event, and consider turning form interactions off to avoid confusion.

Tracking form submissions on WordPress

An enquiry should be counted when the form is sent successfully, not when someone clicks the button, because a click on a form with an error isn't an enquiry. There are three common ways:

  1. A thank-you page. Redirect the form to a page such as https://example.com/thank-you/ and fire generate_lead when it loads. It's simple and reliable; thank-you pages explains how to set the redirect in common form plugins and keep the page out of Google.
  2. The form plugin's success event. Many form plugins signal a successful submission in the browser, and some have their own analytics settings or integrations. Contact Form 7, for example, fires a wpcf7mailsent event at the time of writing, which a small script can pass to Tag Manager.
  3. Tag Manager's form submission trigger. It works on some forms, but often misses forms that submit without reloading, so test it carefully.

For Contact Form 7, a script like this, added site-wide after the Tag Manager container, pushes an event that a Tag Manager trigger can listen for:

<script>
document.addEventListener('wpcf7mailsent', function (event) {
  window.dataLayer = window.dataLayer || [];
  window.dataLayer.push({
    event: 'form_submitted',
    form_id: event.detail.contactFormId
  });
});
</script>

In Tag Manager, create a Custom Event trigger for form_submitted, and a GA4 Event tag named generate_lead that fires on it, with the form ID as a parameter if you have several forms.

Tracking WhatsApp clicks and calls with Google Tag Manager

Tag Manager suits WordPress sites well, because you can add and change tracking without editing the theme. If you're new to it, Google Tag Manager basics explains tags, triggers and variables first. Then:

  1. Under Variables, click Configure and turn on the built-in Click URL, Click Text and Page Path variables.
  2. Create a trigger of type Click - Just Links, set to fire on some link clicks where Click URL contains wa.me. Add a second condition or trigger for api.whatsapp.com if your buttons use that address.
  3. Create a Google Analytics: GA4 Event tag with your measurement ID, the event name contact_whatsapp and useful parameters, and attach the trigger.
  4. Repeat for calls, with a trigger where Click URL starts with tel: and an event named contact_call.
  5. Test in Preview mode, then publish the container.

The WhatsApp setup looks like this:

Trigger:  WhatsApp click
  Type:        Click - Just Links
  Fires on:    Some Link Clicks
  Condition:   Click URL contains wa.me

Tag:      GA4 event - contact_whatsapp
  Type:        Google Analytics: GA4 Event
  Measurement ID:  G-XXXXXXXXXX
  Event name:  contact_whatsapp
  Parameters:  link_url  = {{Click URL}}
               page_path = {{Page Path}}
  Trigger:     WhatsApp click

A tap on a WhatsApp or phone link shows intent, not a conversation that happened. Call tracking for small businesses covers ways to measure real calls and chats.

Sending events without Tag Manager

If GA4 is added directly with the gtag snippet, events can be sent from your own JavaScript instead. This site does it that way, with lines like these:

gtag('event', 'contact_whatsapp', { link_text: 'WhatsApp Me' });
gtag('event', 'generate_lead', { form_name: 'contact' });

It's lighter than Tag Manager but needs a developer for every change. Either way, use one method per event, or you'll count everything twice.

Marking key events

Once an event has been received, open Admin > Data display > Events and turn on Mark as key event for it. You can also create a key event by name under Key events before it has fired. If you run Google Ads, import the same key events as conversions, or set up the Ads tag, as Google Ads conversion tracking on WordPress explains.

Testing with DebugView and Realtime

  1. Open Tag Manager's Preview mode, which connects Tag Assistant to your site, or use a GA4 debugging extension if you send events without Tag Manager.
  2. On the site, submit a real test enquiry, tap the WhatsApp button and tap the phone link.
  3. In Tag Assistant, check that each tag fired once, with the right parameters.
  4. In GA4, open Admin > Data display > DebugView and confirm each event arrives with its parameters.
  5. Check the Realtime report as well, then allow a day or two before events appear in standard reports.

If GA4 shows nothing at all, work through GA4 not showing data on WordPress.

Reading events in your reports

Reports > Engagement > Events lists every event and its count. Key events also appear as a column in the Traffic acquisition and Landing page reports, which is where they become useful: which channels and which pages produce enquiries. To see a custom parameter, such as the form name, register it under Admin > Custom definitions first. Website analytics metrics that matter suggests a monthly routine for reading them.

FAQs

What is the difference between an event and a key event in GA4?

An event is any interaction GA4 records. A key event is an event you've marked as a business outcome, such as an enquiry or purchase, so it's counted separately in reports.

Does GA4 track form submissions automatically?

Enhanced measurement tries to, but it often misses or misreads WordPress forms. Send your own event on a thank-you page or on the form's success event instead.

How do I track WhatsApp clicks in GA4?

In Google Tag Manager, create a link click trigger for URLs containing wa.me and a GA4 Event tag such as contact_whatsapp, then mark it as a key event. Without Tag Manager, send the same event with gtag code on the button.

Why don't my GA4 events show in reports?

Standard reports can take a day or two to update. Check DebugView and Realtime first; if events are missing there too, the tag or trigger isn't firing.

Do I need Google Tag Manager for GA4 events?

No. Events can be sent with gtag code directly. Tag Manager makes it easier to add and change tracking without editing the site's code, which suits most WordPress sites.
