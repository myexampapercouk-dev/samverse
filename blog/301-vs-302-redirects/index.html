301 vs 302 Redirects: The Difference, Which to Use, How They Affect SEO and How to Set Them Up in WordPress

301 vs 302: a 301 is a permanent redirect, a 302 is temporary. Learn which to use, how each affects SEO, common mistakes and how to set them up in WordPress.

Key takeaways
  • Use a 301 when a page has moved for good, and a 302 only when the original URL will genuinely come back, such as during short maintenance or a test.
  • A 301 tells Google to replace the old URL with the new one in results; a long-running 302 keeps Google guessing and can leave the old URL indexed.
  • Avoid redirect chains, redirecting everything to the homepage and forgetting to update internal links, sitemaps and canonicals after a redirect.

The difference between a 301 and a 302 redirect is that a 301 means a page has moved permanently, while a 302 means it has moved temporarily and the original URL will return. For SEO, use a 301 whenever the change is permanent, such as a new URL, a deleted page with a replacement or a domain change, so Google moves the old page's signals to the new address and shows the new URL in results.

Short answer: 301 = permanent, pass signals and replace the old URL. 302 = temporary, keep the old URL in Google's index. If you are not sure which you need, ask "will the old URL ever be used again?" If the answer is no, use a 301.

301 vs 302: what each redirect means

A redirect is an instruction from your server that says "the page you asked for is somewhere else". The number is the HTTP status code that comes with it, and it tells browsers and search engines how to treat the move.

301 Moved Permanently302 Found (temporary)
MeaningThe page has moved for goodThe page is elsewhere for now
URL Google showsUsually the new URLUsually the old URL
Ranking signalsConsolidated on the new URLGenerally kept with the old URL while it is treated as temporary
Browser cachingBrowsers may cache it for a long timeNot cached by default
Typical useURL changes, merged pages, domain or HTTPS movesShort maintenance, A/B tests, seasonal or out-of-stock pages

There are also 307 (temporary, keeps the request method) and 308 (permanent, keeps the request method). For most business websites, 301 and 302 cover everything you need.

301 vs 302 for SEO: does it really matter?

Google has said that all redirect types pass ranking signals, and that a 302 left in place long enough may eventually be treated like a 301. So a wrong redirect is rarely a disaster. But it still matters, for three reasons:

  • Which URL gets indexed: with a 302, Google tends to keep showing the old URL, because you told it the move is temporary. That can leave outdated URLs in search results for months.
  • Speed of consolidation: a 301 is a clear signal, so Google updates its index faster. A 302 makes Google wait and guess.
  • Clarity for other tools: other search engines, SEO tools and AI crawlers may not be as forgiving, and a clear 301 removes doubt.

The redirect is one signal among several. Google also looks at your canonical tags, internal links and sitemap. When all of these point to the same new URL, the move is clean.

When to use a 301 redirect

  • You changed a page's URL or slug, for example to make it shorter and cleaner (see SEO-friendly URLs).
  • You merged two thin pages or posts into one stronger page.
  • You deleted a page or product and there is a close replacement.
  • You moved from HTTP to HTTPS, or from www to non-www.
  • You moved to a new domain. Our guide to changing your domain without losing SEO covers the full process.
  • You redesigned the site and the URL structure changed. See redesigning without losing rankings.

When to use a 302 redirect

  • The page is down for short maintenance and you are sending visitors to a notice page.
  • You are running a test and sending some traffic to a variant page.
  • A seasonal page, such as a festival offer, temporarily points to the main category until next season.
  • Visitors are redirected by location or language, and the original URL still matters.
  • A product is temporarily out of stock and you want to send people to a similar product for a short time.

If a "temporary" redirect has been in place for months with no plan to remove it, it is not temporary. Change it to a 301.

Common redirect mistakes that hurt SEO

  1. Using 302 for permanent moves. Many plugins and hosting panels default to 302. Always check the type you selected.
  2. Redirect chains. Page A redirects to B, which redirects to C. Each hop slows the visitor and wastes crawl effort. Point A straight to C.
  3. Redirect loops. A goes to B, B goes back to A, and the browser shows "too many redirects". See how to fix the too many redirects error.
  4. Redirecting everything to the homepage. When an old page has no close match, sending it to the homepage is often treated by Google as a soft 404. A helpful 404 page is usually better than an irrelevant redirect (see helpful 404 pages).
  5. Not updating internal links. Your menus, buttons and posts should link straight to the new URL, not through the redirect.
  6. Leaving old URLs in the sitemap. Your XML sitemap should list only final URLs that return 200.
  7. Removing redirects too soon. Keep 301s for at least a year, and ideally permanently if old links still point to them.

How to set up 301 and 302 redirects in WordPress

Option 1: a redirect plugin

The simplest way for most owners is a redirect plugin or the redirect manager in an SEO plugin. You enter the old path, the new URL and choose 301 or 302. Many also log 404 errors, so you can spot broken URLs and redirect them. Our WordPress SEO plugins comparison covers which include redirects.

Option 2: the .htaccess file (Apache and LiteSpeed)

On Apache or LiteSpeed hosting, which includes many Indian shared hosts and Hostinger, redirects can go in .htaccess. They run before WordPress loads, so they are fast. A permanent redirect looks like this:

Redirect 301 /old-page/ https://example.com/new-page/

Edit .htaccess carefully and keep a copy first, because one typo can take the whole site down.

Option 3: Nginx or Cloudflare

On Nginx servers, redirects go in the server configuration, usually through your host. If your site uses Cloudflare, you can create redirect rules there and choose 301 or 302 for each. See our Cloudflare setup guide for WordPress.

Option 4: changing a slug in WordPress

When you change a post slug, WordPress often redirects the old one automatically. It is not reliable for pages, products or bulk changes, so add a proper 301 yourself.

How to check whether a redirect is 301 or 302

  • Use a free online HTTP status or redirect checker. Paste the old URL and it shows each hop and its status code.
  • In Chrome, open Developer Tools, go to the Network tab, tick "Preserve log" and load the old URL. The first request shows the status code.
  • In Google Search Console, use URL Inspection on the old URL. It shows "Page with redirect" and the final URL Google chose.
  • Crawl the site with an SEO crawler to list every redirect, chain and loop in one go.

A simple redirect checklist

  1. List every old URL that is changing, with its best new match.
  2. Use 301 for permanent changes and 302 only for genuinely temporary ones.
  3. Redirect one-to-one, old page to the closest new page.
  4. Remove chains so every old URL points straight to the final URL.
  5. Update internal links, menus, canonicals and the sitemap.
  6. Test a sample of old URLs, then watch Search Console's Pages report for a few weeks.

FAQs

What is the difference between a 301 and 302 redirect?

A 301 redirect tells browsers and search engines a page has moved permanently. A 302 says the move is temporary and the original URL will come back, so search engines usually keep the old URL indexed.

Is a 301 or 302 better for SEO?

For permanent changes, a 301 is better because it clearly tells Google to replace the old URL with the new one and consolidate signals. A 302 is only better when the move really is temporary.

Does a 302 redirect lose SEO value?

Google says 302s can pass signals, but because they signal a temporary move, the old URL tends to stay in results and consolidation is slower. For a permanent move, switch it to a 301.

How long should I keep a 301 redirect?

At least a year, and longer if other websites or old emails still link to the old URL. Keeping a 301 in place has very little cost.

Should I redirect deleted pages to the homepage?

Only if the homepage is genuinely the best replacement. Otherwise redirect to the closest relevant page, or return a 404 or 410 with a helpful page.

Can too many redirects slow down my website?

A single redirect adds a small delay. Chains of several redirects add more and can stop crawlers following them, so always point old URLs straight to the final destination.
