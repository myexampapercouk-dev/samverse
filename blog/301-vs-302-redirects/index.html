301 vs 302 Redirects: Which to Use, How They Affect SEO and How to Set Them Up in WordPress

301 vs 302 redirects explained: permanent vs temporary, 307 and 308, the SEO effect, chains and loops, and setting up redirects in WordPress and .htaccess.

Key takeaways
  • A 301 says a page has moved for good, so Google moves its ranking signals to the new URL; a 302 says the move is temporary, so Google keeps showing the old URL.
  • Use a 301 for almost every real change, point each old URL straight at its closest equivalent in one hop, and keep the redirect for at least a year.
  • Manage page redirects in one place, such as the Redirection plugin or Rank Math, keep site-wide rules at server level, and test in a private window because browsers cache 301s.

A 301 redirect tells browsers and search engines that a page has moved permanently, so Google transfers indexing and ranking signals to the new URL. A 302 says the move is temporary, so Google keeps the original URL in its results and expects it back. Use a 301 for almost every real change, such as a new slug, a merged page, a new domain or the switch to https, and keep 302s for situations where the old URL genuinely returns. Whichever you use, send each old URL straight to its closest equivalent in a single hop.

Redirects are where most redesigns and migrations quietly lose rankings. In my WordPress migration work, every old URL that changes is 301-redirected to its new equivalent and Search Console is monitored after the move. This guide covers which redirect to use, what each does to SEO, and how to set them up on WordPress.

If a redirect has gone wrong and your site now shows "too many redirects", go straight to fixing ERR_TOO_MANY_REDIRECTS in WordPress.

When to use a 301

  • You changed a page or post URL, including a permalink structure change; see SEO-friendly URLs in WordPress before changing any.
  • You merged pages, such as two thin posts on the same topic combined into one stronger article.
  • You removed a page that has a close replacement, such as a discontinued product with a direct successor.
  • You moved to https, or settled on one version of the domain (www or non-www).
  • You changed domain or platform, such as a rebrand or a move from Wix to WordPress, where every old URL needs mapping; changing your domain without losing SEO walks through the domain case.

When a 302 or 307 is the right choice

  • The original URL will come back. For example, a menu link to an offers page temporarily sending visitors to a festival sale page for a fortnight.
  • Split-testing two page URLs. Google's own advice for A/B tests that redirect visitors is to use a temporary redirect, so the original stays indexed.

And when neither is right:

  • Maintenance or downtime: return a 503 status, which tells Google to come back later. Good maintenance-mode plugins do this, and so does WordPress during core updates. Redirecting every page to a "back soon" page looks like a permanent change.
  • Temporarily out-of-stock products: keep the page live with a back-in-stock note rather than redirecting it.
  • Language or country detection: automatic redirects based on location can stop Google seeing your other versions. Offer a visible choice instead.

If a permanent move was set up as a 302 by mistake, Google may eventually treat a long-standing 302 as permanent, but there's no reason to wait and see. Change it to a 301.

How redirects affect SEO

Google has said for years that a 301 or 302 doesn't lose ranking value just by being a redirect. When rankings drop after URLs change, it is almost always because of how the redirects were done:

  • Redirecting to an unrelated page. Sending many old URLs to the homepage or a loosely related category looks like a deleted page to Google, which may treat it as a soft 404 and pass nothing on.
  • Missing redirects. Old URLs that 404 lose the links pointing to them and the history Google had built up.
  • Chains, where Google and visitors pass through several hops.
  • Removing redirects too soon. Google's own site-move guidance is to keep them for as long as possible, generally at least a year. External links and bookmarks keep using old URLs for much longer, so I'd leave them in place indefinitely.

Expect some movement in rankings for a few weeks after a large set of redirects while Google recrawls. A redirect is also not the only way to consolidate duplicates: when both URLs must stay usable, a canonical tag is the softer option; see canonical tags explained.

Redirect chains, loops and "Avoid multiple page redirects"

A chain is a redirect that leads to another redirect. A common one on WordPress sites looks like this:

http://example.com/old-page/
  -> https://example.com/old-page/
  -> https://www.example.com/old-page/
  -> https://www.example.com/new-page/

Googlebot follows a limited number of hops, and every hop adds a delay on a slow mobile connection. The fix is for every rule to point at the final URL, so the first request lands on https://www.example.com/new-page/ directly.

PageSpeed Insights flags redirects on the page you test, for years under the name "Avoid multiple page redirects" (newer versions group it with other server response checks). On WordPress the usual causes are internal links or ads still using http or the wrong www version, https being forced in two places (a plugin and the server, or the server and Cloudflare), and an old redirect pointing to a URL that was itself redirected later. Update the old redirect's target, force https in one place only, and replace old URLs in your content and menus. A loop, where A points to B and B back to A, breaks the page entirely and needs the step-by-step checks in the too-many-redirects guide linked above.

Menu names are correct at the time of writing. Pick one home for page-level redirects and one for site-wide rules, and write down which is which. If you ever uninstall a redirect plugin, export its redirects first, because they stop working the moment it is deactivated.

.htaccess examples

Take a backup of the file first, and place your rules above the "# BEGIN WordPress" line, since WordPress rewrites everything between its own markers:

# Send http to https on one hostname, in one hop
RewriteEngine On
RewriteCond %{HTTPS} off
RewriteRule ^(.*)$ https://example.com/$1 [R=301,L]

# Send one old page to its new address
RewriteRule ^old-services/?$ https://example.com/services/ [R=301,L]

If your site sits behind Cloudflare or a host's proxy, the https check above can cause a loop, because the server may see every request as plain http. In that case, force https with your host's or Cloudflare's own setting instead.

A redirect checklist for changed URLs

  1. List every old URL: a crawl of the site, your XML sitemap, Search Console's top pages and GA4 landing pages.
  2. Map each one to its closest new equivalent in a spreadsheet. Only URLs with no equivalent and no traffic or links should be left to return a 404 or 410, with a helpful 404 page to catch visitors.
  3. Create 301s that go to the final URL in one hop.
  4. Update internal links, menus, buttons and your sitemap to the new URLs, so you aren't relying on redirects for your own links.
  5. Test old URLs in a private window, because browsers cache 301s and can show you an old result, or use a redirect checker that lists every hop.
  6. Watch Search Console's Pages report for new 404s over the following weeks. Old URLs showing as "Page with redirect" are expected.

FAQs

What is the difference between a 301 and a 302 redirect?

A 301 means the page has moved permanently, so Google indexes the new URL and moves its signals there. A 302 means the move is temporary, so Google usually keeps the original URL indexed. Visitors see the same thing with both.

Does a 301 redirect hurt SEO?

Not by itself. Problems come from redirecting to unrelated pages, chains of several hops, missing redirects for pages that had links, and removing redirects too early.

How long should I keep a 301 redirect?

Google recommends keeping redirects from a site move for as long as possible, generally at least a year. Since old links and bookmarks keep working only while the redirect exists, leaving them in place permanently is the safer choice.

How do I fix "Avoid multiple page redirects" in WordPress?

Find the chain with a redirect checker, then make every rule point to the final URL, force https in only one place, and update internal links and ads that use old, http or wrong-www addresses.

Can I redirect a deleted page to my homepage?

Only if the homepage genuinely replaces it. Otherwise Google tends to treat it as a soft 404. Redirect to the closest related page, or let the URL return a 404 or 410 if nothing related exists.
