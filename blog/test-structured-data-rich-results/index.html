Rich Snippet Testing Tool: How to Check Rich Snippets and Test Structured Data in WordPress

The best rich snippet testing tool is Google's Rich Results Test. Learn how to check rich snippets, read errors and warnings, and fix schema in WordPress.

Key takeaways
  • Google's Rich Results Test is the main rich snippet testing tool: it shows which rich results a page is eligible for and lists errors and warnings.
  • Use the Schema Markup Validator to check all schema.org markup, and Search Console enhancement reports to monitor rich snippets across the whole site.
  • Valid markup makes a page eligible, not guaranteed: Google still decides whether to show a rich snippet based on quality, relevance and its own policies.

The main rich snippet testing tool is Google's Rich Results Test: paste a URL or code and it tells you which rich results (such as FAQ, product, review, breadcrumb or article snippets) the page is eligible for, and lists any errors or warnings in the structured data. To check rich snippets across your whole site, use the enhancement reports in Google Search Console, and use the Schema Markup Validator when you want to check schema types Google does not show as rich results.

Short answer: test a single page with the Rich Results Test, validate general schema with the Schema Markup Validator, and monitor the whole site in Search Console. Fix errors first (they block eligibility), then warnings (they limit what can be shown), then re-test and request indexing.

What is a rich snippet, and why test it?

A rich snippet is a search result with extra information, such as star ratings, price and stock, breadcrumbs, event dates or recipe details. They come from structured data, usually schema markup added as JSON-LD in the page code.

Testing matters because small mistakes, such as a missing price, a wrong date format or markup that does not match the visible page, quietly stop Google from using it. Nothing breaks on the page itself, so you only find out by checking.

How to check rich snippets with the Rich Results Test

  1. Open the Rich Results Test and choose URL or Code. Use URL for live pages and Code to test markup before you publish it.
  2. Pick the crawler. Smartphone is the default and matches how Google indexes most sites.
  3. Read the summary. It says "Page is eligible for rich results" or "Not eligible", and lists each detected item, such as Product snippets, Breadcrumbs or FAQ.
  4. Open each item. Errors are shown in red and warnings in amber, with the field name that caused them.
  5. Check the rendered HTML. If your schema is added by JavaScript, look at the rendered page to make sure Google actually sees it.
  6. Preview the result where available, to see roughly how the snippet could look.

Errors vs warnings: what to fix first

Errors mean a required property is missing or invalid, so that item cannot appear as a rich result. Common examples:

  • Product markup with no offers, review or aggregateRating.
  • Missing name, or an invalid price or currency format.
  • Invalid dates (Google expects ISO 8601, such as 2026-11-15).
  • Broken JSON, such as a missing comma or quote, which makes the whole block unreadable.

Warnings mean a recommended property is missing. The item is still valid, but Google has less to show. Examples include a missing brand, SKU, priceValidUntil or review author. Fix the ones that are true and useful; never fill fields with made-up data just to clear a warning.

How to fix common structured data problems in WordPress

Most WordPress sites get schema from an SEO plugin, WooCommerce, the theme or a page builder. Problems often come from these overlapping.

Duplicate or conflicting schema

If the theme, an SEO plugin and a schema plugin all output Organization or Product markup, Google sees two versions with different details. Choose one source, and switch schema off in the others. Our SEO plugins comparison explains where each adds markup.

WooCommerce product errors

WooCommerce adds product schema automatically. Errors usually come from products with no price (variable products with no variations set up), no reviews, or stock settings that are blank. See our WooCommerce SEO guide and Merchant Center setup, which relies on the same data.

Markup that does not match the page

Google's policies require structured data to describe content visible on the page. Ratings that do not appear on the page, prices that differ from the visible price, or reviews written by the business about itself can lead to rich results being dropped or a manual action.

FAQ and HowTo expectations

Google now shows FAQ rich results only for a limited set of authoritative sites and has stopped showing HowTo rich results. FAQ markup can still be valid, and the questions still help readers and AI search, but do not expect FAQ snippets in most cases. See FAQ pages for SEO.

Breadcrumb errors

Breadcrumb schema needs a name and item URL for each level. Missing levels usually come from theme breadcrumbs and plugin breadcrumbs disagreeing. Read breadcrumbs explained.

Monitoring rich snippets across the whole site

Testing one page is useful, but problems usually affect templates, so they repeat across many pages. In Search Console, the enhancement reports (under Shopping, Enhancements or Experience, depending on the type) group items into valid and invalid, with example URLs for each issue.

  1. Open the report for the schema type, such as Product snippets or Breadcrumbs.
  2. Click an issue to see affected pages, and test one in the Rich Results Test.
  3. Fix the template or plugin setting, not just one page.
  4. Click Validate Fix so Google re-checks the affected URLs over the following days.

Our guide to Search Console reports walks through where each report lives.

Why valid schema still shows no rich snippet

A green "eligible" result does not guarantee a rich snippet. Google may not show one because:

  • The page has not been recrawled since you fixed it. Use URL Inspection and request indexing.
  • The site or page does not meet Google's quality expectations for that feature.
  • The search query does not suit a rich result.
  • The rich result type is restricted, as with FAQ, or no longer supported.
  • The markup describes something that is not the main content of the page.

Rich snippets also tend to appear more for pages already ranking well, so they work alongside wider on-page SEO rather than replacing it.

A quick structured data testing checklist

  1. Test your homepage, one service or category page, one product and one blog post in the Rich Results Test.
  2. Run the same pages through the Schema Markup Validator.
  3. Remove duplicate schema so each type comes from one source.
  4. Fix all errors, then any warnings you can fill with real data.
  5. Check that markup matches what visitors see on the page.
  6. Validate the fix in Search Console and recheck in two to four weeks.

FAQs

What is the best rich snippet testing tool?

Google's Rich Results Test is the best place to start, because it shows whether a page is eligible for Google rich results. Pair it with the Schema Markup Validator for general schema checks.

How do I check rich snippets for my whole website?

Use the enhancement and shopping reports in Google Search Console. They list valid and invalid items for each schema type across all crawled pages, with example URLs.

Is Google's Structured Data Testing Tool still available?

No. Google retired it. Use the Rich Results Test for Google features and the Schema Markup Validator at schema.org for general validation.

Why does the Rich Results Test say my page is eligible but no rich snippet shows?

Eligibility only means the markup is valid. Google decides whether to show it based on quality, relevance, the query and feature restrictions. Recrawling can also take time.

Should I fix warnings in the Rich Results Test?

Fix warnings when you have genuine data for the missing field, such as brand or SKU. Warnings do not block eligibility, and you should never add fake values just to clear them.

Can I test structured data before publishing a page?

Yes. Choose the Code option in the Rich Results Test or Schema Markup Validator and paste your HTML or JSON-LD to check it before it goes live.
