How to Test Structured Data: Rich Results Test vs Schema Markup Validator, Reading Errors and Fixing Them in WordPress

How to test structured data: Rich Results Test vs Schema Markup Validator, live URL vs code, errors vs warnings, Search Console validation and fixes.

Key takeaways
  • Use the Rich Results Test to see what Google can use for rich results, the Schema Markup Validator to check any schema.org code, and Search Console to watch the whole site.
  • Fix errors before warnings, and never fill a warning with invented data; most errors trace back to a missing field, a badly formatted value, wrong nesting or two plugins outputting the same type.
  • Test one page of every template after launch and after every SEO plugin, theme or WooCommerce update, purge caches first, then use Validate fix in Search Console.

To test structured data, run the page through two tools: Google's Rich Results Test, which shows which rich result types Google can read from the page and what is stopping them, and the Schema Markup Validator, which checks that the schema.org code itself is valid, including types Google doesn't use for rich results. Then use Search Console's Enhancements reports to catch problems across the whole site, fix errors before warnings, retest and click Validate fix.

Structured data for your business, services, products, articles and breadcrumbs, checked with Google's testing tools, is part of my WordPress SEO services. This guide shows the same checking process so you can run it yourself, read what the tools are telling you, and trace each error back to the plugin, theme or template causing it.

If you are still deciding which types to add, start with schema markup explained. This article assumes markup already exists and covers testing and fixing it.

Step 1: See what is on the page before testing

Open the page, press Ctrl+U and search the source for application/ld+json. Count the blocks you find. A typical WordPress page has one connected block from the SEO plugin, sometimes a second from WooCommerce or a schema plugin. Three or four blocks, or the same type appearing twice, is the first sign of duplication.

The source often tells you which plugin wrote each block. At the time of writing, Yoast SEO's script tag carries a class mentioning yoast-schema-graph and Rank Math's mentions rank-math-schema, and many plugins leave an HTML comment with their name nearby. Old themes may also add microdata straight into the visible HTML, which you can spot as itemtype and itemprop attributes. Note each source for when an error appears.

Step 2: The Rich Results Test, live URL or code

The Rich Results Test offers two modes, and they test different things:

  • URL mode fetches the live page the way Google's smartphone crawler does, runs its JavaScript, and tests the rendered result. This is closest to what Google sees, including markup injected by scripts or tag managers.
  • Code mode tests a snippet or a full page source you paste in. Use it for a staging site behind a password, for markup you are writing before it goes live, or to isolate one block from the rest of the page.

Three things trip people up in URL mode. First, if the test reports that the page couldn't be fetched, a firewall, a bot protection setting or robots.txt may be blocking Google's crawler, which is a bigger problem than the schema. Second, a page cache may serve old markup, so purge your caching plugin, host cache and CDN before retesting a fix. Third, the test reports each detected item separately; a product page might show both Product snippets and Merchant listings, each with its own list of issues.

Testing on staging first is sensible for big schema changes; staging sites explained covers how to set one up.

Step 3: The Schema Markup Validator

The Schema Markup Validator, run by schema.org at validator.schema.org, is the successor to Google's old Structured Data Testing Tool. It checks your markup against the full schema.org vocabulary rather than Google's rules, which makes it the right tool for:

  • Types with no Google rich result, such as Service, ProfessionalService or WebSite, which the Rich Results Test may simply report as "no items detected"
  • Seeing the whole graph: whether the article's author points to the same Person or Organization as the rest of the site, and whether the WebPage links to the right business
  • Spotting misspelt property names and properties used on the wrong type, which the validator flags as not recognised

A clean validator result means the code is well formed, not that Google will show anything.

Errors, warnings and valid items

StatusWhat it meansWhat to do
Error, or invalid itemA required property is missing or a value can't be read, so the item can't produce a rich resultFix first, starting with templates that cover many pages
Warning, or valid with warningsA recommended property is missing; the item is still eligible, with less detailFix only when you genuinely have the information
ValidGoogle can read the item and it is eligibleNothing, but eligibility is not a promise of display

Google's wording varies between tools and has changed over time; Search Console may describe the same split as critical and non-critical issues. The rule doesn't change: a missing optional field is fine, and a made-up rating, brand or price added to silence a warning breaks Google's guidelines.

Wrong nesting and invalid values, side by side

This is a shortened LocalBusiness and Product example. The first version has the two most common mistakes; the second is correct:

Wrong:
"address": "12 Example Road, Kothrud, Pune 411038",
"offers": { "price": "Rs 1,499/-", "availability": "In stock" }

Right:
"address": {
  "@type": "PostalAddress",
  "streetAddress": "12 Example Road, Kothrud",
  "addressLocality": "Pune",
  "postalCode": "411038",
  "addressCountry": "IN"
},
"offers": {
  "@type": "Offer",
  "url": "https://example.com/product/example-product/",
  "price": "1499.00",
  "priceCurrency": "INR",
  "availability": "https://schema.org/InStock"
}

Duplicate schema from two plugins

This is common on sites that have changed SEO plugins or added a separate schema plugin. Rank Math lets you switch off its Schema module from its dashboard; Yoast's output, at the time of writing, can only be removed with a code filter, so it is usually simpler to switch off the other source. Theme microdata may need a theme setting or a child theme. Yoast vs Rank Math vs All in One SEO covers the plugins more broadly, and WooCommerce SEO covers product markup in stores.

Search Console Enhancements reports and validation

Once Google finds a supported type on your pages, Search Console creates a report for it in the left menu, under Enhancements or, for stores, Shopping, at the time of writing. Breadcrumbs, Product snippets, Merchant listings and Review snippets are typical. There is also an Unparsable structured data report for code Google couldn't read at all.

  1. Open the report and click an issue to see example URLs.
  2. Open one example in the Rich Results Test, find the item and the field, and trace it to its source using your list from step 1.
  3. Fix the template or setting, not one page, so every affected page is fixed at once.
  4. Purge caches and retest two or three example URLs.
  5. Click Validate fix. Google rechecks the affected URLs over the following days or weeks, and the status moves through started and passed, or failed.

A failed validation means at least one affected URL still showed the issue when Google rechecked it, often a page using a different template. Fix that template and validate again. For the other reports, see Search Console reports explained.

Testing after plugin and theme updates

Structured data breaks quietly. Nothing changes on screen when an update changes a plugin's schema output or a theme starts adding its own. Keep a short list with one URL per template: home, a service page, a blog post, a simple product, a variable product, a category and the contact page. Then:

  • After any SEO plugin, schema plugin, theme or WooCommerce update, purge caches and run each URL through the Rich Results Test
  • Compare the detected items with your last notes; a missing type or a new duplicate is the warning sign
  • After switching SEO plugins, deactivate the old one fully once its settings are imported, then test every template
  • Once a month, check the Enhancements reports for a drop in valid items

How to update WordPress safely covers backups and staging for those updates.

Valid, but no rich result?

Passing the tests makes a page eligible, nothing more; Google decides per search whether to show a rich result, and it has narrowed several features: FAQ rich results are now limited to a small group of authoritative sites, so check FAQs for SEO before expecting dropdowns, and review stars aren't shown for reviews a business marks up about itself on its own LocalBusiness or Organization markup. Check Google's current documentation for supported types.

FAQs

What is the difference between the Rich Results Test and the Schema Markup Validator?

The Rich Results Test checks markup against Google's requirements for rich results and only reports types Google supports. The Schema Markup Validator checks any schema.org markup for valid syntax and vocabulary, but says nothing about Google eligibility.

Why does the Rich Results Test say no items were detected?

Either the page has no markup Google uses for rich results, which is normal for Service or WebSite markup, or the markup didn't load for Google's crawler. Check the source, then run the URL through the Schema Markup Validator.

Do structured data warnings hurt rankings?

No. A warning means a recommended field is missing; the item stays eligible. Fill it only with accurate information.

How long does Search Console take to validate a fix?

It varies with how often Google crawls your pages, from a few days to a couple of weeks or more. Retest a few URLs yourself first so you only start validation once the fix is live.

Why does Search Console still show errors I have fixed?

The reports reflect Google's last crawl, so they lag behind your changes. Check that caches are purged, use Test live URL in URL Inspection to confirm Google sees the fix, then validate.
