WordPress Auto-Updates: Should You Turn Them On for Core, Plugins and Themes?

Which WordPress auto-updates to turn on for core, plugins and themes, the real risks, WooCommerce cautions, backups and staging, and how to roll back an update.

Key takeaways
  • Leave minor core updates, translations and small, well-maintained plugins on auto-update, but update major core releases, page builders, WooCommerce and your theme by hand after testing.
  • Auto-updates only roll back fatal errors, so broken layouts, silent form failures and expired premium licences still need daily backups, uptime monitoring, a monitored admin email and a weekly check.
  • Use staging for stores, major versions and PHP changes, check exactly what your host's managed updates cover, and keep a recent backup, because restoring it is the most reliable rollback.

WordPress can update itself in the background: core, plugins, themes and translations. It sounds like the perfect way to stay secure without effort, and for some parts of your site it is. For others, an update that arrives at 3am can break a layout, a form or your checkout before anyone notices.

The short answer: for most business sites, leave minor core updates and translations on, turn on auto-updates for small, well-maintained plugins, and update major core releases, your theme, page builder and anything to do with WooCommerce or payments by hand, after a backup and ideally a test on staging. Here's what each setting does and how to decide.

This article is about the auto-update settings themselves. For the hands-on process of updating by hand, see how to update WordPress safely.

What each auto-update setting does

WordPress version numbers explain the first two rows. A change in the first two numbers, such as 6.7 to 6.8, is a major release with new features and bigger changes. A change in the third number, such as 6.8.1 to 6.8.2, is a minor maintenance or security release.

SettingWhere to find itWhat it does
Minor core updatesOn by defaultInstalls maintenance and security releases automatically
Major core updatesDashboard > UpdatesMoves your site to new major versions of WordPress without asking
Plugin auto-updatesPlugins screen, per pluginInstalls each new version of that plugin as soon as WordPress picks it up
Theme auto-updatesAppearance > Themes, in the theme detailsUpdates that theme automatically
TranslationsAutomaticKeeps language files for core, plugins and themes current

A few details worth knowing:

  • Plugin and theme auto-updates are off by default in WordPress itself, though some hosts switch them on. Whether major core updates are on can depend on when and how the site was installed, so check Dashboard > Updates rather than assuming.
  • Auto-updates run through WordPress's built-in scheduler, which relies on site visits, so on quiet sites they can happen later than you expect; see WP-Cron explained.
  • WordPress emails the site's admin address after auto-updates. If that address is an old developer's inbox, nobody hears about failures.
  • Some hosts manage updates themselves or hide these toggles. If a setting is missing or greyed out, check with your host or developer.

How to turn auto-updates on or off

  1. Core: go to Dashboard > Updates. Near the top, WordPress says whether the site updates automatically for maintenance and security releases only, or for all new versions, with a link to switch.
  2. Plugins: go to Plugins > Installed Plugins. The Automatic Updates column has an "Enable auto-updates" or "Disable auto-updates" link for each plugin, and the bulk actions menu changes several at once.
  3. Themes: go to Appearance > Themes, click a theme to open its details and use the auto-updates link.

Developers can also fix these rules in code so they can't be changed by accident. For example, this line in wp-config.php limits core to minor updates:

define( 'WP_AUTO_UPDATE_CORE', 'minor' );

Setting it to true allows all core updates, and false turns core auto-updates off. Plugins and themes can be controlled with filters in a small site-specific plugin. If the dashboard toggles are missing, something like this is probably already in place.

The case for turning them on

Outdated plugins are one of the most common ways WordPress sites get hacked. When a security fix is released, auto-updates get it onto your site within hours rather than whenever someone remembers to log in. They make most sense when:

  • Nobody on your team logs into the dashboard every week
  • The site is a simple brochure site with a handful of well-maintained plugins
  • The plugin in question is small and single-purpose, from an established developer

The risks

Breaking changes

Major versions of page builders, WooCommerce and themes sometimes change how things work. Theme templates that override WooCommerce can go out of date, and a new version may need a newer PHP version than your hosting runs. If a page builder update scrambles your design, see Elementor layout broken after an update.

Silent breakage

Recent WordPress versions can roll back a plugin auto-update that causes a fatal error. But a misaligned layout, a contact form that stops sending emails or a checkout bug isn't a fatal error, so nothing rolls back, and you may not notice for days.

Bad timing

An update can land in the middle of a festival sale or a paid ad campaign, exactly when a broken page costs you most.

Premium plugins that don't auto-update

Premium plugins and themes update through their own licence system. If the licence has expired, no updates arrive at all, even with the toggle switched on. Plugins bundled with a premium theme often only update when the theme itself does; see how to update a premium theme and its bundled plugins.

WooCommerce needs extra caution

A store has more moving parts than a brochure site, and they all touch money:

  • Frequent releases: WooCommerce is updated often, and major versions can change how the cart, checkout or order storage work.
  • Database updates: some versions update the store's database, either automatically or after you confirm a prompt. Plugin files can be rolled back; database changes are much harder to undo without a backup.
  • Outdated template overrides: WooCommerce > Status lists templates your theme overrides and flags outdated ones.
  • Payment, shipping and invoice extensions often need to move in step with WooCommerce, and a broken payment gateway may not show any visible error.

For most stores the safe pattern is auto-updates off for WooCommerce, its extensions, payment gateways and the theme, with updates tested on staging, then applied live at a quiet time and followed by a test order. The WooCommerce maintenance checklist covers the routine around this.

Managed hosting and maintenance-service updates

Some managed WordPress hosts and maintenance services run updates for you. The more careful ones take a backup first, compare screenshots of key pages before and after, and roll back if something looks different. Others simply switch on WordPress's own auto-updates. Before relying on one, ask:

  • Does it cover core only, or plugins, themes and premium plugins too?
  • When do updates run, and can you exclude plugins or pause updates during a sale?
  • Is a backup taken immediately before each update?
  • Which pages are checked afterwards, and does anyone test the checkout or forms?
  • Who is told when an update fails or is rolled back?

Safety nets to put in place first

  • Daily automatic backups stored away from your hosting account, so you can restore yesterday's site. See the backup and restore guide.
  • Uptime monitoring that alerts you when the site goes down. It catches outages and fatal errors, not broken layouts. See uptime monitoring explained.
  • A monitored admin email. Update reports go there, and so does the recovery-mode link WordPress sends when a plugin causes a fatal error. If you do see "There has been a critical error on this website", follow this step-by-step fix.
  • A quick weekly check: open the homepage on your phone, send a test enquiry through the contact form and, for stores, add something to the cart.

When to use staging instead

A staging site is a private copy of your website where you can test updates before they touch the live site. It's worth using when you run a store or take bookings and payments, when a major version of your page builder, WooCommerce or theme is released, when you're changing the PHP version, when the site has custom code or a long list of plugins, and before a big campaign or sale.

One catch: auto-updates on the live site don't wait for your staging tests. For any plugin you want to test first, switch its auto-update off on the live site. See staging sites explained for how to set one up.

Rollback options when an update goes wrong

  • Automatic rollback of fatal errors: in recent WordPress versions, if a plugin auto-update causes a fatal error, WordPress tries to restore the previous version. It doesn't catch layout, form or checkout problems.
  • Failed-update protection: WordPress also keeps a temporary copy of a plugin or theme while updating, so an update that fails part-way can be restored. If the site gets stuck on a maintenance message, see WordPress stuck in maintenance mode.
  • Reinstall the previous version: older versions of free plugins are usually available on their WordPress.org page (under Advanced View at the time of writing), and premium vendors often offer them in your account. This replaces files only; it doesn't undo database changes.
  • Restore a backup or host snapshot: the most reliable option, especially after updates that changed the database.

Make it someone's job

Whatever you choose, someone should own it. Once a month, review which plugins are set to auto-update, check that premium licences are active, delete anything unused and read through the update emails for failures. The WordPress maintenance checklist shows where this fits alongside backups, security and speed checks.

FAQs

Are WordPress auto-updates safe?

Minor core updates and small, well-maintained plugins are generally low risk. Larger plugins, themes and WooCommerce carry more risk, so they're safer updated by hand with a backup ready. Safety depends less on the setting than on having backups and someone checking the site.

Does WordPress update itself automatically by default?

Minor core releases and translations, yes. Plugin and theme auto-updates are off unless you or your host switch them on, and major core updates depend on your settings, so check Dashboard > Updates.

Should I turn on auto-updates for WooCommerce?

For most live stores, no. Update WooCommerce and its extensions by hand after testing on staging, at a quiet time, and place a test order afterwards.

Why didn't a plugin update automatically?

Common reasons: an expired premium licence, the new version needing a newer PHP or WordPress version, WP-Cron not running on a quiet site, file permission problems, or your host controlling updates.

Can I choose what time auto-updates run?

Not from the WordPress dashboard. Some hosts and maintenance tools let you schedule updates; otherwise, switch auto-updates off for important plugins and update them yourself at a quiet time.
