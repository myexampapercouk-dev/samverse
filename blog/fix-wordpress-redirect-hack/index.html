WordPress Site Redirecting to Spam? How to Find and Remove the Redirect Hack

WordPress site redirecting to spam? Catch the hidden redirect, find the malware in .htaccess, wp-config, themes or the database and remove it for good.

Key takeaways
  • If your WordPress site redirects visitors to spam and you did not set it up, it is almost always malware that targets mobile visitors from Google while hiding from logged-in admins.
  • Redirect malware hides in .htaccess, wp-config.php, index.php, theme files, JavaScript files, the database, fake plugins, mu-plugins and cron jobs, so check every location rather than trusting one scan.
  • Removing the visible code is not enough: replace core, plugins and themes, remove backdoors, change every password, purge every cache and close the entry point, or the redirect comes back.

If your WordPress site is redirecting to spam (gambling, dating, fake prize or "your phone has a virus" pages) and you didn't set the redirect up, your site has been hacked with redirect malware. The code usually targets mobile visitors arriving from Google while hiding from logged-in admins, which is why the site looks normal when you check it yourself.

Below: how to rule out harmless causes, how to catch the hidden redirect, a table of where the malware lives, and a step-by-step removal checklist. Redirect hacks often come back when a backdoor is missed; if you would rather have it handled, see my WordPress malware removal service.

First, make sure it's really a hack

A few harmless things can look like a redirect hack. Rule them out quickly:

  • A redirect rule you or your developer added. Check any redirect plugin and your SEO plugin's redirect settings.
  • "Too many redirects" errors are a settings loop, not spam; see fixing ERR_TOO_MANY_REDIRECTS.
  • Ads or third-party scripts. A bad ad or a compromised widget script can redirect visitors without your site files being hacked.
  • Only one person sees it. Adware or a browser extension on their own device may be the cause. Ask whether it happens on other devices.
  • Domain or DNS problems. An expired domain or changed DNS records can send all visitors to someone else's server.

If it happens to different people on different devices and you didn't set it up, treat it as malware. For the wider warning signs, see how to know if your WordPress site has been hacked.

Why a hacked WordPress redirect hides from you

Redirect malware is usually conditional. The code checks who is visiting before deciding whether to redirect:

  • Device: it reads the user agent and targets phones, because owners mostly check on a computer
  • Referrer: it redirects people arriving from Google, Facebook or other search engines, but not people who type your address
  • Logged-in status: it looks for the WordPress login cookie and leaves administrators alone
  • Once per visitor: it sets a cookie so the second visit looks normal
  • Location or IP: it targets certain countries, or skips IP addresses that have used the dashboard

That is also why one quick check from your office computer proves nothing: test the way a real visitor arrives, on a phone, from a search result, logged out and without old cookies.

Caching adds another layer. Logged-out visitors get cached pages while admins bypass the cache, so an infected cached page can keep redirecting visitors after the code is removed.

How to catch the redirect

  1. Phone test: switch off Wi-Fi, open a private tab, search Google for your business and tap your result. Use a fresh private tab for each attempt.
  2. Desktop test: in Chrome DevTools, turn on device emulation, open the Network tab, tick "Preserve log", then visit your site from a Google result and watch for unfamiliar domains.
  3. View the page source: search for script tags loading from unfamiliar domains, and for scrambled code containing things like eval(, atob( or String.fromCharCode.
  4. Remote scanner: an online scanner fetches your pages as a visitor would and flags known redirect code; see WordPress malware scanners compared.
  5. Search Console: check the Security issues report for hacked content or malware warnings.

If you're comfortable with a terminal, you can pretend to be a mobile visitor arriving from Google:

curl -sI -A "Mozilla/5.0 (iPhone)" -e "https://www.google.com/" https://yourdomain.com/

A Location: header pointing to another domain means a server-side redirect. JavaScript redirects only run in a browser, so use the browser tests as well.

Where WordPress redirect malware hides

.htaccess files

On Apache and LiteSpeed hosting, .htaccess runs before WordPress loads. A malicious rule often looks like this:

RewriteEngine On
RewriteCond %{HTTP_REFERER} (google|bing|facebook) [NC]
RewriteCond %{HTTP_USER_AGENT} (android|iphone|mobile) [NC]
RewriteRule ^(.*)$ https://spam-domain.example/ [R=302,L]

That rule redirects only mobile visitors arriving from search or Facebook. Check .htaccess in your main folder, in subfolders such as wp-content and uploads, and in any folder above your site. Keep the standard # BEGIN WordPress block and rules you can explain, such as those from your caching or security plugin.

wp-config.php and index.php

These files load on every request. Look for code before the normal opening <?php line, long encoded strings, or an include of a strange file disguised with an image or icon extension:

<?php @include "/home/account/public_html/wp-content/uploads/2024/03/.cache.ico"; ?>

The root index.php in a normal WordPress install is only a few lines long. If yours is much longer, compare it with a fresh download.

Theme and JavaScript files

Check header.php, footer.php and functions.php in your theme and child theme. Injected scripts are often disguised as jQuery, analytics or a CDN file:

<script src="https://cdn-jquery-min.example/jquery.min.js"></script>

Also look for PHP that reads HTTP_USER_AGENT or HTTP_REFERER, and for long scrambled lines appended to theme and plugin .js files. Sort by last modified date and compare suspicious files with clean copies.

The database

Redirect scripts are often injected into posts, widgets, theme options or "header and footer scripts" settings. Your table prefix may differ from wp_. In phpMyAdmin:

SELECT ID, post_title FROM wp_posts WHERE post_content LIKE '%<script%';
SELECT option_name FROM wp_options WHERE option_value LIKE '%<script%';

With WP-CLI you can search the whole database and check the site address:

wp db search "<script" --all-tables
wp option get siteurl
wp option get home

Some results will be legitimate embeds such as maps or booking widgets, so review each one. Back up the database before editing anything.

Rogue plugins, mu-plugins and cron jobs

Look in wp-content/plugins for folders you didn't install, especially with names that mimic real plugins; some malware hides itself from the Plugins screen, so compare the server folders with your dashboard list. Check wp-content/mu-plugins, which loads automatically and is easy to miss, and drop-ins such as advanced-cache.php that your caching setup didn't create. If the redirect returns within hours, look for a cron job in your hosting panel and list WordPress events with wp cron event list.

How to fix the WordPress redirect hack, step by step

  1. Back up the infected site (files and database) and note the redirect destinations and dates.
  2. Change every password: hosting, SFTP, database (then update wp-config.php) and all WordPress admins. Generate new security keys in wp-config.php to log everyone out.
  3. Remove admin users you don't recognise.
  4. Replace WordPress core: fresh wp-admin and wp-includes, then check root files with wp core verify-checksums.
  5. Reinstall plugins and themes from official sources, and delete unused or nulled ones.
  6. Clean .htaccess, wp-config.php and index.php.
  7. Remove PHP files from uploads and anything suspicious in mu-plugins.
  8. Clean the database: injected scripts, spam posts and changed site URLs.
  9. Remove malicious cron jobs and scheduled events.
  10. Purge every cache: plugin, server and CDN.
  11. Test again on mobile data, from Google, in fresh private windows, over the next few days.

Backdoors are what usually bring the redirect back, so read finding and removing WordPress backdoors. The complete process is in how to remove malware from WordPress step by step.

Why the redirect keeps coming back

  • A backdoor was missed: attackers usually leave several ways back in
  • The entry point is still open: an outdated plugin or theme, or a reused password
  • Another site in the same hosting account is infected; see cleaning a whole hosting account
  • A cron job reinstalls the code
  • A computer with saved FTP passwords is infected, so new passwords get stolen too

Check Google once it's clean

Redirect hacks often lead to a red browser warning or "This site may be hacked" in results. Once clean, check Search Console's Security issues report and request a review; see removing "This site may be hacked" and, if rankings dropped, recovering rankings after a hack.

How to prevent redirect hacks

Keep WordPress, plugins and themes updated and delete anything unused, never use nulled plugins or themes, turn on two-factor login for admins, disable file editing in the dashboard, block PHP in uploads and use a firewall with file-change monitoring. If you'd rather not keep on top of it yourself, WordPress maintenance and support covers updates, backups and security monitoring each month.

FAQs

Why is my WordPress site redirecting to spam?

If you didn't set up the redirect, malware has most likely been injected into .htaccess, a core or theme file, a plugin or the database. Less often it's a bad ad, a compromised third-party script, or a domain or DNS problem.

What is WordPress redirect malware?

Code an attacker adds to your site that sends some visitors to spam or scam pages, usually only mobile visitors from search engines, so the owner doesn't notice. It is often paired with backdoors that reinstall it.

Why does the hacked redirect only happen on mobile?

The malware checks the device and where the visitor came from, and targets mobile visitors from search. Owners mostly check on a computer while logged in, so the hack survives longer.

Can a security plugin remove redirect malware automatically?

It can detect and remove some known infections, but code in the database, .htaccess or a fake plugin is often missed, and plugins don't close the hole the attacker used. Use a scanner, then check the locations above by hand.

Will a WordPress hacked redirect hurt my Google rankings?

It can, through browser warnings, visitors bouncing straight back and spam pages indexed under your domain. Rankings usually recover after a thorough clean-up and a successful review, though how long that takes varies.

The redirect came back after I removed it. What now?

Something was missed: usually a backdoor, a cron job, an infected neighbouring site or an unpatched plugin. Change passwords again from a clean device and work through every location in this guide.
