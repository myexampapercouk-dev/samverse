Core Web Vitals Explained for Business Owners: LCP, INP and CLS, What Counts as Good and How to Improve Them

Core Web Vitals explained: LCP, INP and CLS thresholds, field vs lab data, the 28-day window, Search Console reports and what to fix first on WordPress.

Key takeaways
  • A page passes Core Web Vitals when LCP, INP and CLS are all good for at least 75% of real visits over 28 days.
  • Field data from real Chrome users decides the pass or fail; lab tools such as Lighthouse help find the cause.
  • On Indian mobile networks, heavy hero images, sliders and chat or ad scripts are the most common reasons pages fail.

Core Web Vitals are three measurements Google uses to judge how a page feels to real visitors: Largest Contentful Paint (LCP) for loading, good at 2.5 seconds or less; Interaction to Next Paint (INP) for responsiveness, good at 200 milliseconds or less; and Cumulative Layout Shift (CLS) for visual stability, good at 0.1 or less. They're measured on real Chrome users over the previous 28 days, and a page passes when all three are good for at least 75% of visits.

You can see your results in PageSpeed Insights and in Search Console's Core Web Vitals report. Below is what each metric means, how the measurement works, how to read the report and what usually causes problems on WordPress sites. Mobile and desktop are assessed separately. Most sites do worse on mobile, which is also where most of their visitors are.

What each metric means in practice

LCP: does the main content appear quickly?

LCP is the moment the largest image or block of text in the visible part of the screen finishes rendering. On most business sites that's the hero image, a slider, or the main heading. A slow LCP usually comes from one of four places: the server taking too long to respond, the browser discovering the image late, the image itself being too heavy, or CSS and JavaScript blocking the page from drawing. How to fix slow LCP shows how to find your LCP element and which of the four is to blame.

INP: does the page respond when someone taps?

INP replaced First Input Delay as a Core Web Vital in March 2024. Where First Input Delay only looked at the first tap, INP looks at interactions throughout the visit, such as opening a menu, choosing a product option or submitting a form, and reports one of the slowest. Poor INP almost always means the browser is busy running JavaScript: chat widgets, trackers, sliders, heavy page builder layouts or plugins doing work on every page. See how to improve INP.

CLS: does the layout stay still?

CLS adds up unexpected movements of content, such as text pushed down by an image without dimensions, a late-loading banner or a font swap. Movement that happens straight after someone taps, such as an accordion opening, doesn't count. Bad CLS is why people tap the wrong button. See how to fix CLS on WordPress.

Field data vs lab data

This is the part that confuses most people, because two tools can show completely different numbers for the same page.

The lab performance score from 0 to 100 isn't a Core Web Vital. It's useful for finding problems and checking fixes, but a page can pass Core Web Vitals with an orange score, or fail them with a green one. How the 75th percentile and 28-day window work

Google doesn't use your average visitor. It takes the value that 75% of page visits meet or beat, so a page passes LCP only if at least three-quarters of visits saw the main content within 2.5 seconds. That's deliberate: it means people on slower phones and networks count.

The data covers a rolling 28 days. When you fix something today, each new day of good visits replaces an old day of bad ones, so field data improves gradually and fully reflects a fix only after about four weeks. That's normal, and it's why the lab test is the place to confirm a fix straight away.

Field data also needs enough traffic. If a page doesn't have enough Chrome visits, PageSpeed Insights shows data for your whole domain instead, or no field data at all. Many small business sites only have domain-level data, which is still useful.

Reading the Core Web Vitals report in Search Console

  1. Open Search Console and go to Core Web Vitals, in the Experience section at the time of writing.
  2. Choose the mobile or desktop report. Start with mobile.
  3. Look at the counts of URLs rated Poor, Need improvement and Good. A URL's rating comes from its worst metric.
  4. Open an issue such as "LCP issue: longer than 2.5s (mobile)". Search Console groups similar pages together, such as all blog posts or all product pages, and shows example URLs.
  5. Test an example URL in PageSpeed Insights to find the cause. Fixing the template usually fixes the whole group.
  6. After fixing, click Validate fix. Search Console then monitors the group over the next 28 days.

If the report says there isn't enough data, your site doesn't yet have enough Chrome traffic. Use PageSpeed Insights' lab results in the meantime. For the rest of Search Console, see Search Console reports explained.

Do Core Web Vitals affect Google rankings?

They're part of Google's page experience signals, but relevance and content quality matter far more. Google has said good Core Web Vitals align with what its ranking systems reward, but a fast page with weak content won't outrank a slower page that answers the search better. Where Core Web Vitals clearly matter is with visitors: slow, jumpy, unresponsive pages lose enquiries and sales, whatever their ranking.

A sensible order of work

  1. Check the field data in PageSpeed Insights and Search Console, mobile first.
  2. Pick the worst metric on your most important page type, such as service pages or product pages.
  3. Fix server response and caching first, because they affect every metric and every page.
  4. Then fix the LCP element, scripts, and layout shifts, in order of impact.
  5. Confirm each fix with a lab test, check the pages still work, then let field data catch up over 28 days.

Test on a real mid-range Android phone on mobile data as well. Many Indian visitors browse on budget phones and variable connections, and that's exactly the audience the 75th percentile captures; see website speed on Indian mobile networks.

Core Web Vitals on Indian mobile traffic

For most Indian business sites, the majority of visitors arrive on mid-range Android phones over mobile data. That is where Core Web Vitals usually fail, even when the site feels quick on an office laptop on Wi-Fi. A few patterns come up again and again:

  • LCP suffers from large hero images and sliders, image-heavy page builders and slow shared hosting that takes too long to send the first byte.
  • INP suffers from heavy JavaScript: chat widgets, WhatsApp buttons loaded as scripts, pop-up builders, multiple tracking tags and large theme bundles that keep the phone busy.
  • CLS suffers from banners and cookie notices that push content down, ads without reserved space and web fonts that swap late.

Test the way your visitors browse. In PageSpeed Insights, read the mobile tab first. In Chrome DevTools, use network and CPU throttling to approximate a slower phone. Then compare against the field data in Search Console, which reflects your real audience.

If your Shopify store fails Core Web Vitals, the same principles apply: too many apps adding scripts, oversized images and heavy theme sections. The difference is that on Shopify you mostly fix it by removing apps and simplifying the theme rather than changing hosting.

FAQs

What are good Core Web Vitals scores?

LCP of 2.5 seconds or less, INP of 200 milliseconds or less, and CLS of 0.1 or less, each met by at least 75% of page visits. A page passes the assessment when all three are good.

Why does PageSpeed Insights say there's no field data for my page?

The page doesn't have enough visits from Chrome users in the last 28 days. PageSpeed Insights then shows data for your whole domain, or nothing. The lab test below still helps you find and fix problems.

How long does it take for Core Web Vitals to update after a fix?

Up to about four weeks, because field data covers a rolling 28 days. Lab tests show the improvement immediately; Search Console follows as new visits replace old ones.

Do I need a PageSpeed score of 100?

No. The lab score isn't a Core Web Vital, and chasing 100 can mean removing useful features. Aim to pass Core Web Vitals for real visitors, especially on mobile.

What happened to First Input Delay?

Interaction to Next Paint replaced First Input Delay as a Core Web Vital in March 2024. INP measures responsiveness across the whole visit, not just the first tap, so it's harder to pass.

Why do my Core Web Vitals pass on desktop but fail on mobile?

Phones have slower processors and often slower connections, so heavy images and JavaScript hurt them far more. Google reports mobile and desktop separately, so fix the mobile issues first.
