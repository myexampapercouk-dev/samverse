Elementor Stuck on Loading or "Preview Could Not Be Loaded"? How to Fix the Elementor Loading Problem

Elementor stuck on loading forever? Step-by-step fixes for PHP memory, plugin conflicts, mod_security, caching and CDN, the editor loader setting and PHP.

Key takeaways
  • When Elementor is stuck on loading, the cause is usually around Elementor rather than in it: low PHP memory, a plugin conflict, a server firewall rule, or caching and CDN scripts.
  • Diagnose before changing things: check the browser console and Network tab, Elementor's System Info, and whether the editor opens in Safe Mode.
  • If only one page won't load, suspect that page's data and restore a revision or backup; if every page fails, work through memory, plugins, server rules, caching and PHP version in order.

You click "Edit with Elementor" and the loading screen spins forever, the editor stays blank, or you see "Preview could not be loaded". The Elementor loading problem is common, and it's usually caused by something around Elementor rather than Elementor itself: low PHP memory, a plugin conflict, a server security rule, or caching and CDN scripts interfering with the editor.

Work through the fixes below in order. Make a backup first, and where you can, test on a staging copy rather than the live site. Elementor's menus change between versions, so if a setting isn't where I describe it, check Elementor's current docs.

Before you start: find the error behind the loading screen

Two minutes of checking saves an hour of guessing:

  1. Browser console: on the stuck editor, press F12 and open the Console tab. Red errors often name the plugin or file at fault.
  2. Network tab: reload the editor with the Network tab open and look for failed requests, especially to admin-ajax.php or the REST API, with status codes such as 403, 500 or 503.
  3. System Info: Elementor's System Info screen lists your PHP version, memory limit and active plugins in one place.
  4. Server error log: your hosting panel's error log shows PHP fatal errors that the browser never sees.

Elementor stuck on loading because of low PHP memory

The editor needs far more memory than a normal page view. When the limit is too low, it can fail silently and spin forever.

  1. Open Elementor's System Info and note the WordPress memory limit. Elementor's requirements have recommended 256 MB or more; check its current docs.
  2. Edit wp-config.php (via your host's File Manager or SFTP) and add define( 'WP_MEMORY_LIMIT', '256M' ); above the line that says to stop editing.
  3. WordPress can't go above the server's own PHP limit, so also raise memory_limit in your hosting panel's PHP settings, or ask your host.
  4. Reload the editor. If System Info still shows the old figure, the host is capping it.

For memory errors in general, see "Allowed memory size exhausted" errors in WordPress.

Elementor loading problem after an update: plugin conflicts

Elementor add-on packs and other plugins that load scripts in the editor are the most common cause, especially right after an update.

  1. Turn on Safe Mode (Elementor, Tools, General). It loads the editor without other plugins or your theme, for the editor only, not for visitors.
  2. If the editor works in Safe Mode, a plugin or the theme is at fault. Turn Safe Mode off again when you're done.
  3. On staging, deactivate all plugins except Elementor and Elementor Pro, then reactivate them one at a time, reloading the editor after each, until it breaks.
  4. Update the plugin responsible, look for a known issue in its changelog or support forum, or replace it.
  5. Keep Elementor, Elementor Pro and add-ons updated together; a Pro version far behind the free plugin can stop the editor loading.

For a safe method on a live site, see how to find and fix plugin conflicts.

Elementor loading forever because of .htaccess or mod_security

If the Network tab shows the editor's requests failing with 403, 406 or 500 errors, the server may be blocking them.

  1. Reset .htaccess: in File Manager, rename .htaccess to .htaccess-old, then go to Settings, Permalinks and click Save to create a fresh default file. Test the editor. If it works, compare the old file for redirect or security rules added by plugins.
  2. Check mod_security: server firewalls such as mod_security sometimes flag the editor's large requests as attacks, especially when saving. Ask your host to check the firewall logs at the time of the failure and whitelist that specific rule, rather than switching the firewall off for the whole site.
  3. Check security plugins: a plugin firewall can block the same requests. Look at its blocked-request log, or pause it briefly to test.

See 403 Forbidden errors on WordPress for more on firewall blocks.

Caching or CDN scripts breaking the Elementor editor

Script optimisation, such as combining, deferring or delaying JavaScript, and CDN features that rewrite scripts can stop the editor loading.

  1. Purge every cache: your caching plugin, the server cache and the CDN.
  2. Temporarily turn off JavaScript optimisation in your caching or optimisation plugin and test the editor.
  3. If that fixes it, keep optimisation on for visitors but exclude logged-in users and the editor, or exclude Elementor's scripts.
  4. On Cloudflare, features that rewrite how scripts load, such as Rocket Loader, are a common culprit; turn them off or bypass them for wp-admin and the editor. See setting up Cloudflare on WordPress.

Try the "Switch Editor Loader Method" setting

Elementor has an advanced setting that changes how the editor loads, which can help on some server setups. At the time of writing it's under Elementor, Settings, Advanced, labelled "Switch Editor Loader Method". Enable it, save, and reload the editor. If it makes no difference, switch it back so you know exactly what changed.

Browser extensions blocking the editor

  1. Open the editor in a private or incognito window, where most extensions are off by default.
  2. If it loads there, disable extensions one at a time in your normal window. Ad blockers, privacy and script blockers, and some grammar or password tools are frequent causes.
  3. Clear your browser cache, or try another browser, to rule out old cached editor files.

Outdated PHP version

System Info shows your PHP version. Check it against Elementor's current requirements, and ask whether your add-ons support it too, as both too old and, occasionally, too new for an old add-on can cause trouble. Back up, switch the version in your hosting panel, then test the editor and the site; see updating PHP.

Only one page stuck on loading: corrupted Elementor data

If other pages open fine and one page always spins, that page's saved Elementor data is the likely problem.

  1. Regenerate files and data under Elementor, Tools, then clear caches and try again.
  2. Think about what changed last. A widget from an add-on you've since deactivated can stop a page loading; reactivate the add-on, open the page and remove the widget.
  3. Restore an earlier revision from the WordPress revisions screen, which also restores Elementor's content for that revision.
  4. If nothing works, restore the page from a backup, or rebuild it from a saved template.

Site URL, SSL and theme checks

"Preview could not be loaded" often happens when the WordPress Address and Site Address in Settings, General don't match, for example http:// and https://, or www and non-www. Make sure the whole site loads on HTTPS; after a migration, Elementor's Replace URL tool (Elementor, Tools) updates old addresses in its data. See mixed content warnings after moving to HTTPS.

A theme that doesn't support Elementor properly can also break the editor. Test by temporarily switching to Hello Elementor on a staging site; see best themes for Elementor.

FAQs

Why is Elementor stuck on the loading screen?

Usually low PHP memory, a plugin conflict, a server firewall blocking the editor's requests, or caching and CDN scripts. The browser console and Safe Mode will tell you which.

Why does Elementor say "Preview could not be loaded"?

Most often the site addresses don't match (http and https, or www and non-www), a security rule blocks the preview, or a redirect interferes with it.

Elementor is loading forever on one page only. What does that mean?

That page's data is probably the problem, often a widget from a missing add-on. Restore a revision or remove the widget.

Is it safe to use Elementor's Safe Mode on a live site?

Yes. It affects only the editor for logged-in users, not what visitors see. Switch it off once you've finished testing.

Will reinstalling Elementor fix the loading problem?

Rarely on its own, because the cause is usually around Elementor. Diagnose first; reinstalling the same version over itself only helps if its files were damaged.
