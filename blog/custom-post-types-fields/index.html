Custom Post Types and Custom Fields in WordPress: Examples, ACF and Similar Tools, Registering Them in Code, Templates and SEO

Key takeaways
  • Custom post types add new kinds of content, such as properties, courses, doctors or projects, and custom fields store the details each item needs.
  • Plan the content model first: anything visitors filter by should be a taxonomy or a structured field, not a sentence in the description.
  • Register post types in a plugin rather than the theme, give each one proper templates, and decide which archives Google should index.

Custom post types and custom fields let WordPress manage content that isn't a blog post or a plain page. A custom post type adds a new kind of content, such as Properties, Courses, Doctors or Projects, with its own menu in the dashboard. Custom fields store the details every item needs, such as price, duration or qualifications, so staff fill in a form and the site displays each item the same way, while taxonomies group them by location, category or status.

Structured content like this is part of WordPress website development whenever a business has more than a handful of similar items to show. On a real estate website, for example, projects and listings are managed from the dashboard, and you can add photos, prices and status (available, sold) at any time without touching a layout.

This guide explains the building blocks for business owners, then shows developers how to register a post type in code. For large listing sites with search, maps and owner submissions, directory websites on WordPress goes further.

The three building blocks

Building blockWhat it isExample
Custom post typeA new kind of content with its own menu, URL and templatesProperties, at example.com/properties/sunrise-heights/
TaxonomyA way to group items, which gets its own archive pagesLocation (Pune, then Baner), status (ongoing, completed)
Custom fieldA specific detail stored for each itemRERA number, carpet area, possession date, brochure PDF

WordPress already uses these internally. Posts and pages are post types, categories and tags are taxonomies, and WooCommerce products are a custom post type with their own fields for price, stock and SKU.

Why structured content beats free-form pages

  • Consistent pages. Every item uses the same template, so nobody has to design a page to add a new course.
  • Easier, safer editing. Staff fill in labelled fields; they can't accidentally break the layout.
  • Filtering and search. Visitors can narrow by location, price or speciality because the data is structured.
  • Lists that update themselves. The homepage can show the latest three projects, or every course with an upcoming batch, without manual edits.
  • Better SEO. Clean URLs, archive pages for each group and structured data drawn from fields.

Plan the content model before building

Most problems come from deciding fields on the fly. Before anything is built, write down for each content type:

  1. The URL pattern, such as /courses/course-name/.
  2. The groupings visitors will browse by, such as city or course level. These usually become taxonomies.
  3. The details every item needs, with a type for each: text, number, date, image, gallery, file or a choice from a list. Mark which are required. Anything visitors will filter by must be a taxonomy or a field, never a sentence buried in the description.
  4. Where items appear: their own page, an archive, the homepage, a related-items block.
  5. Who adds them, and which role they need.

Taxonomy or field? A simple rule: use a taxonomy for values shared by many items that deserve their own listing page, such as a city, and a field for values unique to each item, such as a price or a phone number.

A common, sensible combination is post types and taxonomies registered in code, with field groups built in a custom fields plugin. Elementor Pro's dynamic tags and the block editor can both display field values in templates; recent WordPress versions can also connect some core blocks to custom fields directly.

Registering a custom post type in code

For developers: this small plugin registers a Property post type and a Location taxonomy. It goes in its own folder under wp-content/plugins, not in the theme's functions.php, so the content survives a redesign.

<?php
/**
 * Plugin Name: Example Site Content Types
 * Description: Registers the Property post type and Location taxonomy for example.com.
 */

add_action( 'init', function () {
    register_post_type( 'property', array(
        'labels'       => array(
            'name'          => 'Properties',
            'singular_name' => 'Property',
            'add_new_item'  => 'Add New Property',
        ),
        'public'       => true,
        'has_archive'  => true,
        'rewrite'      => array( 'slug' => 'properties' ),
        'menu_icon'    => 'dashicons-building',
        'supports'     => array( 'title', 'editor', 'thumbnail', 'excerpt', 'revisions' ),
        'show_in_rest' => true,
    ) );

    register_taxonomy( 'property_location', 'property', array(
        'labels'            => array(
            'name'          => 'Locations',
            'singular_name' => 'Location',
        ),
        'hierarchical'      => true,
        'public'            => true,
        'rewrite'           => array( 'slug' => 'location' ),
        'show_in_rest'      => true,
        'show_admin_column' => true,
    ) );
} );

A few notes. The show_in_rest setting makes the post type work in the block editor. Hierarchical taxonomies behave like categories, with parents and children; non-hierarchical ones behave like tags. After activating the plugin, go to Settings > Permalinks and click Save Changes once, so WordPress picks up the new URLs. Choose post type and taxonomy names carefully at the start, because renaming them later means migrating content.

Templates: how items are displayed

  • Classic themes: a single-property.php template for each item and archive-property.php for the listing, usually in a child theme or custom theme.
  • Block themes: single and archive templates for the post type, created in the Site Editor or shipped with the theme, using the Query Loop block for lists.
  • Elementor Pro: Theme Builder single and archive templates with display conditions for the post type, and dynamic tags pulling in each field.

Design the template around the questions visitors ask, with the key facts near the top, and give editors a sensible fallback when an optional field is empty. Where editors also need flexible sections inside items, custom Gutenberg blocks can give them on-brand components they can't break.

SEO for custom post types

  • Clean URLs. Use a readable rewrite slug, such as /courses/, and keep it stable.
  • Sitemaps. Public post types are usually included in your SEO plugin's sitemap automatically; check that only the ones you want are listed.
  • Indexing rules. SEO plugins let you set titles and index or noindex per post type and taxonomy. Thin taxonomy archives with one or two items are often better left out of Google; see SEO for category and tag pages.
  • Unique content. An item with only a few fields filled in can look thin. Add a genuine description, photos and answers to common questions.
  • Structured data from fields. Where a suitable schema type exists, such as Course, JobPosting or Physician, fields can feed it automatically; see schema markup explained.

Common mistakes

  • Registering post types in the theme, so a theme change hides every item.
  • Using a post type when a category of ordinary posts would do. A handful of items rarely needs one.
  • Typing filterable details into the description instead of fields.
  • Installing several plugins that each register their own post types for similar content.
  • Forgetting archive pages, so items have no listing page to link from.

FAQs

What is the difference between a custom post type and a page?

A page is a single piece of content with a free layout. A custom post type is a group of similar items, each with the same fields and template, plus an archive that lists them.

Do I need a plugin to create custom post types?

No. They can be registered with a few lines of code in a site plugin, as shown above. Plugins such as ACF, Meta Box or Pods make it possible without code, which suits sites without a developer on hand.

What happens to custom post types if I change my theme?

If they're registered in a plugin, nothing: the content stays, though the new theme needs templates for them. If they're registered in the old theme, the items disappear from the dashboard until the code is moved into a plugin.

Are custom post types good for SEO?

They help when they create useful, distinct pages with clean URLs, archives and structured data. They don't help when they create many near-empty pages, so plan which archives Google should index.

Can I add custom fields to WooCommerce products?

Yes. Products are a custom post type, so extra details such as fabric, warranty or compatible models can be added as fields and shown on the product page.
