WordPress White Screen of Death: What Causes It and How to Fix It

Fix the WordPress white screen of death step by step: turn on debugging, disable plugins and theme, raise the memory limit and check PHP version safely.

Key takeaways
  • The white screen is almost always a PHP error from a plugin, theme, memory limit or PHP version change, and the debug log usually names the culprit.
  • Work in a safe order: check recovery mode email, enable debug logging, disable plugins by renaming the folder, then switch theme and check memory.
  • Take a backup before changing files, and test updates on a staging copy so a white screen never reaches a live business site again.

The WordPress white screen of death is a blank page where your site or dashboard should be. It almost always means a PHP error stopped WordPress from loading, usually caused by a plugin, a theme, a low memory limit or a PHP version change. To fix it, check for a recovery mode email, turn on debug logging to find the error, then disable the plugin or theme responsible.

This guide walks through the fixes in a safe order, using your hosting file manager or FTP, which most Indian hosting control panels provide.

What the white screen of death looks like

You may see a completely blank white page, a page with only "There has been a critical error on this website", or a white screen only in wp-admin while the front end still loads. Sometimes only one page, such as checkout, goes blank. Each points to the same root cause: PHP hit an error and WordPress could not finish building the page.

Newer WordPress versions usually show the "critical error" message instead of a fully blank page, and email the site admin a recovery mode link. The guide to fixing the WordPress critical error covers that message in more detail.

WordPress white screen of death fix: step by step

Before you start, take a backup of files and database from your hosting panel if you can. If the site is a busy store, consider putting up a short notice on social media or WhatsApp while you work.

Step 1: Check the recovery mode email

WordPress often emails the admin address with the name of the plugin or theme that failed and a special login link. Use that link to log in, deactivate the named plugin, and the site usually comes back. Check spam folders too.

Step 2: Turn on debug logging

Open wp-config.php in your hosting file manager and find the line that sets WP_DEBUG. Change it to:

define( 'WP_DEBUG', true );
define( 'WP_DEBUG_LOG', true );
define( 'WP_DEBUG_DISPLAY', false );

Reload the blank page, then open wp-content/debug.log. The last lines usually mention a file path under /plugins/ or /themes/, which tells you exactly where the error is. Turn debugging off again when you finish, because the log can expose server paths if left public.

Step 3: Disable plugins

If you cannot reach wp-admin, rename wp-content/plugins to plugins-off. WordPress deactivates all plugins. If the site loads, rename the folder back, then rename individual plugin folders one at a time until the white screen returns. That plugin is the cause. The guide to troubleshooting plugin conflicts explains how to narrow it down when two plugins clash.

Step 4: Switch the theme

If plugins are not the cause, rename your active theme's folder inside wp-content/themes. WordPress falls back to a default theme if one is installed. If the site loads, the problem is in your theme or child theme, often a recent edit to functions.php.

Step 5: Raise the memory limit

If the log mentions "Allowed memory size exhausted", add this line above the "stop editing" comment in wp-config.php:

define( 'WP_MEMORY_LIMIT', '256M' );

Your host's PHP limit also needs to allow it. On shared hosting you may need to change it in the control panel or ask support. The guide to WordPress memory limit errors covers this in depth, but remember that a plugin using endless memory needs fixing, not just more memory.

Step 6: Check the PHP version

Hosts sometimes upgrade PHP across servers. Old plugins or themes may break on newer versions. In your hosting panel, check which PHP version the site uses. You can switch back temporarily to restore the site, but plan to update or replace the outdated code. See how to update the PHP version in WordPress safely.

Step 7: Clear caches and fix failed updates

If you fixed the cause but still see a blank page, clear your caching plugin, server cache and any CDN cache. If an update was interrupted, delete any .maintenance file in the site root and re-upload fresh WordPress core files (not wp-content or wp-config.php).

White screen only in wp-admin or only on one page

If the front end works but the dashboard is blank, the culprit is usually an admin-only plugin feature, such as a page builder, security plugin or backup plugin. The same plugin-renaming test applies.

If only one page is blank, such as a product page, checkout or a page built with a specific widget, look at what is unique on that page: a shortcode, a form, a payment gateway or a large query. On WooCommerce stores, a white checkout often comes from a payment or shipping plugin update; check the debug log and the WooCommerce status logs.

Using your hosting panel to find the error

Most Indian and international hosts give you tools that help even before you touch WordPress files. In cPanel, hPanel or similar panels, look for an "Errors" or "Error log" section, which often shows the same PHP fatal error that WordPress would log. Some hosts also offer a one-click PHP version switcher, a file manager with a built-in editor, and daily automatic backups you can restore from.

If your host offers a staging tool, you can copy the broken site to staging and test fixes there while the live site shows a maintenance message. When nothing in the panel makes sense, the host's support team can often tell you which file triggered the fatal error from their server logs. Ask them for the exact error line and timestamp, since that turns a vague "my site is blank" into a specific fix.

How to prevent the white screen

  • Use a staging site for theme, plugin and PHP updates on business-critical sites.
  • Keep daily backups stored off the server; the WordPress backup and restore guide covers how.
  • Update one thing at a time so you know what broke.
  • Avoid pasting code into functions.php on the live site; use a code snippets plugin with error protection or a child theme tested on staging.
  • Remove abandoned plugins that have not been updated in a long time.
  • Use uptime monitoring so you hear about a blank site before customers do.

For other common faults, see the list of common WordPress errors and fixes.

When to call a developer

If the debug log points to code you do not understand, the site is a live store taking orders, or you suspect the white screen followed a hack, it is safer to get help. Unknown files, new admin users or redirects to strange sites alongside a white screen can mean malware, which needs a proper clean-up rather than just disabling a plugin.

Before you contact anyone, collect the useful facts: when the white screen started, what changed just before (an update, a new plugin, a hosting change), the last few lines of the debug log, and your hosting panel access. That shortens the fix considerably, whoever handles it.

FAQs

What is the WordPress white screen of death?

It is a blank white page, or a critical error message, that appears when a PHP error stops WordPress from loading. It is usually caused by a plugin, theme, memory limit or PHP version problem.

How do I fix the WordPress white screen of death without admin access?

Use your hosting file manager or FTP. Enable debug logging in wp-config.php, rename the plugins folder to disable all plugins, then rename the active theme folder if needed.

Will I lose my content because of the white screen?

Usually not. Your posts and pages are stored in the database, which a white screen does not normally touch. Still, take a backup before changing files.

Why did the white screen appear after a plugin update?

The new version may conflict with another plugin, your theme, or your PHP version. Roll back to the previous version or disable it, then test the update on staging.

Can a hack cause the white screen of death?

Yes, injected or damaged code can cause it. If you see unknown files, new admin users or strange redirects, treat it as a security issue and get the site cleaned.

How do I fix the WordPress white screen of death after a theme update?

Rename the active theme's folder over FTP or the hosting file manager so WordPress falls back to a default theme. If the site returns, restore the previous theme version from a backup or check its changelog for a PHP version requirement before updating again.
