SEO-Friendly URLs in WordPress: Permalinks, Slugs and Changing Them Safely

How to create SEO-friendly URLs in WordPress: best permalink setting, writing short slugs, and changing URLs safely with 301 redirects to keep rankings.

Key takeaways
  • Use the Post name permalink setting and keep slugs short, lowercase and descriptive, ideally with the main phrase people search for.
  • Changing a URL that already ranks is risky: only do it for a clear reason, and always add a 301 redirect from the old address.
  • For WooCommerce and Shopify, keep product and category URLs stable, because they collect links, shares and ad history over time.

An SEO-friendly URL is short, readable and describes the page, such as /wordpress-developer-pune/ rather than /?p=482. In WordPress, you get there by choosing the "Post name" permalink setting and writing a clean slug for each page. If you change a URL that is already indexed, add a 301 redirect so visitors and Google land on the new address.

This guide covers how to create SEO-friendly URLs in WordPress, how to write good slugs, when changing them is worth it, and how to avoid losing rankings in the process.

What makes a URL SEO-friendly

Google has said that URLs are a small ranking factor, but clean URLs still help in practical ways. People are more likely to click a link they can read, they can tell what the page is about before opening it, and shared links on WhatsApp or email look trustworthy rather than like random code.

A good URL usually has these qualities:

  • Readable words separated by hyphens, not underscores or IDs.
  • Short, with filler words such as "and", "the" or "a" removed where the meaning stays clear.
  • Lowercase only, so you never end up with two versions of one page.
  • Stable, without dates or years unless the content is genuinely tied to one.
  • Descriptive, including the main phrase the page targets, such as a service and city.

How to create SEO-friendly URLs in WordPress

Go to Settings, then Permalinks in the WordPress dashboard. For most business sites, choose Post name. This produces URLs like /blog-post-title/ for posts and /page-name/ for pages. If you prefer to keep posts under a blog folder, use a custom structure such as /blog/%postname%/.

Then, for each page or post, edit the slug before publishing. In the block editor it sits in the URL or Permalink field of the sidebar; SEO plugins also show it in their snippet preview. WordPress builds the slug from the title by default, which often makes it too long, so shorten it by hand.

Tips for writing slugs:

  1. Start from the phrase people actually type, for example "cake classes pune" or "wordpress maintenance cost".
  2. Remove words that add no meaning.
  3. Avoid numbers that will change, such as "10-tips" if you may later add more tips.
  4. Use English transliteration consistently if your audience searches in Hinglish, and keep one version.
  5. Never reuse a slug that belonged to a deleted page for something unrelated.

If you set up the site fresh, decide the permalink structure before publishing any content. Changing it later affects every URL at once.

Categories, tags and WooCommerce URLs

WordPress adds /category/ to category archive URLs and WooCommerce adds /product/ and /product-category/ to store URLs. These defaults are fine. Some plugins can remove the base, but doing so on a live site creates a lot of redirects and possible conflicts, so it is rarely worth it.

For stores, the bigger question is whether a product sits in one category or many. WooCommerce keeps one URL per product regardless of category, which avoids duplicate pages. Keep product slugs simple, such as /product/kanjivaram-silk-saree-red/, and avoid adding SKUs or stock codes that mean nothing to buyers. The guide to category and tag pages for SEO covers archive pages in more detail.

On Shopify, URL prefixes like /products/ and /collections/ are fixed, but you can still edit the handle (Shopify's name for the slug) on each product and collection. The same rules apply: short, lowercase and descriptive. When you edit a handle, Shopify offers to create a redirect automatically, and you should leave that option ticked.

Planning a URL structure for a business site

Before a new site goes live, sketch the URL structure on paper alongside the menu. A clear structure makes the site easier to navigate, easier to extend and easier for Google to understand. A simple plan for a typical Indian service business might look like this:

  • Top-level service pages: /website-design/, /seo-services/, /maintenance/.
  • Location pages, only if each is genuinely different: /website-design-pune/, /website-design-mumbai/.
  • Blog posts under one folder: /blog/how-much-does-a-website-cost/.
  • Case studies under their own folder: /work/project-name/.
  • Utility pages kept short: /about/, /contact/, /privacy-policy/.

Keep the depth shallow. A URL like /services/digital/web/design/pune/ adds folders without adding meaning. Two levels are enough for almost every small business site, and flatter URLs are easier to read aloud on a phone call or print on a visiting card.

Think about the future too. If you might add a second city or a new service line next year, pick names that will still make sense then. A slug like /services/ ages better than /our-2024-services/. And if you plan a Hindi or Marathi version of the site, decide early whether it will live in a folder such as /hi/, so English URLs do not need to change later.

Finally, write the plan down. A short list of agreed URLs, shared with whoever adds content, prevents duplicate pages like /contact-us/ and /contact/ appearing side by side months later.

Changing URLs safely without losing rankings

Changing a URL that already ranks resets some of what it has built up, and a missing redirect can turn a good page into a 404. Before changing anything, ask whether the gain is real. A slightly long but working URL is usually better left alone.

Good reasons to change a URL:

  • It contains an ID or draft name such as /?p=482 or /new-page-3/.
  • It includes a year that makes updated content look old.
  • The page has changed topic and the URL is now misleading.
  • You are merging two thin pages into one stronger page.

The safe process:

  1. Note the old URL and check it in Search Console for clicks and impressions.
  2. Change the slug and publish.
  3. Add a 301 redirect from the old URL to the new one. A redirect plugin or your SEO plugin can do this; see 301 vs 302 redirects for which to use.
  4. Update internal links, menus and buttons that point to the old address.
  5. Check the sitemap shows only the new URL, then request indexing in Search Console.

Avoid redirect chains, where URL A redirects to B and B to C. Point every old URL straight to the final one. Chains slow pages down and can end in a too many redirects error.

Common URL mistakes on Indian business sites

  • City names stuffed into every URL, such as dozens of near-identical "service-in-area" pages. Only create location URLs when each page has genuinely different content.
  • Changing the permalink setting on a live site without redirects, which breaks every shared link at once.
  • Both http and https, or www and non-www versions loading separately. Pick one and redirect the rest; a canonical tag helps confirm the preferred version.
  • Uppercase letters or spaces in slugs copied from file names, which create encoded URLs like %20.
  • Old campaign pages left live with outdated offers rather than redirected to a current page.
  • Image and PDF file names such as IMG_20230514.jpg or final-final-v2.pdf. Rename files before uploading, because WordPress builds the attachment URL from the file name and it is awkward to change afterwards.
  • Translated or regional slugs in mixed scripts, where some pages use Devanagari and others use English for the same section. Choose one approach per language and stick to it, so links stay predictable.

Pages returning 404 after a change usually point to a permalink or redirect issue; the guide on fixing WordPress 404 permalink errors walks through the checks.

FAQs

How do I create SEO-friendly URLs in WordPress?

Set Settings, Permalinks to Post name, then edit each slug to a short, lowercase, hyphenated phrase that describes the page. Do this before publishing so you never need to change it later.

Should I put keywords in the URL?

Yes, naturally. Include the main phrase the page targets, such as the service and city, but do not stuff several keywords or repeat words.

Will changing my permalinks hurt SEO?

It can if you skip redirects. With a 301 redirect from every old URL to its new one and updated internal links, most pages recover, though rankings may fluctuate for a while.

Should I remove the date from WordPress blog URLs?

For evergreen content, a date-free structure is usually better. On an existing site, weigh the benefit against the redirects you would need, and plan the change carefully.

Are Shopify URLs SEO-friendly?

Mostly. The /products/ and /collections/ prefixes are fixed, but you can edit each handle, and Shopify can add redirects when you change one.
