WordPress Database Optimisation: How to Clean Up and Speed Up Your Database Safely

Clean up your WordPress database safely: back up, remove revisions, transients, spam and leftovers with WP-Optimize, WP-CLI or SQL, and fix autoload.

Key takeaways
  • Always take a full backup first, then remove revisions, auto-drafts, trash, spam and expired transients, which are safe to delete on almost every site.
  • Large autoloaded options and leftover plugin data cause more slowness than revisions, but delete them only once you know which plugin created them.
  • Limit revisions and trash days in wp-config.php, trim plugin logs and never delete WooCommerce orders, then repeat the clean-up every few months.

To clean up a WordPress database safely, take a full backup first, then remove old post revisions, auto-drafts, trashed posts, spam comments and expired transients with a plugin such as WP-Optimize or Advanced Database Cleaner, check for large autoloaded options, and limit revisions so the clutter doesn't build up again. Leave anything you're unsure about, such as leftover plugin tables, until you've confirmed what created them.

A clean-up helps most on older or busier sites, where it can make the dashboard and uncached pages noticeably quicker. It won't fix a heavy theme or weak hosting. Database and autoload clean-up is one part of my WordPress speed optimization service, alongside caching, images and plugins.

Signs your database needs attention

  • The dashboard is slow to load or save, even when the public site feels fast
  • Site Health warns about autoloaded options
  • Backups take much longer than they used to, or fail part-way
  • Your host warns about database size or slow queries
  • The site has run for years, with many plugins installed and removed along the way

If visitors see slow pages but the dashboard is fine, the database is rarely the main cause. Page caching, hosting, images and scripts usually matter more; see why WordPress sites are slow and WordPress caching explained.

Check the database size first

Tools > Site Health > Info > Directories and Sizes shows the total database size. For a per-table breakdown, open phpMyAdmin from your hosting panel, or run this read-only query in its SQL tab:

SELECT table_name, ROUND((data_length + index_length) / 1024 / 1024, 1) AS size_mb
FROM information_schema.tables
WHERE table_schema = DATABASE()
ORDER BY (data_length + index_length) DESC;

Unusually large options, postmeta, log or scheduled action tables tell you where to look first.

Step 1: Back up, and know how to restore

Database clean-up deletes data permanently. Take a full backup with UpdraftPlus or your host's backup tool, download a copy, and make sure you know how to restore it; see the backup and restore guide. Developers can export the database with one command before starting:

wp db export before-cleanup.sql

Work at a quiet time, especially on a store, because table optimisation can briefly slow things down.

Step 2: Clean up with a plugin

WP-Optimize

The Database tab lists each clean-up task with a count of items: revisions, auto-drafts, trashed posts, spam and trashed comments, expired transients, orphaned data and table optimisation. Tick the ones you want and run them. You can tell it to keep a set number of recent revisions, and it can run on a schedule.

On a first run, start with the safe items: revisions, auto-drafts, trash, spam and expired transients. Leave anything labelled orphaned or unused for a second pass, once you've looked at what it would remove.

WP-Optimize also includes page caching and image compression. If you already use a caching plugin such as LiteSpeed Cache or WP Rocket, leave those modules switched off so you don't run two caches.

Advanced Database Cleaner

Its strength is leftovers: it lists tables, options and scheduled tasks that remain after plugins are removed, and its paid version tries to identify which plugin each one belongs to at the time of writing. Delete only items you're sure about, and keep the backup handy.

If you only need a clean-up occasionally, deactivate and delete the plugin afterwards. One fewer plugin is one less thing to update.

Step 3: The WP-CLI way

With SSH access, WP-CLI does the same jobs quickly and shows exactly what it's doing:

wp post list --post_type=revision --format=count
wp post delete $(wp post list --post_type=revision --format=ids) --force
wp comment delete $(wp comment list --status=spam --format=ids) --force
wp transient delete --expired
wp db optimize

On a site with tens of thousands of revisions, delete them in batches rather than all at once.

Step 4: Find and fix large autoloaded options

Options marked to autoload are loaded on every single request, front end and dashboard alike. When a plugin stores large amounts of data that way, every page pays the price. Recent versions of WordPress warn about this in Site Health. To see the biggest offenders:

SELECT option_name, LENGTH(option_value) AS bytes
FROM wp_options
WHERE autoload IN ('yes', 'on', 'auto-on', 'auto')
ORDER BY bytes DESC
LIMIT 20;
  • The option name usually starts with the plugin's prefix, which tells you where it came from.
  • If it belongs to an active plugin, look for a logging or cache setting that's storing too much, or replace the plugin.
  • If it belongs to a plugin you've already removed, a developer can switch its autoload off or delete it after a backup.

Autoload problems often show up first as a slow dashboard; see why the WordPress admin is slow. A persistent object cache such as Redis, where your host supports it, reduces repeated database queries, but it doesn't make bloated autoload data small.

Step 5: Stop the clutter coming back

Add these two lines to wp-config.php above the line that says "That's all, stop editing", to keep the last five revisions of each post and empty the trash after seven days instead of the default 30:

define( 'WP_POST_REVISIONS', 5 );
define( 'EMPTY_TRASH_DAYS', 7 );
  • Stop spam at the source with form and comment protection, or turn comments off if you don't use them.
  • Set log retention in security, email and redirect plugins, which can quietly fill tables.
  • When removing a plugin, check its settings for an option to delete its data on uninstall.

WooCommerce stores need extra care

  • WooCommerce > Status > Tools has buttons to clear transients and expired transients. "Clear customer sessions" empties active carts, so only use it at a quiet time and when you have a reason.
  • Scheduled actions: WooCommerce > Status > Scheduled Actions can hold large numbers of completed and failed actions. Completed ones are cleaned up automatically after a while; a growing pile of past-due actions usually means WP-Cron isn't running properly; see WP-Cron explained.
  • Never delete orders, customers or order notes to save space. They're your accounting and GST records.

Store databases grow faster than brochure sites, which is one reason they need their own tuning; see WooCommerce speed optimization.

What "optimise tables" actually does

After lots of deletions, tables keep the empty space. Optimising rebuilds each table to reclaim it. On modern InnoDB tables the speed gain is usually modest, and very large tables can be briefly locked while they rebuild, so run it off-peak. It's the last step after a clean-up, not a fix on its own.

How often to clean the database

For most business sites, every few months is plenty. A busy blog or store benefits from a monthly check of revisions, transients, logs and autoload size. It belongs on the same routine as updates and backups; see the WordPress maintenance checklist.

If the site can't reach its database at all, that's a connection problem rather than bloat; see fixing "Error establishing a database connection".

FAQs

How do I clean up my WordPress database?

Take a full backup, then use WP-Optimize or Advanced Database Cleaner to remove revisions, auto-drafts, trashed posts, spam comments and expired transients, and optimise the tables. Check autoloaded options, and limit revisions in wp-config.php so the clutter doesn't return.

Is it safe to delete post revisions?

Yes. Revisions are earlier saved versions of your posts and pages, and deleting them doesn't affect what's published. Keep a few recent ones if you like the option of rolling back an edit.

Will cleaning the database speed up my site?

It helps most where the database is genuinely bloated, especially with large autoloaded options, and it shows mainly in the dashboard and uncached pages. Visitors seeing cached pages may notice little difference, because caching, hosting, images and scripts matter more for them.

What are transients, and can I delete them?

Transients are temporary cached data that plugins store, often in the options table, with an expiry time. Expired ones are safe to delete, and even active ones are rebuilt when needed, though deleting them all may make the next few page loads slightly slower.

Is WP-Optimize safe to use?

Yes, for the standard clean-up tasks, as long as you take a backup first. Be more careful with options that remove orphaned or leftover data, and don't enable its caching module alongside another caching plugin.

How often should I optimise the WordPress database?

Every few months for a typical business site, and monthly for busy blogs and stores. Scheduling it as part of regular maintenance stops the problem returning.
