Business Website Web Font Performance: How to Reduce Font Load in WordPress and Shopify

Improve business website web font performance: fewer font files, WOFF2, self-hosting, font-display swap, preloading and subsetting in WordPress and Shopify.

Web font performance on a business website comes down to how many font files the page has to download and how quickly the text can appear. To improve it, use one or two font families with only the weights you need, serve them as WOFF2 from your own domain, add font-display: swap so text shows immediately, preload the main font, and remove fonts your theme or plugins load but never use.

Short answer: fewer files, smaller files, loaded earlier, never blocking text. On many WordPress sites, cutting unused font weights and self-hosting Google Fonts is the single quickest fix.

Why web fonts affect business website performance

Every custom font is a file the browser must download before it can draw text in that font. Each weight (regular, medium, bold) and style (italic) is usually a separate file. A theme with two families in four weights each can mean eight font files before the page looks right.

Fonts affect performance in three ways:

  • Largest Contentful Paint (LCP): if your main heading is the largest element, it cannot finish painting until its font loads. See fixing LCP.
  • Layout shift (CLS): when the web font replaces a fallback font of a different size, text reflows and the page jumps. See fixing CLS.
  • Invisible text: some browsers hide text for a few seconds while fonts load, so visitors on slow mobile connections see a blank page.

On slower Indian mobile networks the effect is bigger, because each extra request and each extra connection to another server takes longer. Our guide on website speed on Indian mobile networks explains why.

How to check your web font performance

  1. Run PageSpeed Insights on your homepage and a key service page. Look for "Ensure text remains visible during webfont load", "Eliminate render-blocking resources" and the LCP element.
  2. Open Chrome Developer Tools, Network tab, filter by Font, and reload. Count the files and note their sizes and where they come from.
  3. Check for unused fonts. Many sites load icon fonts, extra families from page builders or fonts for sliders that no longer exist.
  4. Check the file formats. WOFF2 is the modern format; TTF or older formats are larger.

Practical fixes to speed up web fonts

1. Use fewer families and weights

Most business websites need one family, or two at most (one for headings, one for body). Regular and bold are often enough; a semi-bold for headings is fine if you drop something else. Each weight you remove is one less file. Our guide on choosing website colours and fonts helps you pick a sensible pair.

2. Use WOFF2

WOFF2 is compressed and supported by all modern browsers. If your theme loads TTF, OTF or WOFF files, switch to WOFF2 versions.

3. Self-host Google Fonts

Loading fonts from Google's servers means extra connections to other domains before the font can start downloading. Hosting the same WOFF2 files on your own domain (or your CDN) removes those steps and also avoids sending visitor data to a third party. Many WordPress performance plugins and some themes have a "host Google Fonts locally" option.

4. Add font-display: swap

This CSS setting tells the browser to show text in a fallback font immediately and swap in the web font when it arrives. Visitors can start reading straight away. If you self-host, add it to each font-face rule; if you use Google Fonts, the display=swap parameter does the same.

5. Preload the most important font

Preloading tells the browser to fetch a font early, before it discovers it in the CSS. Preload only the one or two files used above the fold, such as your heading font, or you will slow down other resources.

<link rel="preload" href="/fonts/heading.woff2" as="font" type="font/woff2" crossorigin>

6. Subset fonts

Many fonts include thousands of characters for languages you do not use. Subsetting creates a smaller file with only the characters you need, such as Latin. If your site uses Hindi or Marathi, include Devanagari only where it is needed; see Hindi and Devanagari fonts on websites.

7. Consider variable fonts

A variable font holds many weights in one file. If you need three or more weights of one family, a single variable WOFF2 file can be smaller than separate files. If you only need two weights, separate files are often lighter.

8. Reduce layout shift with a matched fallback

Choose a fallback system font with similar width and height, and use size-adjust or similar font-face settings so the swap barely moves the text.

9. Replace icon fonts

Loading a whole icon font for a handful of icons is wasteful. Inline SVG icons are lighter and sharper.

How to preload fonts correctly

Preloading tells the browser to fetch a font file early, before it discovers the font inside your CSS. Used well, it makes the main heading or body text appear sooner. Used badly, it competes with the hero image and other important files and can make the page slower.

A preload line goes in the head of the page and looks like this:

<link rel="preload" href="/fonts/heading.woff2" as="font" type="font/woff2" crossorigin>

Rules that keep preloading helpful:

  • Preload one or two files only: the font used for text above the fold, usually the main body or heading weight.
  • Always include crossorigin: without it the browser downloads the font twice, even on your own domain.
  • Match the exact file: the preloaded URL must be the same file your CSS uses, or it is wasted.
  • Do not preload Google Fonts from their servers: those file URLs can change. Self-host first, then preload the local file.
  • Check the result: run PageSpeed Insights before and after. If LCP does not improve, remove the preload.

Many WordPress performance plugins and some themes have a setting to preload fonts, so check there before adding code by hand.

Web font performance in WordPress

  • Theme settings: many themes let you choose fonts and weights in the Customizer. Remove anything you are not using.
  • Page builders: Elementor and similar builders can load fonts per widget. Set global fonts, and use any option to load fonts locally or disable Google Fonts. See why Elementor sites are slow.
  • Plugins: sliders, forms and popups sometimes load their own fonts. Check the Network tab after disabling suspects on a staging site.
  • Performance plugins: many can combine, preload or self-host fonts, but test after each change.
  • Block themes: theme.json lets you register local fonts properly, which is cleaner than pasting links into the header.

Fonts are often one of several render-blocking resources; our guide to eliminating render-blocking resources covers the rest.

Web font performance in Shopify

Shopify themes usually use the Shopify font library, served from Shopify's own CDN, and many themes already apply font-display: swap. The main improvements are:

  • Choose a body font from the system font options in the theme settings if you want the fastest result.
  • Avoid apps or custom code that inject extra Google Fonts.
  • Limit headings and body to the weights the theme actually uses.

Are system fonts a good option for a business website?

System fonts are already on the visitor's device, so they need no download at all. A modern system font stack looks clean and professional, and many well-known sites use one. If your brand does not depend on a particular typeface, using system fonts for body text and one web font for headings is a strong balance between speed and personality.

Common web font mistakes on business websites

  • Loading every weight "just in case": theme demos often import a full family from thin to black. Your site probably uses two or three of them.
  • Loading the same font twice: once from the theme and once from a page builder or plugin, sometimes from two different servers.
  • Using a decorative font for body text: script or display fonts are hard to read in paragraphs and are often large files. Keep them for a logo or a single heading, or use an image or SVG for the logo instead.
  • Preloading fonts that are not used above the fold: this pushes useful resources back in the queue.
  • Forgetting the crossorigin attribute on preload: without it the browser may download the font twice.
  • Changing fonts during a redesign without re-testing: a new heading font can quietly become the slowest part of the page.

After any font change, re-run PageSpeed Insights on mobile and look at the page on a real phone over mobile data. The difference between a font that appears instantly and one that flashes in late is easy to see.

Web font performance checklist

  1. List every font file the page loads and remove unused ones.
  2. Limit to one or two families and only the weights you use.
  3. Serve WOFF2 from your own domain or CDN.
  4. Add font-display: swap.
  5. Preload the main above-the-fold font only.
  6. Subset to the languages you need.
  7. Match fallback fonts to reduce layout shift.
  8. Re-test with PageSpeed Insights and real devices.

A simple font budget for a business website

The easiest way to keep web font performance under control is to agree a font budget before design starts, and check it whenever the site changes. A budget turns "use fewer fonts" into a rule everyone on the project can follow, including the designer, the developer and whoever adds plugins later.

A practical budget for most service businesses, clinics, shops and agencies looks like this:

  • Families: one for body text and at most one for headings. A system font stack for body text counts as zero downloads.
  • Weights: two or three in total across the whole site, for example regular and bold for body plus one heading weight.
  • Format and source: WOFF2 only, served from your own domain or CDN, with font-display: swap on every font-face rule.
  • Preloads: one, or two at most, and only for text that appears above the fold on mobile.
  • Icons: inline SVG instead of an icon font.

Write the budget into your design notes or website brief so a future redesign does not quietly add a third family. When a new plugin, page builder widget or theme update arrives, open the Network tab filtered by Font and compare the list with the budget. Anything extra is either removed or deliberately replaces something else.

Fonts are only one part of page speed. Once they are in budget, look at the other Core Web Vitals problems, such as large hero images, heavy scripts and slow server response.

How to test web font changes properly

Font fixes are easy to undo by accident, so test in a repeatable way. Run PageSpeed Insights on mobile for the homepage and one key service or product page before you change anything and note LCP, CLS and font requests. Make one change at a time, clear any page cache and CDN cache, then test again. Finally, open the page on a mid-range Android phone over mobile data and watch the first few seconds: text should appear at once and should not jump when the web font arrives.

FAQs

How do I reduce font load on my website?

Web fonts can slow a site because each file is an extra download that can delay text. Reduce font load by using one or two families, removing unused weights, serving WOFF2 from your own domain, adding font-display: swap and preloading only the main font.

Is it faster to self-host Google Fonts?

Usually yes, because the browser avoids extra connections to other servers, and you get control over caching and preloading. It also avoids sending visitor data to a third party.

What does font-display: swap do?

It tells the browser to show text immediately in a fallback font, then swap to the web font when it loads, so visitors are never left looking at invisible text.

How many fonts should a business website use?

One or two families, with two or three weights in total, is enough for most business websites and keeps performance under control.

Should I preload all my fonts?

No. Preload only the one or two fonts used above the fold. Preloading too many files competes with images and CSS and can make the page slower.

Are system fonts better for performance than web fonts?

Yes. System fonts need no download, so they are the fastest option. Many business sites use system fonts for body text and a single web font for headings.
