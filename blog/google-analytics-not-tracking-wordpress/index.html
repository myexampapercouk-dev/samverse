Google Analytics 4 Not Showing Data on Your WordPress Site? How to Find and Fix It

GA4 showing no data on your WordPress site? Check for a missing or doubled tag, the wrong measurement ID, cookie banners, caching plugins and filters.

Key takeaways
  • Test GA4 with Realtime, DebugView and a clean browser, because standard reports take time to process and ad blockers can hide your own visits.
  • WordPress tracking failures usually come down to a missing tag, a doubled tag, the wrong measurement ID, a consent banner or a speed plugin delaying or breaking the script.
  • Use Tag Assistant to see every Google tag on the page and its ID, then confirm events arrive in DebugView and a real visit shows up in Realtime.

You open Google Analytics 4 and it shows zero visitors, a fraction of what you expected, or numbers that stopped on a particular day. On WordPress the cause is usually one of a handful of things: the tag isn't on the page, it's there twice, it carries the wrong ID, a cookie banner or speed plugin is stopping it, or a GA4 setting is hiding the data. Work through the checks below in order. If you're setting GA4 up from scratch, follow how to set up GA4 and Search Console first.

Before you start: test with Realtime, not standard reports

Standard GA4 reports aren't instant. Data is processed first, so a newly tracked site can look empty in normal reports for a while even when everything works. For testing, use the Realtime report and DebugView, which show activity almost as it happens.

Test in a clean browser too: ad blockers and privacy extensions block Google Analytics, so you may not see your own visit even when the tag is fine. Then match what you see to the likely cause:

What you seeMost likely cause
Zero users from the startTag not installed, or installed with the wrong ID
Data stopped on a specific dateA theme change, plugin update, new cookie banner or new speed setting around that date
Page views roughly double what you'd expectThe tag is installed twice
Far fewer users than expectedConsent banner, delayed JavaScript or visitors' ad blockers
Realtime shows visits but reports stay emptyProcessing time, a filter, or the wrong property or date range

1. Check the tag is on the page at all

Open your site in a private window, right-click and choose View Page Source, then search (Ctrl+F) for your measurement ID, which starts with G-. If GA4 is loaded through Google Tag Manager, search for your GTM- container ID instead. If neither appears, the tag isn't there. Common reasons:

  • The plugin that added it, such as Site Kit, an analytics plugin or your SEO plugin, was deactivated, disconnected or reset
  • The code was pasted into the old theme's header file and disappeared when the theme was changed or updated
  • It was added to some pages only, for example through a page builder widget on the homepage
  • It was set up on the staging site and never added to the live one

Check a few page types, not just the homepage.

2. Check the measurement ID

  • An old UA- ID: Universal Analytics IDs start with UA-, and Universal Analytics stopped processing data in 2023. You need a GA4 ID starting with G-.
  • A Tag Manager ID in the wrong field: a container ID starting with GTM- belongs in a Tag Manager setting, not a field asking for a measurement ID.
  • An ID from someone else's property: an earlier developer or agency may have created GA4 under their own account. Compare the ID in your page source with the one in GA4 under Admin → Data streams. If they don't match, your data is going to a property you can't see.

3. Check it isn't installed twice

WordPress makes it easy to add GA4 in several places at once: Site Kit, an SEO plugin's analytics option, a theme setting, a header-code plugin and Tag Manager. Two copies can count every page view twice. Tag Assistant (covered below) lists every Google tag on the page, which is the easiest way to spot duplicates. Keep one method and remove the rest. If you use Tag Manager, let it handle GA4 entirely; see Google Tag Manager basics.

4. Cookie consent banners

Many consent banners hold analytics back until a visitor accepts cookies. Visitors who reject or ignore the banner then don't appear, or appear only partly if you use Google's Consent Mode, which can send limited signals without analytics cookies. That's the banner doing its job, not a fault.

The real problem is a banner that blocks analytics even after someone accepts. To test, open a private window, accept all cookies, browse two pages and look for yourself in Realtime. If you never appear, check which category the banner puts Google Analytics in and whether its script blocking is set up correctly. Don't switch consent off to recover numbers; privacy policy and cookie consent basics covers the essentials, and check the current rules with your lawyer for anything specific.

5. Caching and speed plugins

Speed plugins are an easily missed cause:

  • Delayed JavaScript: features that delay scripts until someone scrolls, taps or moves the mouse mean visitors who leave without interacting may never be counted
  • Combining and minifying JavaScript: merging scripts can break the small inline Google tag code or load it in the wrong order
  • Stale cached pages: if you added or changed the tag without purging the cache, visitors still receive the old HTML

Exclude the Google tag from delay and combine settings, then purge the plugin cache, server cache and any CDN. If you delay analytics on purpose for speed, accept that some short visits won't be recorded. WordPress caching explained covers the different cache layers.

6. Filters, properties and report settings

  • Data filters: under Admin → Data filters, an internal traffic filter set to Active with an IP rule that's too broad can exclude real visitors. Use the Testing state before activating a filter, because data an active filter removes can't be brought back later.
  • The wrong property: if you manage several sites, check the property name at the top of GA4.
  • Report settings: a narrow date range, a comparison or a report filter can make a report look empty.

7. Confirm the fix with Tag Assistant, DebugView and Realtime

  1. Tag Assistant: go to tagassistant.google.com, enter your site's address and connect. Your site opens in a debug session, and Tag Assistant shows each Google tag it finds, its ID and the events it sends.
  2. DebugView: with that session running, open DebugView in GA4 Admin (under Data display). Events such as page_view arrive one by one from your device.
  3. Realtime: close the debug session, visit the site normally on your phone using mobile data, and check Reports → Realtime for an active user.

If you're comfortable with developer tools, the Network tab gives one more check: filter for "collect" and you should see requests to google-analytics.com as you browse. Once page views come through, track form submissions and call clicks too.
