WordPress Activity Logs and Change Logs: Track Who Changed What on Your Site

WordPress activity logs explained: track who changed what, activity vs error vs server logs, what to log, plugin options, and retention and privacy basics.

Key takeaways
  • WordPress doesn't keep a change log of logins, users, plugins or settings by default; an activity log plugin records who did what and when, which helps with security, teamwork and troubleshooting.
  • An activity log is different from an error log (PHP errors) and a server log (every request to the server); each answers a different question, and you often need more than one.
  • Log what matters, give everyone their own login, review alerts and a short monthly summary, and set a retention period, because logs contain personal data.

"Who changed the price on this product?" "When did this page disappear?" "Did anyone log in last night?" On most WordPress sites, nobody can answer these questions, because WordPress doesn't keep a detailed change log of admin activity by default. An activity log (also called an audit log or change log) fills that gap. It's a small addition that helps with security, teamwork and troubleshooting.

In short: a WordPress activity log is a plugin that records events inside WordPress, such as logins, content edits, plugin updates and settings changes, with the user, time and IP address. It isn't the same as an error log or a server log, which record different things in different places; the table below shows which one answers which question.

Activity log vs error log vs server log

"WordPress logs" can mean several different things. Knowing which one you need saves a lot of searching:

LogWhat it recordsWhere it livesUse it to answer
Activity (audit) logActions by users inside WordPress: logins, edits, plugin, theme and settings changesA plugin, usually stored in the WordPress databaseWho changed what, and when?
RevisionsEarlier versions of a single post or page's contentBuilt into WordPressWhat did this page say before?
Error log (PHP or debug log)PHP warnings and fatal errors from WordPress, themes and pluginsThe host's PHP error log, or wp-content/debug.log when debugging is switched onWhy is the site showing a critical error or a blank page?
Server access logEvery request to the server: IP address, page, status code, browser or botThe web server, viewed through your hosting panelIs a bot hammering the site? Where are 404s and attacks coming from?
Server error logErrors from the web server itselfYour hosting panelWhy am I seeing 500 or 403 errors?

To turn on WordPress's own debug log temporarily, add define( 'WP_DEBUG', true );, define( 'WP_DEBUG_LOG', true ); and define( 'WP_DEBUG_DISPLAY', false ); to wp-config.php. Switch it off when you're done, because a debug.log file in a public folder can expose details about your site. For using error logs to fix specific problems, see "There has been a critical error on this website" and 500 Internal Server Error in WordPress.

What an activity log records

AreaExamples of logged events
LoginsSuccessful logins, failed attempts, logouts, password resets
UsersNew accounts, role changes, deleted users, profile edits
ContentPages and posts published, edited, trashed or restored
Plugins and themesInstalled, activated, deactivated, updated or deleted, and files edited from the dashboard
SettingsChanges to the site address, permalinks and other core settings
WooCommerceProduct, price and stock changes, order status updates and coupon edits, depending on the plugin

Revisions already show changes to a single page's content, but they don't cover logins, users, plugins or settings. That's what an activity log adds.

What to log (and what to skip)

  • Always: logins and failed logins, new users and role changes, plugin and theme installs, updates and deletions, file edits from the dashboard, and changes to core settings
  • For most business sites: page and post changes, menu and widget changes, and form plugin settings, so a broken enquiry form can be traced
  • For stores: price, stock and coupon changes, and order status changes made by staff
  • Usually skip: detailed tracking of every visitor or customer action. It fills the database and collects personal data you probably don't need

Why it helps with security

  • Spot suspicious activity early: a new administrator nobody created, a login at 3 a.m. from an unfamiliar location, or a plugin nobody asked for; see signs your WordPress site has been hacked
  • See password-guessing attacks: bursts of failed logins show bots at work, a sign to tighten login security
  • Build a timeline after a hack: knowing when a user was created or a plugin changed helps find the way in, and helps choose a clean backup from before it

Logins are the front door, so pair a log with the steps in how to secure your WordPress login. If the log shows signs of a break-in, the step-by-step malware clean-up guide explains what a proper clean-up involves.

Why it helps with teamwork

Many business sites are edited by several people: the owner, a marketing executive, an agency and a developer. When something changes unexpectedly, a log replaces guesswork and blame with facts: who changed a price or phone number, which update happened just before a layout broke, and what an agency actually worked on.

Logs only work when everyone has their own login. With a shared account, every entry just says "admin"; see WordPress user roles explained for giving each person the right access, and how to audit your WordPress user accounts to clear out old logins.

Activity log plugins

Well-known options include the following. Features and free versus paid limits change, so check each plugin's current listing before choosing:

  • WP Activity Log: detailed coverage of WordPress events, with support for WooCommerce and some other popular plugins; paid plans add features such as notifications, reports and external log storage
  • Simple History: a clear, readable history in the dashboard, with optional paid add-ons
  • Stream: a free activity log with alerts for selected events
  • Security plugins: some include login records or a basic change log, which may be enough for a small site

Whichever you choose, look for coverage of the areas you care about, email alerts for critical events, retention settings, search and filters, and export or off-site storage, because an attacker with admin access may be able to delete logs kept on the site. Stick to one logging plugin; two doing the same job doubles the load on your database.

What to review, and how often

  • Straight away, via alerts: new administrator accounts, anyone promoted to administrator, plugins installed, and files edited from the dashboard
  • Weekly: spikes in failed logins, and logins by unexpected users or from unexpected places
  • Monthly: plugin, theme and settings changes, plus accounts that haven't been used and can be removed

If you have a maintenance provider, ask whether reviewing the log is part of their monthly checks and report.

Retention and privacy

Activity logs contain personal data: usernames, email addresses, IP addresses and, on stores, sometimes customer and order details. Treat them with care:

  • Set a retention period long enough to investigate problems you might discover weeks later, and let the plugin delete older entries automatically. Unlimited retention also bloats the database; see WordPress database optimisation
  • Export what matters: before old entries are deleted, keep a copy of anything tied to a security incident
  • Limit access to the administrators who actually need it
  • Don't log more than you need, and mention it in your privacy policy if you log customers or other users, not only staff

India's DPDP Act sets general expectations around the purpose, security and retention of personal data, and its rules are being phased in. Separately, CERT-In directions issued in 2022 include log-keeping requirements for many organisations. Whether and how these apply depends on your business, so see the DPDP Act and your website and confirm the specifics with your lawyer or adviser.

What activity logs can't do

A WordPress activity log records what happens inside WordPress. It won't catch files changed over FTP or a compromised hosting account; your host's logs cover some of that. It also doesn't block attacks on its own. Treat it as one layer alongside prompt updates, strong logins, a firewall and tested backups.

FAQs

Does WordPress have a change log built in?

Only partly. Revisions record changes to post and page content, but WordPress doesn't log logins, user changes, plugin updates or settings by default. You need an activity log plugin for that.

Where are WordPress logs stored?

Activity logs are usually stored in the WordPress database by the plugin. The debug log is written to wp-content/debug.log when enabled, and server access and error logs are in your hosting panel.

Can I see who deleted a page in WordPress?

Only if an activity log was running at the time. Without one, check the trash, the page's revisions and, if needed, ask your host whether their logs show the request.

Do activity logs slow down WordPress?

Recording admin events adds very little load. Problems come from logging every visitor action or keeping entries forever, so limit what you log and set a retention period.
