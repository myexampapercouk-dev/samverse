Payment Gateway Not Working in WooCommerce? Fixing Failed Payments and Pending Orders in India

Razorpay, PayU, Cashfree, PhonePe or Paytm payments failing, or paid orders stuck in Pending payment? Check webhooks, keys, INR settings and firewall blocks.

Key takeaways
  • Paid orders stuck at Pending payment usually mean the return redirect failed and no working webhook was set up, so configure the webhook URL, events and secret your gateway's docs give.
  • Keep test and live keys and webhooks separate, set the store currency to Indian rupee, and check that firewalls, bot protection or staging passwords are not blocking the gateway.
  • Confirm a payment in the gateway dashboard before marking an order as Processing, and reconcile gateway exports against WooCommerce orders regularly.

When online payments go wrong on an Indian WooCommerce store, it's usually one of two problems. Either customers can't pay at all, or they pay and the order stays at "Pending payment". Both can happen with Razorpay, PayU, Cashfree, PhonePe, Paytm or any other gateway, and the causes are mostly the same. Plugins and dashboards change often, so treat this as a checklist and follow your gateway's current documentation for exact settings.

First, work out which problem you have

SymptomWhere to look first
The gateway doesn't appear at checkoutWhether it's enabled in WooCommerce → Settings → Payments, the store currency, block checkout support
An error before the payment page opensAPI keys, test or live mode, account activation, your server reaching the gateway
Payment fails on the gateway's pageThe failure reason in the gateway dashboard; whether that method is enabled on your account
Customer paid, order stuck at Pending paymentWebhooks and the return (callback) URL
Customer paid, order cancelledA late confirmation plus WooCommerce's hold stock setting

"Pending payment" means no payment has been confirmed yet; "Failed" means it was declined or didn't complete; "Processing" means it was received. If customers can't reach the payment step at all, the checkout itself may be at fault; see how to fix a WooCommerce checkout that isn't working.

Webhooks, and why they matter

A gateway can tell your store about a payment in two ways:

  • The return redirect: after paying, the customer's browser returns to your site, which checks the payment and updates the order.
  • The webhook: the gateway's server sends a message straight to your site, whatever happens in the customer's browser.

The redirect often fails: customers close the tab, switch to their UPI app and never return, or lose signal. Without a webhook, those paid orders stay pending. Set one up properly by:

  • Using the exact webhook URL your plugin's settings or documentation gives
  • Selecting the events the plugin's documentation lists
  • Entering the same webhook secret in the gateway dashboard and the plugin, where a secret is used
  • Creating live-mode webhooks separately from test-mode ones, if your gateway keeps them apart

Some plugins create webhooks automatically, but confirm one exists in the dashboard. Many dashboards also log recent deliveries and your site's response, the quickest way to spot a problem.

API keys in test mode and live mode

Gateways issue separate credentials for test (sandbox) and live use. Mixing them up causes errors, and "successful" payments that exist only in test mode. Some keys show their mode at a glance (Razorpay's key IDs include "test" or "live"); otherwise check the dashboard.

  • Switch the plugin to live mode and paste live keys only once your account is activated
  • Copy keys without stray spaces, and update the plugin if you regenerate them
  • When you copy the live site to staging, switch the staging copy to test keys
  • If you've changed domain or switched between www and non-www, check the website registered with your gateway, as some gateways check where payments come from

Currency, payment methods and settings

In WooCommerce → Settings → General, check the currency is set to Indian rupee. Some gateway plugins hide themselves at checkout if the store currency isn't one they support, and multi-currency plugins that show overseas visitors another currency can make the gateway disappear or send an unexpected amount. International card payments usually need a separate activation; see how to choose a payment gateway in India.

Also confirm each method you advertise (UPI, cards, net banking, wallets, EMI) is enabled on your gateway account, and that the plugin is up to date and supports your checkout type.

Callback URLs and firewall blocks

For webhooks and return redirects to work, the gateway must be able to reach your site. Common blockers:

  • Security plugin rules, your host's server firewall or a CDN's bot protection treating gateway requests as suspicious
  • Country blocking that also catches the servers your gateway sends from
  • A password-protected staging site, or a maintenance or "coming soon" mode
  • An old http:// or pre-migration address as the webhook URL; redirects may not be followed
  • The return page being served from a page cache

The status codes in the gateway's webhook log help: 403 usually means blocked, 404 a wrong URL and 500 a PHP error. Match the time against your firewall log, WooCommerce → Status → Logs and the plugin's debug log. Your server also needs outgoing access to the gateway's API, which an outdated server SSL setup or a host blocking outbound connections can break; your host can check. WordPress firewalls explained shows where these rules live.

Paid, but not marked as paid

  1. Find the payment in the gateway dashboard by order number, email or phone, and confirm it succeeded. Some gateways treat authorised and captured payments differently, so check your capture settings in their docs.
  2. Check the order notes in WooCommerce for a payment or transaction ID.
  3. If the payment succeeded, change the order to Processing and add a private note with the gateway's payment ID. This normally sends the customer's order email and reduces stock if it wasn't reduced already.
  4. Don't ask the customer to pay again until you've checked. If they did pay twice, refund the duplicate.

Watch the hold stock setting too, under WooCommerce → Settings → Products → Inventory. With stock management on, WooCommerce cancels unpaid pending orders after that many minutes, so a late confirmation can arrive for an order that's already cancelled. Working webhooks make this rare; a very short hold time makes it likelier.

Reconcile with the gateway dashboard

Daily for busy stores, weekly otherwise, export the gateway's payments for a date range and compare them with your orders. Look for:

  • Successful payments whose orders are still pending, failed or cancelled
  • Processing orders with no matching payment, other than Cash on Delivery
  • Refunds made in the gateway dashboard that don't show on the order, since they may not sync back
  • Settlement reports that don't match the payouts in your bank account

Keeping the payment ID on every order makes this quick.

Test changes safely

Try updates and setting changes on a staging site with test keys, remembering that staging passwords can block webhooks. Test successful, failed and cancelled payments, and close the tab straight after paying to check the webhook alone updates the order. Finish with a real low-value UPI payment on a phone on the live site. If it still fails, give the gateway's support the order number, payment ID, time and exact error.
