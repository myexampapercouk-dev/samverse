SSL Certificate Errors Explained: "Not Secure", "Connection Not Private" and How to Fix Them

SSL certificate errors explained: what Not Secure, connection not private and NET::ERR_CERT warnings mean, and how to fix each one on a WordPress site.

Key takeaways
  • Most SSL errors come down to five causes: no certificate, an expired one, one that does not cover the domain, an untrusted one, or pages loading files over plain http.
  • Read the exact error code first, check the certificate details and test from another device, so you know whether the problem is the site or the visitor's device.
  • Prevent repeats with auto-renewing certificates, expiry monitoring, one preferred domain version with redirects, and an SSL check after every migration or redesign.

An SSL certificate error means the browser couldn't confirm a secure connection to the website. Usually the certificate is missing, expired, issued for a different domain name, not trusted, or the page loads some files over insecure http. On a WordPress site, most SSL issues are fixed in your hosting panel by issuing a free certificate that covers both the www and non-www addresses, then forcing HTTPS and updating old http links.

Below, each common error message is matched to its cause and fix, with the WordPress, Hostinger and Cloudflare settings involved. If you'd rather someone kept your site updated, monitored and backed up every month so these problems get caught early, see WordPress maintenance.

SSL error messages and what they mean

Start with the exact wording. In Chrome, click "Advanced" on the warning page to see the error code; Firefox and Safari use different wording for the same problems.

What you seeUsual causeWhere to fix it
"Not secure" next to the addressThe site loads over http, or has no certificateHosting panel, then WordPress settings
"Your connection is not private" with NET::ERR_CERT_DATE_INVALIDThe certificate has expired (or the visitor's clock is wrong)Hosting panel: renew or reissue
NET::ERR_CERT_COMMON_NAME_INVALIDThe certificate doesn't cover this exact name, such as www or a subdomainReissue covering every version of the domain
NET::ERR_CERT_AUTHORITY_INVALIDSelf-signed or untrusted certificate, or a missing intermediate certificateInstall a proper certificate with its full chain
ERR_SSL_PROTOCOL_ERROR or ERR_SSL_VERSION_OR_CIPHER_MISMATCHNo certificate on this hostname, or a server or CDN configuration problemHost or Cloudflare settings
No padlock, or "parts of this page are not secure"Mixed content: images, scripts or fonts loading over httpContent, theme and page builder settings
ERR_TOO_MANY_REDIRECTS after switching to HTTPSA redirect loop, often Cloudflare's Flexible SSL modeCloudflare SSL mode or redirect rules

Full-page warnings such as "Deceptive site ahead" are not SSL problems. They mean Google has flagged malware or phishing; see how to tell if your WordPress site has been hacked.

Is it the website or the visitor's device?

Before changing anything, spend two minutes working out where the problem is:

  1. Open the site on another device, ideally a phone on mobile data. If it works there, the problem is probably the first device or network.
  2. Check the certificate details. Click the icon next to the address, then the connection or certificate option, and look at the "valid from" and "valid to" dates and the names it covers.
  3. Run a free SSL checker, such as Qualys SSL Labs' SSL Server Test. It shows the expiry date, every name on the certificate and whether the chain is complete.

If only one person sees a security certificate problem, often on every website they visit, the cause is usually on their side: a wrong date and time on the device, antivirus software that scans HTTPS traffic, a hotel or office Wi-Fi login page, or a very old device that doesn't trust newer certificates.

How to fix each SSL certificate error

"Not secure": no certificate, or the site is still on http

  1. Install a certificate. Most hosts include a free Let's Encrypt certificate. In Hostinger's hPanel, look in the website's Security section for SSL; in cPanel, use SSL/TLS Status and run AutoSSL. Make sure it covers both example.com and www.example.com.
  2. Update WordPress. In Settings > General, change both WordPress Address and Site Address to https.
  3. Force HTTPS. Use your host's "Force HTTPS" option if it has one. Otherwise, on Apache or LiteSpeed servers, add this to .htaccess above the # BEGIN WordPress block:
RewriteEngine On
RewriteCond %{HTTPS} off
RewriteRule ^(.*)$ https://%{HTTP_HOST}/$1 [L,R=301]

If the site sits behind Cloudflare or another proxy, use the host's or Cloudflare's redirect setting instead, because this rule can cause a loop there. The free Really Simple SSL plugin can handle the redirect and many mixed content issues for you, which is handy, but fixing the stored http links properly is cleaner in the long run.

Expired certificate (NET::ERR_CERT_DATE_INVALID)

Free certificates only last a few months and renew automatically, so an expired one means renewal failed. Common reasons:

  • The domain's A record no longer points to the server that issued the certificate, for example after a host change or a DNS edit
  • A CAA record in DNS doesn't allow the certificate authority your host uses
  • A paid certificate reached the end of its term and nobody renewed it

Check your DNS points to the right server, then reissue the certificate from the hosting panel. Renewal usually works again once DNS is correct. If the browser still shows the old expiry date, clear its cache or test in a private window.

Wrong domain (NET::ERR_CERT_COMMON_NAME_INVALID)

The certificate is valid, just not for the name in the address bar. Typical cases are a certificate for example.com but not www.example.com, a new subdomain without its own certificate, or a domain recently added to the hosting account. Reissue the certificate to cover every name you use, or a wildcard certificate for many subdomains, then pick one preferred version (www or non-www) and 301-redirect the other to it.

Untrusted certificate (NET::ERR_CERT_AUTHORITY_INVALID)

  • Self-signed or default certificate: the server is showing its own placeholder certificate, often because the domain isn't properly added to the hosting account yet
  • Missing intermediate certificate: when a paid certificate is installed by hand, the CA bundle (intermediate certificates) must be pasted in too, or some browsers and phones won't trust it

Mixed content: the padlock is missing

The page itself is on HTTPS, but something on it loads over http: usually old image links in posts, a logo or background set in the theme or page builder, or a hard-coded script. Open the browser's developer tools and check the Console for "Mixed Content" warnings, which name each file.

To update old links across the database, take a backup and use a search-and-replace tool that handles serialised data, such as the Better Search Replace plugin, Elementor's Tools > Replace URL, or WP-CLI:

wp search-replace 'http://example.com' 'https://example.com' --all-tables --dry-run

Remove --dry-run once the preview looks right. Never do this with a plain SQL find-and-replace, which can break serialised settings. The full process is in fixing mixed content warnings.

Redirect loop after switching to HTTPS

If the site shows "too many redirects" right after you enabled HTTPS and it uses Cloudflare, check the SSL/TLS mode. Flexible mode talks to your server over http while WordPress redirects to https, so they bounce visitors back and forth. With a valid certificate on the server, Full (strict) fixes it. See ERR_TOO_MANY_REDIRECTS and the Cloudflare setup guide.

Warnings after moving hosts

Most hosts can only issue a free certificate once the domain points to them, so for a short window after the DNS switch visitors can reach the new server before its certificate exists. Plan for it: lower the DNS TTL beforehand, switch, and issue the certificate straight away, or use Cloudflare or DNS validation to have it ready. This step belongs in every migration plan; see migrating WordPress to Hostinger or my WordPress migration service.

Do SSL errors hurt SEO?

HTTPS is a light ranking signal, but that isn't the real risk. A full-page warning stops almost every visitor, enquiry and sale until it's fixed, and Google's crawler has trouble with an invalid certificate too. After fixing it or moving to HTTPS:

  • Make sure every http and non-preferred URL 301-redirects to the https version
  • Check that canonical tags, the XML sitemap and internal links all use https
  • Use a Domain property in Search Console, which covers http, https, www and non-www together

How to prevent SSL problems

  • Use hosting with automatic certificate renewal, and keep the domain's DNS pointing where the certificate is issued
  • Monitor certificate expiry; many uptime monitors can alert you before it lapses, see uptime monitoring explained
  • Keep one preferred version of the domain with proper redirects
  • Check for mixed content after redesigns, theme changes and migrations
  • Only turn on HSTS once HTTPS has been stable for a while, because it makes browsers refuse plain http for a long time
  • Keep a note of where your domain, DNS and hosting are managed; see domain, hosting and SSL explained

FAQs

What causes SSL certificate errors?

The usual causes are a missing certificate, an expired one that failed to renew, a certificate that doesn't cover the exact domain name, an untrusted or incomplete certificate chain, and pages that load files over http. On the visitor's side, a wrong clock or antivirus software can also trigger warnings.

How do I fix "Your connection is not private" on my website?

Click "Advanced" to read the error code. NET::ERR_CERT_DATE_INVALID means the certificate expired, so reissue it in your hosting panel after checking your DNS. NET::ERR_CERT_COMMON_NAME_INVALID means it doesn't cover that name, so reissue it to include www and any subdomains. If the error only appears on one device, check that device's date and time first.

Why does my site say "Not secure" when I have an SSL certificate?

Either the site still loads over http because nothing forces HTTPS, or the page includes mixed content. Set both addresses in Settings > General to https, turn on a redirect to HTTPS, and look for "Mixed Content" warnings in the browser console.

Why do I get a security certificate problem on every website?

Then the problem is almost certainly your device or network, not the websites. Check the date, time and time zone, try a different network, and temporarily turn off any antivirus feature that scans HTTPS traffic. On public Wi-Fi, you may need to open the network's login page first.

Is a free SSL certificate good enough for a business website?

For most business websites and online stores, yes. A free Let's Encrypt certificate encrypts the connection just as well as a paid one. Paid certificates add things like business validation and a warranty, but browsers no longer show a special green bar for them, so visitors see the same padlock.

How long does SSL take to start working?

Issuing a certificate usually takes minutes once the domain points to your host. If you've just changed DNS, it can take longer until the change has spread, and browsers may cache the old error for a while, so test in a private window.
