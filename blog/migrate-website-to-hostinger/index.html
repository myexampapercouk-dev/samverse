How to Migrate a WordPress Website to Hostinger Without Downtime: 3 Methods

Hostinger site migration step by step: hPanel's migration tool, plugins or a manual move, testing before DNS changes, keeping email working and SSL.

Key takeaways
  • Copy the site to Hostinger first, using hPanel's migration tool, a plugin such as All-in-One WP Migration, or a manual move, and test it before the domain points there.
  • Recreate every email DNS record (MX, SPF, DKIM, DMARC) before changing nameservers, or switch only the A record, so email keeps working through the move.
  • After the switch, check SSL, forms, checkout and caching, remove the old host's plugins, and keep the old hosting for a week or two as a fallback.

To migrate a WordPress website to Hostinger without downtime, copy the site to your Hostinger account first, using hPanel's website migration tool, a plugin such as All-in-One WP Migration, or a manual files-and-database move. Test it on Hostinger before your domain points there, recreate your email DNS records, then switch the nameservers or A record. Once the domain resolves to Hostinger, let the free SSL certificate issue, run final checks and keep the old hosting for a week or two as a fallback.

Done in that order, visitors never see a broken site and email keeps flowing. This guide covers each method, testing, DNS, email, the checks I run afterwards and moving from SiteGround specifically. If you'd rather hand it over, see my WordPress migration service.

Before you start: pre-migration checklist

  • Take a full backup of files and database from the current host, and keep a copy on your computer or cloud storage, separate from both hosts; see WordPress backup plugins compared
  • Screenshot or export your DNS records, especially MX, TXT (SPF, DKIM, DMARC, verification codes) and any CNAMEs
  • Find out where everything lives: who the domain is registered with, where DNS is managed (registrar, old host or Cloudflare) and where email is hosted
  • Note the PHP and WordPress versions on the old host, so you can match PHP on Hostinger
  • Check your Hostinger plan's limits for disk space, files (inodes) and websites
  • Lower the DNS TTL to 300 seconds or so a day ahead, if you control DNS, so the switch spreads quickly
  • Pick a quiet time, and for WooCommerce stores, plan how to handle orders placed during the move
  • Check the old host's renewal date, but don't cancel anything yet

Method 1: Hostinger's Migrate Website tool

  1. In hPanel, go to Websites and choose to add or migrate a website. Hostinger's menus change from time to time, so follow the current screens if the wording differs.
  2. Choose WordPress, then either enter your old site's admin URL, username and password, or upload a backup file such as an All-in-One WP Migration .wpress file.
  3. Enter the domain name you're moving, and submit the request.
  4. Wait for the migration status to show as complete, then test the copy before touching DNS.

Rather than handing over your own admin password, create a temporary administrator account on the old site for the migration, and delete it once the move is done.

Method 2: Using a migration plugin

All-in-One WP Migration is the simplest for most small sites:

  1. On the old site, install the plugin and export the site to a file.
  2. On Hostinger, install a fresh WordPress for your domain using hPanel's auto installer.
  3. Install the same plugin on the new install and import the file. This replaces the fresh install, including its admin login, with your old site.
  4. Log in with your old site's username and password, then go to Settings > Permalinks and click Save Changes, which fixes most 404 errors after a move.

The free version has an import size limit, so very large sites may need a paid extension, Duplicator or one of the other methods. Duplicator builds a package plus an installer.php file that you upload and run on the new host; WP Migrate is handy for database moves with built-in find and replace.

Method 3: Manual migration

  1. Download all WordPress files from the old host by SFTP or File Manager, and export the database from phpMyAdmin (or run wp db export over SSH).
  2. In hPanel, create a new MySQL database and user under the databases section, and note the names, which Hostinger prefixes with your account ID.
  3. Upload the files to the domain's public_html folder and import the database through phpMyAdmin.
  4. Edit wp-config.php with the new database details:
define( 'DB_NAME', 'u123456789_wpsite' );
define( 'DB_USER', 'u123456789_wpuser' );
define( 'DB_PASSWORD', 'the-password-you-set' );
define( 'DB_HOST', 'localhost' );

Keep the same domain during the move so you don't need to rewrite URLs. If you do have to change them, use WP-CLI's search-replace or a plugin that handles serialised data, never a plain SQL replace.

Test before switching the domain

Check the migrated site on Hostinger while the old site is still live. hPanel may offer a preview or temporary domain, but the most reliable test is your computer's hosts file, which makes only your computer load the domain from Hostinger. Find the server IP in hPanel, then add a line like this:

203.0.113.10  example.com  www.example.com

On Windows, open Notepad as administrator and open the hosts file in the Windows folder, under System32, drivers, etc. On a Mac or Linux it's /etc/hosts. Then test:

  • Key pages on desktop and mobile, menus, images and sliders
  • Every contact form, and whether the emails arrive
  • WordPress admin, logins and the page builder editor
  • For stores: cart, checkout and a test payment in the gateway's test mode

Remove the hosts line when you're done, or you'll keep seeing the new server after the switch and miss problems others see.

Changing only the A record is the safer choice if your DNS is already somewhere reliable. With a lowered TTL, most visitors reach the new server within minutes to a few hours.

Don't break email

Email is the most common thing to break in a migration, and it's often noticed only when a client says your emails bounced.

  • Email on Google Workspace, Zoho or Microsoft 365: copy every MX, SPF, DKIM and DMARC record exactly into Hostinger's DNS zone before changing nameservers, or use the A-record method
  • Email on the old host's cPanel: those mailboxes stop working when the old hosting is cancelled. Set up mailboxes with your new email provider and copy old mail across before the switch; see business email on Hostinger
  • Website emails: form notifications and WooCommerce emails should send through SMTP, not the server's PHP mail; see fixing WordPress emails with SMTP

The records themselves are explained in SPF, DKIM and DMARC explained.

After the move: final checks

  1. SSL: once the domain points to Hostinger, check the free certificate is active in hPanel's security section and force HTTPS. A brief certificate warning right after the switch is normal until it issues; see SSL certificate errors.
  2. Mixed content: look for a missing padlock on key pages; see fixing mixed content warnings.
  3. Caching: Hostinger's shared and cloud plans have used LiteSpeed servers, so use the LiteSpeed Cache plugin and remove the old host's plugins, such as SiteGround Optimizer or other host-specific caching and security plugins.
  4. PHP version: match or improve on the old host's version in hPanel's PHP settings.
  5. Forms, checkout and payment webhooks: test again on the live domain.
  6. Search Console: check for crawl errors over the following days.
  7. Backups and monitoring: confirm Hostinger's backups are running and add an off-site backup and uptime monitoring.
  8. Old hosting: keep it for a week or two in case anything was missed, then cancel before it renews.

Migrating from SiteGround to Hostinger

The process is the same, with a few SiteGround-specific points:

  • SiteGround uses its own Site Tools panel rather than cPanel, so a plugin or Hostinger's migration tool is usually the easiest way to copy the site
  • Remove the SiteGround Optimizer and SiteGround Security plugins after the move; they're built for SiteGround's servers
  • If the domain is registered with SiteGround, you can point it to Hostinger now and transfer the registration later; see transferring a domain without downtime
  • Check whether your email or DNS is hosted at SiteGround, and move those deliberately before cancelling

FAQs

Does Hostinger migrate websites for free?

Hostinger has offered free website migration with many of its hosting plans, through the migration tool in hPanel. Check the current terms for your plan, and test the result yourself before switching DNS, because a copied site still needs checking.

How long does a Hostinger site migration take?

Copying a small WordPress site with a plugin can take under an hour; larger sites and queued migration requests take longer. DNS changes then take minutes to a few hours with a low TTL, and up to a day or two in some cases.

Will my website go down during the migration?

It shouldn't. The old site keeps serving visitors while you copy and test on Hostinger, and you only switch DNS once everything works. The one short gap to plan for is the SSL certificate, which issues once the domain points to Hostinger.

Will I lose my emails when I move to Hostinger?

Not if you plan for it. If email is with Google Workspace or Zoho, recreate the MX and TXT records in Hostinger's DNS or change only the A record. If email is on the old host, move the mailboxes to a new provider before cancelling the old hosting.

Do I need to transfer my domain to Hostinger?

No. You can keep the domain registered where it is and just point it to Hostinger with nameservers or an A record. Transferring the registration is optional and can be done later, separately from the website move.
