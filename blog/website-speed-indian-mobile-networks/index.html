Website Speed on Indian Mobile Networks: How to Test and Build for Real 4G, Budget Phones and Data Packs

Website speed on Indian mobile networks: why sites crawl on 4G, how to test with throttling and budget Android phones, page weight budgets and what to fix.

Key takeaways
  • Indian visitors often browse on budget Android phones over 4G connections that vary by hour and place, so latency, JavaScript and page weight matter more than an office Wi-Fi test suggests.
  • Test the way customers browse: PageSpeed field data, Chrome DevTools with Slow 4G and CPU throttling, and a real mid-range phone on mobile data in a private tab.
  • Set a page weight budget, host close to your visitors, cut heavy scripts and fonts, and make calls, WhatsApp, forms and checkout work even on a weak connection.

A website that feels instant on office Wi-Fi can take many seconds to become usable on a budget Android phone over a busy 4G connection, which is how a large share of Indian visitors arrive. To build for those conditions, test with network and CPU throttling and on a real mid-range phone, keep total page weight and JavaScript low, host the site close to your visitors, and make sure the actions that matter (calling, WhatsApp, forms and checkout) work even when the signal drops.

This is the testing and budgeting side of speed work for Indian audiences. If your site is already slow and you want the causes found and fixed for you, see WordPress speed optimization, which includes a before-and-after PageSpeed Insights report.

What real conditions look like for Indian visitors

Jio, Airtel and Vi cover most cities with 4G, and 5G is spreading, but the experience on a given phone varies a lot more than a speed-test app suggests:

  • Speed changes through the day. The same connection can be quick at 7 am and congested in the evening, in crowded markets, at railway stations or inside large buildings.
  • Coverage drops while moving. Customers browse in autos, trains and lifts, and in smaller towns between cities.
  • Phones are often budget or mid-range. A slower processor and limited memory take far longer to run JavaScript than a flagship phone or a laptop, whatever the network.
  • Data is metered. Many prepaid plans come with a daily data limit, so a heavy page has a cost to the visitor, not just a delay.
  • Phones switch apps mid-task. UPI payments and WhatsApp hand-offs take people out of the browser and back again, so pages need to survive being interrupted.

A faster network helps, but it doesn't make a budget phone's processor any quicker, which is why heavy JavaScript stays a problem even on 5G.

Why latency matters as much as bandwidth

Bandwidth is how much data arrives per second; latency is how long each round trip to the server takes. A page that needs dozens of files from several different servers pays the latency cost over and over, and on a congested mobile network those round trips are much slower than on fibre.

What adds delayWhy it hurts on mobileWhat to do
Server far from your visitorsEvery request travels furtherHosting in or near India for Indian audiences, plus a CDN
Slow server responseNothing can start until the HTML arrivesPage caching, a lighter theme, better hosting
Many third-party domainsEach new domain needs its own connectionRemove or delay scripts nobody uses
Large JavaScript bundlesSlow to download, slower to run on budget phonesFewer plugins and add-ons, delay non-essential scripts
Heavy images and fontsCompete for limited bandwidth with what mattersResize, compress, use WebP, limit font files

How to test like your customers

  1. Check field data first. In PageSpeed Insights, look at the mobile tab's real-user section, which shows how actual Chrome visitors experienced the page over the last 28 days, if your site has enough traffic. Core Web Vitals explained covers what the numbers mean.
  2. Read the lab test with its settings in mind. The PageSpeed mobile lab test simulates a mid-range phone on a slow 4G connection. At the time of writing, Lighthouse's default mobile settings are roughly 1.6 Mbps download, 150 ms of latency and a 4x CPU slowdown.
  3. Throttle Chrome DevTools. Open DevTools, choose the Network panel and pick a preset such as "Slow 4G" (older versions call it "Fast 3G"). In the Performance panel, add CPU throttling as well, because network throttling alone hides how slowly a budget phone runs scripts. Disable the cache and reload.
  4. Use a real phone. An ordinary mid-range or older Android phone, on mobile data rather than Wi-Fi, in a private tab. Note when the main heading appears, when you can tap the menu, and whether anything jumps.
  5. Test from India. If you use WebPageTest or GTmetrix, choose a test location in or near India where your plan offers one, and keep it the same for every comparison.
  6. Watch Search Console. The Core Web Vitals report groups your pages by mobile and desktop over time.

Developers can run a harsher test from the command line by raising the CPU slowdown:

npm install -g lighthouse
lighthouse https://www.example.com --throttling.cpuSlowdownMultiplier=6 --view

Set a page weight budget

A budget turns "make it faster" into something you can check. These are sensible starting points for a typical business site on mobile, not official standards:

ResourceStarting budget per pageNotes
Total page weightAround 1 to 1.5 MB or lessLower is better for service and landing pages
ImagesWell under 1 MB in totalThe hero image is the one to get right
JavaScriptAs little as possible, a few hundred KB compressed at mostPage builders, sliders and chat widgets add up quickly
FontsTwo to four font filesHindi and Devanagari fonts are larger, so subset or limit weights
Third-party domainsA handfulAnalytics, one chat tool, maps only where needed

To see where a page stands, open DevTools, reload with the Network panel open and read the totals at the bottom: requests, data transferred and resources.

Where the weight usually comes from on WordPress sites

  • Images: photos uploaded straight from a camera, sliders loading every slide and CSS background images with no mobile version. Image optimization for WordPress covers the full workflow.
  • Page builder and plugin scripts: add-on packs, animation libraries and plugins that load their files on every page rather than only where they're used.
  • Third-party tools: chat widgets, several analytics tags, heatmaps, social feeds and review widgets. How third-party scripts slow your website shows how to measure and trim them.
  • Fonts: several families and weights, or full Devanagari font files when only a few pages use Hindi; see Hindi and Devanagari fonts on your website.
  • Video: autoplaying background videos and YouTube embeds that load the full player before anyone taps play.

Serve the site from close by

  • Hosting location: for mainly Indian visitors, choose a host with servers in India, such as a Mumbai data centre, or as close as possible.
  • Page caching: visitors should receive a ready-made page rather than waiting for WordPress to build it each time.
  • A CDN: useful when visitors are spread across regions or countries, as most large CDNs have edge locations in several Indian cities; see what a CDN is and when you need one.
  • Modern protocols and compression: HTTP/2 or HTTP/3 and Brotli or gzip compression, which most decent hosts and CDNs enable by default.

Make key actions work on a weak connection

Speed isn't only about the first load. On a patchy connection, the things that bring you business need to work reliably:

  • Tap-to-call and WhatsApp links should be plain links that work even before every script has loaded.
  • Forms should be short, show a clear success message on screen and not depend on several heavy scripts to submit.
  • Popups shouldn't cover the content while the page is still loading.
  • Checkout should stay light, and payment webhooks should be set up so an order paid by UPI is still marked as paid if the customer's connection drops on the way back from their UPI app.

If the site is fast on desktop but still slow on phones after all this, WordPress site slow on mobile covers the mobile-only causes, such as hidden builder sections and mobile menus.

A quick checklist

  1. Test key pages on mobile with Slow 4G and CPU throttling, and on a real budget phone.
  2. Check total page weight and JavaScript against your budget.
  3. Fix the hero image first, then remove or delay unused scripts.
  4. Limit fonts and replace autoplaying video with a tap-to-play image.
  5. Confirm hosting location, page caching and compression.
  6. Test calls, WhatsApp, forms and checkout on mobile data.
  7. Re-check after adding plugins, campaigns or new sections.

Heavy JavaScript mostly shows up as slow taps and clicks, which Google measures as INP; see how to improve Interaction to Next Paint.

FAQs

Why is my website slow on mobile data but fast on Wi-Fi?

Mobile connections usually have higher and more variable latency, so pages that need many files from several servers slow down sharply. Budget phones also run JavaScript more slowly than laptops. Throttled testing in Chrome shows the difference before your customers notice it.

How do I test my website on a slow 4G connection?

In Chrome DevTools, choose a network preset such as Slow 4G and add CPU throttling in the Performance panel, then reload with the cache disabled. Also try an ordinary Android phone on mobile data in a private tab.

Should my website's hosting be in India?

If most of your visitors are in India, hosting in India or nearby reduces the delay on every request. If your visitors are spread across countries, good hosting plus a CDN matters more than the server's exact location.

Does 5G mean page speed matters less?

No. Many visitors still connect over 4G, indoors or in areas without 5G, and a faster network doesn't speed up a budget phone's processor. Heavy JavaScript and slow server response hurt on any network.

What is a good page size for mobile visitors?

There's no official figure, but keeping a typical business page to around 1 to 1.5 MB or less, with as little JavaScript as possible, is a sensible starting budget. Landing pages for ads should be lighter still.
