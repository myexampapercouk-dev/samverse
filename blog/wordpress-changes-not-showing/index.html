WordPress Changes Not Showing on Your Website? Every Cause, From Caches to the Wrong Template

WordPress changes not showing after you update or publish? Find the cause fast: caches, CDN, page builder files, mobile settings, templates or the wrong site.

Key takeaways
  • Most changes that do not show are held back by a cache, so check the page as a visitor would, then clear the plugin, server, CDN and browser caches in that order.
  • If clearing caches does not help, check you edited the right thing: a template, a synced pattern, a translation, a child theme or a staging copy instead of the live site.
  • Changes that show only on desktop, only for you or only for a while each point to a different layer, which tells you where to look first.

When WordPress changes don't show on your website, the cause is almost always one of three things: the change didn't actually save, a cache is still serving the old version, or you edited something other than what visitors see, such as a template, a staging copy or the wrong language. Check the page in a private window first, clear your caches in order (plugin, server, CDN, then browser), and if it's still old, trace where that part of the page really comes from.

It's one of the most frequent support requests I get, and this is the checklist I work through. If styling is the only thing missing, the narrower guide to WordPress CSS changes not showing goes deeper into stylesheets. 1. Make sure the change really saved

  • Block editor: Save draft and Preview don't change the live page. Click Update or Save (the button's name depends on your WordPress version), and check the page isn't scheduled for a future date.
  • Elementor: click the green Update or Publish button before closing the editor. Closing the tab without it leaves an autosave, not a live change.
  • Check the revisions to confirm your edit is there. In the block editor, the Revisions link sits in the post settings sidebar; in Elementor, use the History panel's Revisions tab.
  • No revisions at all? They only appear once a post has been saved more than once, and a developer can switch them off by setting WP_POST_REVISIONS to false in wp-config.php. Some hosts limit them too.

2. Look at the page the way a visitor does

Logged-in administrators usually skip the page cache, so you may see your change while every visitor still gets the old copy. Test properly:

  • Open the page in a private or incognito window, which ignores your login and your browser cache.
  • Check on your phone using mobile data rather than office Wi-Fi.
  • Add a random query string such as ?v=2 to the end of the address. Many caches treat that as a new page, so if the change appears with it, a cache is the culprit. Some CDNs ignore query strings, so this test isn't conclusive.
  • Do a hard refresh (Ctrl+F5 or Ctrl+Shift+R on Windows, Cmd+Shift+R on Mac) to reload your own browser's copy of the page and its files.

3. Clear every cache layer, in order

A WordPress site can have four or five caches stacked on top of each other, and clearing one isn't enough if another still holds the old page. Work from the server outwards:

LayerExamplesHow to clear it
Caching pluginLiteSpeed Cache, WP Rocket, W3 Total Cache, WP Super CachePurge All from the plugin's menu or the admin bar
Optimisation pluginAutoptimize, or the minify and combine options in your caching pluginClear its CSS and JavaScript cache
Host or server cacheHostinger's cache, LiteSpeed server cache, Varnish on managed hostsThe purge option in the hosting panel or the WordPress admin bar
Object cacheRedis or MemcachedFlush it from the plugin or hosting panel; it can hold menus, settings and widget data
CDNCloudflare, or your host's CDNPurge everything, or just the changed URLs and files
BrowserYours and your visitors'Hard refresh; visitors' copies expire on their own

LiteSpeed Cache can keep a separate copy of each page for mobile visitors when its mobile cache option is on, a common reason a change shows on desktop but not on phones; Purge All clears both. For how each layer works, see WordPress caching explained, and for Cloudflare's settings, the Cloudflare setup guide.

4. Regenerate page builder files

Page builders store styles in generated CSS files, and those files don't always refresh when you'd expect:

  • Elementor: go to Elementor > Tools and use Regenerate Files & Data (older versions call it Regenerate CSS & Data), then clear every cache above.
  • Divi, Beaver Builder and others have a similar option to clear or regenerate their static CSS in the builder's settings or tools.
  • Theme options: some premium themes write their customiser settings to a CSS file and need a save or "regenerate" to refresh it.

Styling problems that survive all of this are usually specificity, loading order or a child theme stylesheet, which the CSS guide linked above walks through.

5. Check you edited the right thing

When nobody sees the change, including you in a private window, the part you edited probably isn't the part on screen:

  • Templates: headers, footers, blog post layouts and archive pages often come from a template, not the page itself. In Elementor Pro, look under Templates > Theme Builder; on block themes, under Appearance > Editor; on classic themes, under Appearance > Customize or Widgets.
  • Synced patterns and global widgets: a block reused across pages (synced patterns, once called reusable blocks) or an Elementor global widget has one source. Editing a detached copy changes only that page.
  • Menus: a menu only appears if it's assigned to a location, so you may be editing a menu that isn't the one in the header.
  • Duplicate pages: a page whose address ends in "-2" is usually a copy. Check which one the menu links to.
  • Translations: on a Hindi and English site using WPML, Polylang or similar, each language is a separate page, so editing the English version doesn't change the Hindi one; see multilingual WordPress websites.
  • Display conditions: popups, banners and some blocks only show on certain pages, devices or dates, or only to logged-out visitors.

6. Check you're on the right site

  • Staging vs live: changes on a staging copy don't reach the live site until they are pushed, and pushing staging to live can overwrite edits made on live in the meantime; see staging sites explained.
  • Two WordPress installations: an old copy in a subfolder, or a second site on the same hosting, has its own login. Check that the address bar in wp-admin shows your real domain.
  • Just after a migration: if the domain still points to the old host, you may be editing the new site while visitors see the old one, or the other way round. A DNS lookup tool shows which server the domain points to.

7. Theme files and child themes

Edits made directly in a theme's files, such as functions.php, style.css or template files, are overwritten the next time that theme updates, which looks like your change disappearing. Code changes belong in a child theme or a code snippets plugin. The reverse happens too: edits in a child theme don't show if it isn't the active theme under Appearance > Themes. See WordPress child themes explained.

8. Changes not showing on mobile

  • Device-specific settings: Elementor and most builders let you set different sizes, spacing or visibility per device, so a change made in desktop view can be overridden by a tablet or mobile value. Switch the responsive mode and check each one.
  • Hidden duplicates: some sites have one section for desktop and a separate copy for mobile. Edit the one that's visible on phones.
  • Mobile cache: purge the caching plugin's mobile cache, as above.
  • The phone's own browser: clear the site's data in the browser settings, or test in a private tab.

9. Images that won't update

If you upload a new image with the same file name as the old one, browsers, CDNs and image optimisation plugins may keep serving the old file, especially a converted WebP copy. Upload the new image with a different file name and swap it in, or regenerate the optimised versions and purge the CDN.

10. The site is updated but Google still shows the old version

Search results show what Google saw on its last visit, so new titles, descriptions and prices appear only after it recrawls the page. In Search Console, inspect the URL and click Request Indexing. Google can also rewrite titles and snippets on its own, so a result won't always match your page exactly.

A quick routine after every change

  1. Click Update, and confirm the revision saved.
  2. Clear the caching plugin, then the host cache, then the CDN.
  3. Check the page in a private window on your phone, on mobile data.
  4. If styles look wrong, regenerate the page builder's CSS and clear the caches again.

If several people edit the site, an activity log shows who changed what and when, which settles "it was working yesterday" quickly; see WordPress activity logs.

Caching layers that hide changes also exist to keep pages fast. If removing them makes the site crawl, read about fixing a slow WordPress site properly instead.

FAQs

Why are my WordPress changes not showing?

Usually a cache is still serving the old page. Clear your caching plugin, host cache and CDN, then check in a private window. If the change still isn't there, confirm it saved, and check you edited the right template, language or site rather than a staging copy.

Why are my WordPress changes not showing on mobile?

Either the page builder has a tablet or mobile setting overriding your change, the caching plugin keeps a separate mobile cache, or your phone's browser has an old copy. Check responsive mode in the editor, purge all caches and test in a private tab on mobile data.

Why can I see my changes but visitors can't?

Logged-in administrators usually bypass the page cache, so you see the latest version while visitors get a cached copy. Purge the caching plugin, server cache and CDN, then check while logged out.

Why are my WordPress revisions not showing?

Revisions only appear after a post has been saved more than once, and they can be switched off with WP_POST_REVISIONS in wp-config.php or limited by your host. Page builders keep their own history too: in Elementor, check the History panel's Revisions tab.

How do I clear the cache in WordPress?

Use Purge All in your caching plugin, then the purge option in your hosting panel, then purge your CDN, such as Cloudflare, if you use one. Finish with a hard refresh in your browser. If you're not sure which caches your site has, your host's support can tell you what runs at server level.

How long until changes show in Google search results?

Only after Google recrawls the page, which can take from days to a few weeks. Requesting indexing in Search Console's URL Inspection tool usually speeds it up for an important page.
