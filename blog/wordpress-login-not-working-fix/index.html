WordPress Login Not Working? How to Fix Login Loops, Lockouts and Lost Passwords

Can't log in to WordPress? Fix login pages that keep refreshing, cookie errors, wrong site URLs, security lockouts and forgotten passwords, step by step.

Key takeaways
  • Match the symptom first: a silently reloading login page usually means cookies, a cached login page or mismatched site URL settings, while lockouts and 404 login pages point to a security plugin.
  • Without dashboard access, a developer can correct the site URLs in wp-config.php or phpMyAdmin, or temporarily rename a security or caching plugin's folder, then re-enable it once you are in.
  • Reset forgotten passwords by email where possible, use phpMyAdmin or WP-CLI carefully with a backup, and treat unexplained password or admin changes as a sign of a hack.

You type your username and password, press Log In, and the login page simply reloads. Or WordPress insists the password is wrong when you're sure it isn't, or tells you you've been locked out. Being shut out of your own website is stressful, but login problems rarely mean anything has been lost. Work through the checks below in order, and take a backup before changing any files or the database.

First, match the symptom to the likely cause

Step 1: Rule out your browser and cookies

WordPress keeps you logged in with cookies. If the browser refuses them, or holds on to old ones, the login appears to work and then sends you straight back.

  • Try a private or incognito window, a different browser, or your phone on mobile data
  • If that works, clear cookies and cached data for your site only, rather than wiping everything
  • Temporarily switch off privacy, ad-blocking or script-blocking extensions
  • Type the address exactly as the site uses it. Cookies are tied to the domain, so logging in at the www version of a site set up without www (or the reverse) can fail

Step 2: Check the site URL settings

WordPress stores two addresses in Settings → General: the WordPress Address and the Site Address. If they don't match how the site is actually reached, for example after a move to https or a migration, WordPress sets its login cookie for the wrong address and you bounce back to the login page.

Without dashboard access, a developer can set them by adding two lines to wp-config.php, above the comment that says to stop editing:

define( 'WP_HOME', 'https://www.example.com' );
define( 'WP_SITEURL', 'https://www.example.com' );

Use your real address, with or without www exactly as your site uses it. The alternative is editing the siteurl and home rows in the options table through phpMyAdmin; the table name starts with your site's prefix, which isn't always wp_. Keep a copy of the original file or values so you can undo the change.

Step 3: Security plugin and firewall lockouts

Security tools are meant to block repeated failed logins, and sometimes they block the owner too.

  • Lockout after failed attempts: most lockouts expire after a set time. Trying from a different network, such as your phone's mobile data, confirms whether your IP address is the problem
  • Custom login address forgotten: check your handover notes or the plugin's set-up emails. Failing that, rename the security plugin's folder inside wp-content/plugins using your host's File Manager or SFTP. That deactivates it and restores the normal login page
  • Lost two-factor phone: use the backup codes you saved when setting it up. Without them, deactivating the plugin the same way lets you in, and you should set up two-factor again straight away
  • Host or CDN firewall: if the login page itself won't load, your host or CDN dashboard can show and lift the block

Whatever you disable, rename it back and re-enable it once you're in. For setting these protections up sensibly, see how to secure your WordPress login.

Step 4: Make sure the login page isn't cached

The login page and the dashboard should never be cached. If a caching plugin, server cache or CDN rule stores a copy of wp-login.php, people get an old page with expired security tokens, and logins fail or loop. A "cache everything" rule at the CDN is a common culprit.

  • Purge the caching plugin, the hosting cache and any CDN cache
  • Check that wp-login.php and the /wp-admin/ area are excluded from caching, and that logged-in users bypass the cache
  • If you can't reach the plugin settings, rename the caching plugin's folder temporarily, as above

Step 5: Reset a forgotten password safely

The simplest route is the "Lost your password?" link on the login page, which emails a reset link. If the email never arrives, check spam, and check whether the account uses an old address, such as a former employee's or a previous developer's. Many sites can't send email reliably until SMTP is set up; see WordPress not sending emails.

Through phpMyAdmin

In your hosting panel, open phpMyAdmin, export a backup of the database, then open the users table (again with your site's prefix). Edit your account's row, choose MD5 from the function dropdown beside user_pass, type a new password and save. WordPress accepts this older format for your next login and then replaces it with its own stronger hash. Don't touch any other fields.

Through WP-CLI

If your host offers SSH access with WP-CLI, these commands list administrator accounts and send a fresh reset email:

wp user list --role=administrator
wp user reset-password <username>

Sending a reset email is safer than typing a new password on the command line, where it can stay in the server's history. If you're unsure about either method, ask your host or developer rather than guessing.

When it could be something more serious

Be suspicious if your password or admin email changed without anyone on your team doing it, if there are administrator accounts you don't recognise, or if logging in sends you to an unfamiliar site. Those are signs of a compromised site. Change every password (hosting, WordPress, email and SFTP), and get a proper cleanup rather than just regaining access; see hacked site repair.

How to avoid getting locked out again

  • Keep the admin email address current, using a mailbox someone checks
  • Use a password manager, and store two-factor backup codes and any custom login address with your site records
  • Give a trusted person a second administrator account of their own
  • Set up SMTP so reset emails arrive
