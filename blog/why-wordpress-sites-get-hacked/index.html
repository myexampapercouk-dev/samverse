Why WordPress Sites Get Hacked: The Real Causes, How Attacks Work and How to Prevent Each One

Why WordPress sites get hacked: vulnerable plugins, stolen passwords, nulled themes, weak hosting and admin access, plus the fix that prevents each one.

Key takeaways
  • Most WordPress hacks come through outdated or abandoned plugins and stolen or reused passwords, not WordPress core.
  • Leftover staging sites, old admin accounts and shared hosting folders give attackers easy side doors.
  • A short monthly routine of updates, access reviews and off-site backups prevents most small business hacks.

WordPress sites rarely get hacked because WordPress itself is weak. Core is actively maintained and security fixes are released quickly. Sites get hacked through what surrounds it: a plugin or theme with a known vulnerability that hasn't been updated, a password that was guessed, reused or stolen, pirated software with malware built in, a forgotten site in the same hosting account, or a computer with saved logins that got infected. Nearly all of it is automated, which is why small business sites are hit as often as big ones.

If your site is already showing signs of a hack, cleaning comes before prevention, because hardening an infected site leaves the backdoors in place. My WordPress malware removal service ends with a plain-English report that includes the likely way in, when the evidence shows it.

This post explains the causes. The steps to close them are in the WordPress security checklist.

How a typical WordPress hack happens

Most hacks follow the same automated chain. Nobody sits down and decides to attack your site.

  1. A vulnerability is published in a plugin or theme, or a list of leaked passwords starts circulating.
  2. Bots scan huge numbers of sites for the vulnerable version, often by requesting a plugin's readme file, or try the leaked passwords on login pages.
  3. The exploit runs on every site that matches, often within days of the vulnerability becoming public.
  4. A backdoor is planted so the attacker keeps access even after the hole is patched.
  5. The site is put to use: spam pages, redirects, phishing pages, spam email or, on stores, card skimming.

The gap between steps 1 and 3 is why update speed matters so much, and step 4 is why updating after a hack isn't enough on its own.

1. Vulnerable and abandoned plugins and themes

Vulnerability databases such as Wordfence Intelligence, Patchstack and WPScan publish yearly reports, and they consistently find that almost all newly reported WordPress vulnerabilities are in plugins and themes rather than core. In plain terms, the common types are:

  • File upload flaws: anyone can upload a PHP file and run it
  • Privilege escalation: a subscriber or customer account can make itself an administrator
  • Stored cross-site scripting: a script saved through a form runs when an admin views it, and uses the admin's session to create a new admin
  • SQL injection: the database is read or changed through a badly checked input
  • Broken access control: a plugin action that should be admin-only isn't

Deactivating a plugin doesn't always protect you, because its files are still on the server and some flaws can be reached directly. Delete what you don't use. A plugin that hasn't been updated in years won't get a fix even when a flaw is found, so replace it.

2. Passwords: guessed, reused and stolen

Bots try common passwords and huge lists of credentials leaked from other websites against wp-login.php, XML-RPC and WooCommerce account pages. A password reused from a breached service is effectively public. Other routes are phishing emails that imitate your host or WordPress, and passwords shared over WhatsApp or email that end up on more devices than anyone remembers. Two-factor login stops most of this even when a password is known; see how to secure your WordPress login.

Remember the accounts around WordPress too. Whoever controls your hosting panel, domain registrar or the inbox that receives password resets controls the website.

3. Nulled themes and plugins

Pirated copies of premium themes and plugins are a well-known source of hidden backdoors and SEO spam, and they never receive security updates. The details are in the risks of nulled themes and plugins.

4. The hosting account: neighbours and leftovers

Many hosting plans run every site in the account as the same user, so one infected site can write to all the others. Old installs in folders such as /old/ or /test/, staging copies nobody updates and abandoned microsites are classic ways in. Leftover files are just as risky:

  • Backup zip files and database exports in public_html, which anyone who guesses the name can download
  • Copies such as wp-config.php.bak or wp-config.old, which the server may show as plain text, database password included
  • A public debug.log revealing file paths and plugin errors
  • Old installer or file manager scripts left behind after a migration

5. People, devices and access

  • Infected computers: malware on a computer used to manage the site can steal saved FTP, hosting and browser passwords. Use SFTP, a password manager and an up-to-date operating system.
  • Too many administrators: every admin account is a target, especially old ones for former staff, agencies or freelancers.
  • Shared logins: one password used by several people can't be revoked from one person, and leaves no record of who did what.
  • No 2FA on hosting and email: a stolen hosting password bypasses every WordPress protection.

6. Supply chain and third-party scripts

Occasionally a trusted source turns bad. In 2024, a handful of plugins on WordPress.org were pushed out with malicious code after their developers' accounts were compromised; it was spotted and fixed quickly. Plugins also change hands, and a new owner can add unwanted code. Third-party scripts such as ad networks, chat widgets and tracking tags run on your pages, and if their provider is compromised, so is your page. Fewer plugins and scripts means fewer people you have to trust.

What attackers want from a small business site

"We're too small to be a target" is a common belief, but bots don't choose by size. A small site still has things worth taking:

  • Search reputation, used to rank spam pages; see the Japanese keyword hack
  • Visitors, sent to scam pages; see the WordPress redirect hack
  • The server, used to send spam email, host phishing pages or mine cryptocurrency
  • Customer data and payments, on stores and booking sites

Which fixes make the biggest difference

If you can only do a few things this month, do them in this order, because each one closes a route from the table above:

  1. Update everything and delete what you don't use, with a backup taken first.
  2. Turn on two-factor login for every administrator, and for your hosting, domain registrar and email accounts.
  3. Replace nulled and abandoned plugins with genuine or maintained alternatives.
  4. Clear out the hosting account: old installs, staging copies nobody uses, backup files and stray scripts.
  5. Review users and remove anyone who no longer needs access.
  6. Add monitoring: off-site backups, uptime checks, file-change alerts and Search Console emails, so a problem is caught in days rather than months.

Before working out the cause, confirm there is a compromise at all. This checklist explains how to tell if your WordPress site has been hacked.

How to work out how your site was hacked

Finding the entry point is what stops the same hack happening twice. The evidence that helps most:

  • Dates: when the first malicious file appeared, compared with when each plugin was last updated
  • Plugin versions: the versions you were running, checked against the vulnerability databases above
  • Access logs: the first unusual POST request, often to a plugin file or upload handler
  • Login records: admin logins from unfamiliar places just before the infection
  • Hosting records: new FTP accounts, cron jobs or file manager activity

Logs aren't always available, especially on cheap shared hosting, so sometimes the honest answer is "most likely". In that case, close every plausible route.

Hidden entry points Indian small business sites often miss

When I clean up hacked sites, the cause is often something the owner forgot existed rather than the live website itself. These are worth checking even if your main site looks fine:

  • Old staging or test copies in a subfolder such as /old/, /test/ or /new/, left behind after a redesign and never updated again.
  • Admin accounts for past freelancers or agencies that still work, often with simple passwords set during the build.
  • cPanel, FTP and hosting logins shared over WhatsApp or email years ago, never changed since.
  • Payment, form and WhatsApp chat plugins installed for a campaign, then deactivated but left on the server with their old code.
  • A cheap shared hosting plan where one outdated site in the same account can infect every other site next to it.
  • The office computer where the browser has saved the WordPress password and someone installs pirated software.

A simple test: list every person, plugin and folder that can touch your site, then remove anything you cannot explain. If you also run a Shopify store, the platform handles server security for you, but staff accounts and third-party apps still need the same review.

The aim is not to buy more security tools. It is to shrink the number of doors, keep the ones you need locked and updated, and keep a clean off-site backup so a bad day is a restore rather than a rebuild.

FAQs

Why do hackers target small business websites?

Mostly they don't target anyone in particular. Bots scan for known weaknesses across the internet, and any site that matches gets used for spam, redirects, phishing or email abuse, whatever its size.

Is WordPress less secure than Wix or Shopify?

Not inherently. Hosted platforms handle updates and servers for you, while a WordPress site's security depends on how it is maintained. A well-maintained WordPress site is a hard target; a neglected one isn't.

Can a deactivated plugin get my site hacked?

It can. Its files stay on the server, and some vulnerabilities can be reached without the plugin being active. Delete plugins you don't use.

Can my site be hacked through my hosting account?

Yes. A stolen hosting or FTP password, or an infected site in the same account, gives an attacker access to your files without touching WordPress logins.

Does a security plugin stop all hacks?

No. It reduces risk, but it can't fix an unpatched plugin, a reused password or a nulled theme. Updates and strong logins do more of the work, and a firewall adds another layer.

How often should a small business check its WordPress site for security problems?

Check updates at least weekly, review admin users and plugins monthly, and test that you can restore a backup every few months. A maintenance plan can handle this routine for you.

Most of these causes come down to upkeep: updates with a backup first, user reviews and monitoring, which is what WordPress maintenance covers every month. If your site has already been hacked, see WordPress malware removal.
