How to Update WordPress Safely: Core, Plugins and Themes Without Breaking Your Site

How to update WordPress safely: backups, staging, the right update order, testing, rolling back a bad update, and best practices for plugins and themes.

Key takeaways
  • Before updating, take a backup you know how to restore, read the changelog for major versions and test big updates such as WooCommerce, page builders and core on staging.
  • Update one thing at a time at a quiet hour, usually plugins, then the theme, then core, and test pages, forms and checkout while logged out after each important update.
  • If an update breaks something, use recovery mode or rename the plugin folder to get back in, roll back that one update or restore the backup, and pause its auto-updates.

To update WordPress safely, take a full backup first, check the changelog for major versions, test big updates on a staging copy, then update one thing at a time at a quiet hour: plugins, then your theme, then WordPress core. After each important update, test your key pages, forms and checkout while logged out. If something breaks, roll back that single update or restore the backup.

That routine takes a few minutes on a small site and prevents most update problems, or makes them quick to undo. Below is the full process, the commands developers use, how to recover from a bad update and the extra care WooCommerce and page builders need. If you'd rather not do it yourself, updates with a backup first and checks afterwards are the core of my WordPress maintenance plans.

Why updates matter

Outdated plugins and themes are one of the most common ways WordPress sites get hacked, because once a security fix is public, attackers know exactly what to look for on sites that haven't installed it. Updates also fix bugs and keep your site working with new PHP versions and browsers. Skipping them doesn't avoid risk; it piles it up, and a site that is many versions behind is much harder to update later.

Step 1: Take a backup you can actually restore

A backup is only useful if it's recent, complete and stored somewhere other than the server it protects.

  • Back up both files and the database. The database holds your content and settings; files hold plugins, themes and uploads.
  • Store a copy off-site, for example UpdraftPlus sending backups to Google Drive or Dropbox, in addition to your host's backups.
  • Check the date of the latest backup before you click update, and take a fresh one if it's more than a day old on a busy site.
  • Know how to restore it. Try a restore on staging once, so you're not learning during an emergency; see the backup and restore guide.

Step 2: Check what's being updated

Go to Dashboard > Updates and look at what's waiting. The version number tells you how careful to be:

  • Minor updates change the last number (6.8.1 to 6.8.2, or a plugin's 3.2.4 to 3.2.5). They're mostly fixes and low risk.
  • Major updates change the first numbers (WordPress 6.8 to 6.9, or a plugin's 3.x to 4.0). Read the changelog through the plugin's "View version details" link for breaking changes and new requirements.
  • PHP requirements: a new version may need a newer PHP version than your host runs; see updating PHP safely.
  • Premium plugins and themes often need an active licence before they'll update. An expired licence quietly leaves you on an old version.
  • WooCommerce stores: check WooCommerce > Status for outdated template overrides in your theme, which can break after a WooCommerce update.

Step 3: Test major updates on staging

A staging site is a private copy of your site where you can update and test without visitors seeing anything. Many hosts, including Hostinger on some plans, have one-click staging, and the WP Staging plugin can create one on most hosts. See staging sites explained.

You don't need staging for every small update. Use it for:

  • Major WordPress core releases
  • Major versions of WooCommerce, page builders (Elementor, Divi and so on) and your theme
  • Payment gateway, membership or booking plugins
  • PHP version changes
  • Any site that has gone months without updates

Step 4: Update in the right order

  1. Plugins, one at a time for important ones such as WooCommerce, page builders, forms and payment plugins; small utility plugins can go together
  2. Theme, including any plugins bundled with a premium theme
  3. WordPress core

Plugin updates often add compatibility for the newest WordPress version, so updating them first is usually safest. The exception: if a plugin update says it requires a newer WordPress version, update core first. Either way, one change at a time means you know exactly what caused a problem.

Developers with SSH access can do the same with WP-CLI, which also makes it easy to update a single plugin and see the result:

wp plugin list --update=available
wp plugin update woocommerce
wp theme update --all
wp core update
wp core update-db

Some plugins, WooCommerce and Elementor among them, also need a database update after a major version. When the dashboard shows that notice, run it once you've confirmed your backup.

Step 5: Test after updating

Clear your caching plugin, host and CDN caches, then open a private window so you see what visitors see:

  • The homepage and your most important pages, on desktop and mobile
  • Every contact form, and check the email actually arrives
  • For stores: add to cart, checkout and a test payment, plus the order emails
  • The page builder editor opens and saves
  • Logins, menus, search and special features such as bookings or calculators

To catch hidden PHP errors, a developer can log them to a file without showing them to visitors by adding this to wp-config.php, then removing it afterwards:

define( 'WP_DEBUG', true );
define( 'WP_DEBUG_LOG', true );
define( 'WP_DEBUG_DISPLAY', false );

Errors are then written to wp-content/debug.log. Tools > Site Health is also worth a look after a big update.

What to do if an update breaks your site

  1. Stop changing things. Note what you updated and what broke.
  2. Get back into the dashboard. For "There has been a critical error", WordPress emails the admin a recovery mode link that lets you log in with the faulty plugin paused; see fixing the critical error. If that doesn't arrive, rename the plugin's folder in wp-content/plugins using your host's File Manager, which deactivates it.
  3. Roll back that update. The free WP Rollback plugin can reinstall a previous version of most WordPress.org plugins and themes. For premium plugins, download the older version from the vendor's account area.
  4. Or restore the backup if several things broke or you can't tell what caused it.
  5. Find the cause before updating again: check the plugin's support forum or changelog for a known issue, and look for a conflict with another plugin; see plugin conflicts.
  6. Pause auto-updates for that plugin until a fixed version is out.

WooCommerce, page builders and premium themes

  • WooCommerce: update during your quietest hours, check that payment gateway and shipping plugins support the new version, run the database update, then place a test order and check the emails and invoice.
  • Elementor and similar builders: update the free and Pro plugins together, then regenerate CSS from the builder's tools if styles look wrong. If layouts break, see Elementor layout broken after an update.
  • Premium themes: they often bundle plugins that update separately, and edits made directly in the theme are lost on update, which is why customisations belong in a child theme; see updating a premium theme safely.

Best practices for WordPress updates

  • Check for updates weekly or fortnightly, and apply security fixes promptly
  • Don't let a site fall many versions behind; small regular updates are far safer than one giant jump
  • Delete plugins and themes you don't use, so there's less to update and less to attack
  • Keep PHP on a supported version your plugins are tested with
  • Keep a simple log of what was updated and when, so problems can be traced
  • Decide which parts update automatically and which you update by hand; see WordPress auto-updates
  • Never edit plugin or theme files directly, because updates overwrite them

FAQs

How often should I update WordPress?

Check weekly or fortnightly and install security releases as soon as practical. Minor core releases usually install automatically. Larger updates can wait a few days for early bugs to surface, but not months.

Should I update plugins or WordPress core first?

Usually plugins first, then the theme, then core, because plugin updates often add support for the newest WordPress. If a plugin update says it needs a newer WordPress version, update core first. Always take a backup before either.

Is it safe to update WordPress without a backup?

Most updates go fine, but when one doesn't, a backup is the difference between a five-minute restore and hours of repair or lost content. Take one every time, especially before WooCommerce, page builder or major core updates.

Why is the WordPress update button missing?

Common reasons are that your user account isn't an administrator, your host manages updates itself, a developer has disabled updates in wp-config.php (for example with DISALLOW_FILE_MODS), or a premium plugin's licence isn't activated. On a Multisite network, only the Super Admin can update.

How do I roll back a WordPress plugin update?

Use the free WP Rollback plugin to reinstall a previous version of a WordPress.org plugin, or download the older version from the vendor for premium plugins. If you can't get into the dashboard, rename the plugin's folder over File Manager first. Restoring a backup works when several things changed.
